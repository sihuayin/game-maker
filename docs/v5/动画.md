# 1. 任务背景

`Animation & Asset Acceptance V1` 的目标是建立一套可重复、可追溯的动画与游戏资源验收能力，覆盖：

1. 固定动画验收基准。
2. 资源与动画结构检查。
3. 动画视觉审查。
4. 现有游戏运行时中的资源集成验证。
5. 统一验收报告。
6. 基线与候选资源的比较。

在开始开发前，必须先核对 `sihuayin/game-maker` 当前代码、数据结构、测试与运行流程。

本阶段不假设以上能力全部缺失，也不因为需求文档列出了某个模块，就直接创建对应的新模块。

**本阶段的核心任务是确认：哪些能力已经存在、哪些能力可以复用、哪些能力确实缺失，以及最小实现应该落在哪里。**

# 2. 目标

Phase 0 必须回答以下问题。

## 2.1 现有能力

- 当前仓库如何表示游戏资源、动画帧、图集与资源引用？
- 当前是否已有动画结构检查、资源包验证和元数据校验？
- 当前是否有动画验收标准、固定样本或基线记录？
- 当前是否能在真实游戏运行时加载并播放指定动画？
- 当前是否能保存测试截图、日志和运行结果？
- 当前是否有统一的错误结构、报告格式和 CLI 入口？

## 2.2 代码边界

- 哪些 package 已经负责资源验证？
- 哪些模块负责图集、动画和资源清单？
- 哪些模块负责游戏运行时加载？
- 新增验收能力应复用哪些模块？
- 哪些职责不应进入现有模块？
- 是否存在相同职责的重复实现？

## 2.3 测试与复现

- 现有测试覆盖了哪些资源异常？
- 是否有真实动画资源的回归测试？
- 当前是否可以使用固定输入重复执行测试？
- 测试结果是否能追溯到具体资源版本？
- 当前基线是否足够稳定，能够用于后续实验比较？

## 2.4 实施决策

最终需要给出：

- 现有能力清单。
- 功能缺口清单。
- 文件与模块映射。
- Phase 1 的最小实现范围。
- 需要新增或修改的文件。
- 测试方案与实施顺序。
- 尚未解决的风险与待裁定问题。

# 3. 执行约束

## 3.1 本阶段只读

允许：

- 阅读源代码、README 和架构文档。
- 检查 Git 历史与相关提交。
- 阅读现有测试。
- 运行不会修改仓库内容的现有测试。
- 检查已有资源样本及其元数据。
- 在临时目录中运行验证命令。
- 生成独立的调查报告。

禁止：

- 修改业务源代码。
- 修改现有测试。
- 新增验收模块或新的 contracts。
- 修改动画资源或重新生成资源。
- 修改现有基准或验收规则。
- 为了调查而升级依赖。
- 修改锁文件、配置文件或项目清单。
- 执行会覆盖已有产物的构建命令。
- 在没有证据的情况下认定某项功能缺失。

如果某项调查必须执行具有副作用的命令，应先说明风险，并选择只读替代方案；不能安全执行时，将其记录为未验证项。

## 3.2 证据优先

每项结论都必须尽量关联实际证据：

- 文件路径。
- 函数、类型或导出名称。
- 对应测试文件。
- 相关测试用例。
- 必要时记录 Git commit。
- 若运行了命令，记录命令与实际结果。

不能仅根据 README 中的描述，就认定功能已经在代码中实现。

不能仅根据文件名，就认定某个模块已经具备目标能力。

## 3.3 区分四种状态

对每项待调查能力，必须标记为以下状态之一：

| 状态 | 含义 |
|---|---|
| `implemented` | 已在代码中实现，并有足够证据支持 |
| `partial` | 存在部分能力，但未覆盖需求 |
| `missing` | 已调查相关代码路径，确认没有对应能力 |
| `unverified` | 因缺少证据、运行条件或执行权限，暂时无法确认 |

`unverified` 不得自动转换为 `missing`。

静态代码检查发现实现，不等于实际运行已经通过。

# 4. 调查范围

## 4.1 A：项目架构与依赖边界

### 调查内容

阅读：

- 根目录 README。
- 项目 package / workspace 配置。
- 架构文档与资源格式说明。
- package 依赖关系检查脚本。
- 与资源生成、图集、动画、游戏运行时有关的模块。
- 现有测试目录与测试运行命令。

### 需要回答

1. 当前仓库采用什么 package 划分？
2. 资源生成、资源处理、资源验证分别位于哪里？
3. 资源格式由哪个模块定义？
4. 游戏运行时由哪个模块提供？
5. CLI 如何调用这些模块？
6. 是否存在可以直接复用的验证入口？
7. 新增验收能力会不会造成不合理的跨 package 依赖？

### 输出要求

形成模块职责表：

| 模块 / 文件 | 当前职责 | 相关接口 | 已有测试 | 对 Phase 1 的建议 |
|---|---|---|---|---|
| 待调查 | 待调查 | 待调查 | 待调查 | 复用 / 修改 / 不涉及 |

不得仅凭预期架构填充此表，必须以实际仓库为准。

## 4.2 B：资源包、图集与动画数据结构

### 调查内容

找到并阅读：

- 资源包 manifest。
- 资源清单。
- 图集 Schema。
- 动画帧及播放元数据。
- 资源尺寸、锚点和位置声明。
- 资源引用与路径解析。
- 资源包加载和验证入口。

优先追踪一条真实数据路径：

`资源产物 → 资源清单 → 图集 / 动画元数据 → 游戏配置 → 运行时加载`

### 需要回答

1. 当前资源包的正式格式是什么？
2. 图集和动画元数据由谁生成？
3. 动画帧如何表示、排序与引用？
4. 锚点、帧尺寸和帧持续时间如何表达？
5. 哪些字段是必填，哪些是可选？
6. 资源路径和资源身份如何确定？
7. 是否存在内容哈希、版本号或稳定资源 ID？
8. 是否已经有 schema 校验和引用完整性检查？
9. 哪些异常会被明确拒绝，哪些可能漏过？
10. 资源包格式是否足以支持后续验收报告关联？

### 重点风险

不得因为某个资源包能够成功解析，就认定其中所有动画均有效。

必须区分：

- Schema 合法。
- 文件存在。
- 文件可以解码。
- 元数据引用有效。
- 动画可以正确播放。

这些是不同层次的验证。

### 输出要求

列出真实的数据结构、相关文件路径、关键字段及其校验入口，并标明每一层已有的检查。

- 相关实验记录。

- `scavenger-actor idle` 两帧样本。

- 动画验收标准及其版本。

## 4.5 E：视觉审查能力

### 调查内容

检查是否已有：

- 动画帧预览。
- 动画循环播放。
- 基线与候选结果的并列展示。
- 帧序列查看。
- 游戏内效果截图。
- 人工审查记录。
- 视觉模型辅助分析。
- 可复用的图像比较工具。

### 需要回答

1. 当前能否独立查看全部动画帧？
2. 能否按指定顺序播放动画？
3. 能否在统一展示条件下比较两个版本？
4. 能否查看角色在游戏中的实际效果？
5. 是否保存人工审查结论？
6. 审查结果能否追溯到具体资源版本？
7. 是否已有视觉模型分析能力，且其结果是否被错误地当作确定性判定？

### 输出要求

将已有能力划分为：

- 可直接复用。
- 可通过少量改造复用。
- 需要新增。
- 目前无法确认。

不要因为当前没有独立的“视觉审查模块”，就断定没有可复用的预览页面或工具。

### 需要回答

2. 资源包如何被游戏加载？

# 5. 缺口判定规则

调查完成后，将发现的问题划分为以下类型。

## 5.1 缺失能力

确认当前不存在满足需求的实现。

例如：没有任何方式保存人工视觉审查结果，且没有可复用的现有机制。

## 5.2 已有能力但缺少覆盖

已有实现，但没有覆盖关键输入或失败场景。

例如：可以验证图集 Schema，却没有测试图集帧越界的情况。

## 5.3 已有能力但缺少追溯

已有检查或运行时测试，但结果无法关联到具体资源版本。

## 5.4 已有能力但尚未验证

静态代码中存在实现，但尚未运行对应测试，或者缺少足够证据证明其在真实环境下有效。

## 5.5 设计不一致

文档、Schema、代码和测试对同一行为存在冲突。

此类问题应先记录具体差异，不应在 Phase 0 直接修改代码或文档来消除冲突。

# 9. 给 Codex / Claude Code 的执行指令

请按以下顺序执行：

1. 读取仓库 README、架构文档、workspace 配置和相关模块说明。
2. 根据实际代码定位资源包、动画、图集、资源验证、CLI 和 Demo Runtime 的入口。
3. 顺着真实数据调用链阅读代码，不要只依赖关键词搜索结果。
4. 找到相关测试，并核对测试实际覆盖的行为。
5. 检查现有动画基准和资源产物，确认哪些证据可以被后续验收直接复用。
6. 在安全的前提下运行必要的只读检查或现有测试。
7. 为每项能力记录状态和证据。
8. 形成需求映射矩阵与缺口分析。
9. 提出 Phase 1 的最小实现方案，并明确文件级改动范围。
10. 最后提交调查报告，不修改业务代码，不新增功能。

**执行过程中如果发现现有代码已经满足某项需求，应明确标记为可复用，并提供证据。不得为了匹配需求文档而重复实现已有能力。**

如果关键能力无法运行验证，应标记为 `unverified`，并说明后续如何验证。

本阶段的成功标准不是新增代码量，而是让后续开发者可以根据一份有证据的现状报告，明确知道 Phase 1 应该修改什么、复用什么，以及哪些事情暂时不应该做。
