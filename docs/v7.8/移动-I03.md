## 1. 能力边界与冻结约束

### 1.1 NB 三状态（不得混用）

1. **接线完成**：生产链路能够消费内部 NB 候选及其 Witness。
2. **证据准入通过**：几何可信度、时序覆盖、lag 语义、Witness 完整性等公共准入条件全部通过。
3. **`PUBLIC_NB` 开放**：只有第 2 项通过，并经过独立审查和授权，才允许发布公共 `NO_PROVEN_BLOCKER`。

**接线完成 ≠ 证据准入 ≠ 公共开放。**

### 1.2 PU 独立链

`PUBLIC_PU` 持续 `BLOCKED`，至少需要：`coverage.geometry = checked`、空中控制 / 模型外规避闭合、hop 图割与加倍采样完整、I-00 六项 PU 条件全部满足、独立审查与增量授权。不得因 NB 通过而推导 PU 可用。

### 1.3 六条冻结边界（来自前沿裁定）

1. `PUBLIC_NB` 接线完成 ≠ `PUBLIC_NB` 开放。
2. `PUBLIC_PU` 不属于第一阶段实施目标。
3. I-02 的 `publicCapability=BLOCKED` / `publicResult=null` 保持原样；适配层只消费，不回写 / 篡改。
4. `INSUFFICIENT_EVIDENCE` 必须保留为独立状态，不能映射为 `NO_PROVEN_BLOCKER`。
5. 时序结果第一阶段不改变 `publish-gate` 的拒稿行为。
6. 授权包签署只建立后续实施依据，不自动授权所有实施单元。
