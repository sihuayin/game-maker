# Level Playability V1.1 — I-01 阶段需求

**基线：** `main` @ `29ea1d1`  
**依据：** `docs/v7.8/移动.md`、`docs/v7.8/移动-I00.md`  
**阶段：** I-01 独立授权准备

## 1. 目标

建立可信的时序分析输入，确保 Hazard 碰撞几何来自经过验证的 Atlas 文件，并为时序分析提供显式、可复核的帧延迟参数。

本阶段只解决输入可信度，不实现时序可达性算法。

## 2. 实施范围

### 2.1 Atlas 可信读取
- 从 AssetPackManifest 指定位置读取 Atlas JSON。
- 对读取字节计算 SHA-256，并与 Manifest 校验值比对。
- 解析和几何校验必须使用同一份已校验字节，避免 TOCTOU。
- 逐帧核验 `sourceSize` 与 `anchor`。
- 无法确认文件身份或几何可信度时，返回 `INSUFFICIENT_EVIDENCE`。

### 2.2 延迟参数
- `lagMs` 必须显式传入，不设隐式默认值。
- 支持分别以 `16.67ms` 和 `200ms` 运行分析。
- 两档结果不一致时，降级为 `INSUFFICIENT_EVIDENCE`。
- Pipeline 使用唯一具名的 `200ms` 基准常量。

### 2.3 测试
新增 `playability-temporal-input.test.ts`，覆盖：
- 正常 Atlas 读取与 SHA 校验。
- SHA 不匹配、文件缺失、JSON 无效。
- 逐帧几何缺失或不一致。
- 文件替换及 TOCTOU。
- `lagMs` 缺失、非法值及两档结果不一致。
- 伪造 hitbox、body、尺寸或垂直规避声明不能获得确定性结论。

## 3. 验收标准

- 所有时序输入均可追溯到已校验的 Atlas 字节。
- 几何与 Manifest 不一致时不得产生确定性结论。
- `lagMs` 显式传入，无隐式默认。
- 两档延迟结果不一致时必须降级。
- 新增测试全部通过。
- 既有 Vitest 全绿，LP-06/07 scratch 语料复跑结果一致。
- 不删除或放宽既有测试断言。

## 4. 范围限制

本阶段禁止：
- 实现 I-02 连续时间求交、witness 或图割算法。
- 修改 Runtime、CLI、MCP。
- 新增依赖。
- 修改持久化 Schema 或 `ConfigIssue.code`。
- 修改 I-00 白名单以外的文件。
- 使用付费模型或产生付费调用。
- 推送 main、自动合并或启动后续阶段。

## 5. 停止条件

出现以下任一情况，立即停止并提交证据，不得绕过：
- Atlas 字节无法与 Manifest 稳定绑定。
- TOCTOU 无法可靠关闭。
- 需要修改白名单外文件或既有测试断言。
- 两档延迟无法满足确定性要求。

必要时返回 I-00 重新裁定范围。

## 6. 授权规则

当前仅准备 I-01 独立授权，不构成生产代码实施授权。

I-01 必须单独获批并以独立 PR 实施。完成后提交测试、回归和范围审计证据，复核通过后再申请 I-02 授权。

**完成定义：** 输入可信性与延迟参数接线通过验收；不宣称已实现移动 Hazard 时序可达性分析。
