## 1. 能力声明（冻结后的承诺边界）

> 系统能够在**可信输入**与**确定性运动假设**成立的条件下，对**单个沿 X 轴运动**的 Hazard 进行受限时序可达性分析，并对安全窗口、正宽度永久封锁及证据不足作出符合既有三态语义的判断。

**不包含**：

- 通用动态障碍物规划；
- 多移动 Hazard、Moving Platform、Danger 联合；
- 跳跃 / 下落 / 重力与 Hazard 的精确时序耦合；
- 生产运行结果的持久化追溯（见 §9）。

## 3. 输入输出契约

### 3.1 输入

| 输入 | 来源 | 必填 | 验证规则 | 失败 |
| --- | --- | --- | --- | --- |
| `GameConfig` | 现有 | 是 | 现有 schema | IE |
| `AssetPackManifest` | 现有 | 是 | `verifyPack` 通过 | IE |
| **Atlas JSON 字节** | pack 内 `meta` 指向的文件 | 是 | **与 manifest `files[]` 同一份字节**；读取后立即校验 SHA-256，解析与比对用这份字节 | IE |
| `FixedRuntimeProfile` | 现有 | 是 | 固定实例 | — |
| Hazard 运动描述 | `Motion` + `Entity.at` | 是 | `cycle` / `x` / `distance>0` / `periodMs>0` | IE |
| 分析范围 | `config.world` + 起点 / 目标 | 是 | 起点盒与终点在范围内 | IE |
| `lagMs` | 显式入参 | 是 | 有限非负数；**无隐式默认** | IE |
| `T_arr`（抵达时刻） | 可选 | 否 | 若提供须可追溯 | 按 §5 处理 |

**TOCTOU 条文**：禁止「先 `verifyPack`，再重新读取可能被替换的文件」。读取、哈希校验、几何比对必须使用同一份字节。

### 3.2 输出

沿用 V1 `PlayabilityVerdict`。新增：

- `coverage.temporal`（§8）；
- `PlayabilityEvidence` 的可选字段 `model` / `lag` / `degradation` / `limits`（§9）。

不新增持久化 verdict、不新增 `ConfigIssue.code`。

## 4. 运动模型

1. 单 x 轴；`Motion.kind` 必须为 `cycle`；`periodMs` 为**往返整周期**。
2. `t = 0` 时锚点位于 `at`；折返点在 `t = periodMs/2`，两端不停留。
3. **相位当自由变量**：不假设玩家首次看到 Hazard 时它恰好在 `t = 0`。
4. **U9（安全等待格）**：相位自由的前提是存在**可达、可等待、且等待过程本身安全**的安全等待格。三者须逐一证明；地图上有一个空格不等于 U9 成立。
5. 模型外（y 轴、多移动 Hazard、Moving Platform、Danger 联合、非 `cycle`、状态转换）⇒ IE，不得静默近似。

## 5. 时间、相位与 `lagMs`

1. 只用 **game-time**；禁止墙钟相位判据。
2. `lagMs` **必填**；核心 API 每次只接受一个值，内部不得有第二个默认值。
3. 上层编排以两档（**16.67ms / 200ms**）分别调用并比较；**两档结论不一致 ⇒ IE**。
4. 200ms 是 `smoothStep` 下 `delta ≤ 200ms` 的**源码上界推导值**，不是实测延迟。
5. 不得复用 `mechanic.ts:62` 的 `FRAME_MARGIN_MS`。
6. `T_arr` 无法确定且 U9 不成立 ⇒ IE。

## 6. 几何、网格与容差

1. **相切语义**：与 `overlapsStrict` 同义（贴着不算撞）。须由 I-01 补一条 Phaser overlap 的直接证据；若推翻，改的是 Runtime 语义基线。
2. **实现方式**：必须解析求交（折返点切段），不得逐点采样。
3. **门宽**：`R − L > ε`，不设语义阈值。
4. **容差**：单一具名常量 `ε = max(1e-9, 1e-9 × (xMax − xMin))`，只在一处定义。
5. **网格**：`N ≥ 2`；`N ≤ floor(maxSpeed × periodMs / xStep)`；在可行上界内取最大 `N`，再受 `maxStates` / `timeBudgetMs` 约束；空区间或预算耗尽 ⇒ IE。
6. **不得**要求 `v_hazard × dt ≤ xStep`——可靠性来自解析求交，不来自采样密度。

## 7. 三态判定

### `PROVEN_UNPLAYABLE`（六条同时成立）

1. 门区恒覆盖：`R − L > ε`，任意相位、任意合法 lag 位姿下都被覆盖（**交集，不带 pad**）。
2. 全部参与判定的几何 `checked`；Hazard 帧几何通过 §3.1 信任链。
3. 含 hop 边的移动图上起点与终点不连通（门区外扩后经 `forbiddenBoxes` 注入）。
4. **hop 采样加倍不变性**：采样密度加倍后连通性结论不变。
5. 模型外规避已排除。
6. 两档 lag 结论一致。

### `NO_PROVEN_BLOCKER`

存在连续时间验证过的安全 witness，且两档 lag 结论一致；必须携带 `coverage.temporal = checked`。**不代表关卡可玩。**

### `INSUFFICIENT_EVIDENCE`

其余全部，不得被提升。

### 禁止

- BFS 无解 / 预算耗尽 / 采样未撞 ≠ PU。
- 任一必要几何证据非 `checked` ⇒ 不得输出确定性结论。
- 调用方的 `verticalEvasionImpossible` 标记一律不接受。

## 8. coverage

1. 新增**内存内** `coverage.temporal`（`checked` / `partial` / `unknown`）。
2. `coverage.spatial` 行为一字不改；不得因它恒为 `partial` 而回退 9 个既有用例。
3. 移动 Hazard 的机制判定必须检查 `coverage.temporal`：非 `checked` ⇒ 机制层 IE；`checked` 才进入时序判定。
4. `temporal = checked` 只表示输入与模型检查完成，**不代表已证明可通行**。
5. **顶层优先级**：时序层证据不足不得被聚合成 `NO_PROVEN_BLOCKER`；须有覆盖顶层聚合路径的测试。

## 9. 证据格式与「可审计」的边界

- 在 `PlayabilityEvidence` 上加法：`model` / `lag` / `degradation` / `limits`。
- 不改 `ConfigIssue`、不加 `code`、不新增持久化 schema、不引入落盘证据链。
- **「可审计」= 测试 + 冻结契约 + scratch 原始证据 + 审计过程可复核，不是生产运行结果可持久化追溯。**

## 12. 性能预算与降级

- 默认 `maxStates = 500_000`、`timeBudgetMs = 2_000`；硬上限 1M / 10s。
- 常量写在机制层模块级（对齐 `completion.ts:68,70` 与 `mechanic.ts:281-284`），不进 `GameConfig` / profile / 公开 API。
- 超限：**逐层降级**（仅移动 Hazard 层 IE + `coverage.temporal = partial`），不允许部分 witness / proof；预算耗尽是单向 `SAFE → IE`。
- 墙钟只用于搜索预算与展示，不得参与物理 / 时序判断。

## 13. 非目标、停止条件与退出条件

**非目标**：见 §1。另加：不新增 CLI / MCP 参数；不扩展 Manifest 契约；不修改 Runtime。

**停止条件（必须回 HITL）**

- 需要改白名单外文件；
- 需要放宽任何 G-01～G-07；
- 需要删除或放宽既有测试断言；
- 发现模型外规避无法排除却想输出 PU。

**退出条件**

- G-01 无法满足 ⇒ 缩范围（PU 不启用）；
- hop 加倍不变性系统性失败 ⇒ 缩范围；
- 19 个既有移动 Hazard 关卡出现假阳 ⇒ 回滚该类别启用；
- 前置条件不成立 ⇒ 停止 effort。
