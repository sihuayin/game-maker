## Answer

**裁定日期**：2026-11-03 · **裁定人**：amber · **性质**：HITL。Q1–Q3 均接受推荐方案（A/A/A）。

### 1. 方案票粒度（Q1 = A）

- **一份合并方案票**，覆盖所有修复项；另开一张**收口 / P1 审批包票**。
- 方案结构（每节独立）：
  1. B-02 — reachability deterministic 审计
  2. D-01 — viewport 贯通
  3. D-02 — role 提示词贯通
  4. D-03 — modelHard 归因与受限重采样反馈
  5. publish-gate — standalone site / assemble_site 的 reachability 复验（第五节）
- 每节必须含：当前缺口与 E1/E2/E3 证据、修复判据、最小修改面、测试矩阵、零付费验证、
  风险与回退条件、契约变更候选（如有）。
- 跨项测试集中呈现，至少覆盖：B-02 × D-03（config-audit / 重采样）、
  D-01 对 VDS / 编译 / QA / site 的贯通、D-02 与 B-01 的边界
  （只保证 `role` 可见，不建立机读语义分类）。
- 收口票负责完整审批包，不重复方案票的技术研究。

### 2. publish-gate 归属（Q2 = A，新增第五项）

- 接受有证据的范围变更：**4 项 → 5 项**；原子项逐项裁定原则不变。
- publish-gate 是独立缺口，**不并入 B-02**：B-02 解决 config pipeline 的 deterministic
  reachability；publish-gate 解决 standalone `site` / `assemble_site` 缺独立复验；
  B-02 修复不自动覆盖。
- 第五项严格限定：
  - **默认**：在 `publish-gate.ts` 现场重跑 `auditReachability`；不改契约；
    不扩大到完整 config-audit 或身份绑定体系。
  - **备选**：`subject.configChecksum` 等契约式身份绑定；只列备选审批候选，不默认采用。
  - **明确排除**：第七条 `visual-config-coherence`；需要 VDS/design 身份或 runDir 的
    跨阶段一致性；不包装成完整 publish-gate 身份完整性修复。
- 第七条单独进入 Q8 推迟交接，避免本轮局部修复与未来统一身份方案混淆。

### 3. 契约批准时点（Q3 = A）

- 方案票只提出候选，**不授予契约批准**。
- 本轮单列：
  - B-02 可选 `unreachable` 错误码：提出、比较替代方案，**不批准**。
  - D-01 可选 `UnderstandingInput.viewport`：提出、比较替代方案，**不批准**。
  - publish-gate `subject.configChecksum`：**备选**，不默认采用。
  - D-03 对外归因码：**不纳入当前方案**；优先内部纯函数分类。
- 收口票 / P1 审批包逐项呈现：变更内容、必要性、不改契约的替代方案、影响面、
  不实施的后果、兼容性/迁移要求、明确的批准问题。
- **方案票 HITL 结论 ≠ 契约批准**；任何候选在收口审批前保持未批准。

### 4. 最终边界确认

- 五项进入同一份方案，不代表五项必须一次性批准。
- 契约候选可在方案中充分论证，但本轮不批准。
- publish-gate 只处理 `reachability`；第七条不扩进来。
- 零付费验证 ≠ 付费模型效果验收。
- 本图仍不修改生产代码、不改变契约、不启动付费调用、不生图。
