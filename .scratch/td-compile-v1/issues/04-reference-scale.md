# 04. 「参考刻度」是多少、它在提示词里长什么样

Type: task
Status: open
Owner: —
Blocked by: —
Map: ../map.md
> 模型不知道「20 血的敌人配 5 点伤害的塔」是什么手感。这一票把那份手感**量成数**。

## Question

提示词里要给一份**数值参考刻度**（画图时定的口径：靠提示词给，不靠代码夹住 ——
夹住等于让代码替模型做设计）。这一票要把它产出来。

要答的几件：

1. **刻度从哪来**？用 `probe/td-balance.mjs` 扫一遍邻域，找出「赢得不勉强」的那一段区间？
   ⚠️ **2026-09-29 改**：原文在这里写「`docs/counter-siege.md` 里那张五波曲线」——
   **那张表不存在**（[票 02](02-reference-player-strategy.md) 决议时核对了）。
   而且要当心：票 02 刚把参考玩家**换成了一把强得多的尺子**，于是
   「这一关现在打起来是什么手感」这个数**已经变了**（20/20 零漏）。
   ⇒ 这一票量刻度时，**必须用换完之后的玩家**，且**不要把「多少声望活下来」当成难度** ——
   票 02 把**难度**判给了观察：刻度要回答的是「这份配置的数值在不在一个能玩的量级上」，
   不是「它有多难」。
2. **写成什么形态**？一张表（塔 / 敌 / 经济各一行）？一段散文（「第一波 6 个 20 血的敌人」）？
   还是**直接引用几个量级**（伤害个位数、护甲 0–2、开局废料一位数乘 20）？
3. **怎么说清「这是参考不是规定」** —— 否则每一关都会长成同一关。
   ⚠️ 这一条是这一票里最容易做错的地方：`game-creation-v1` 的
   [「提示词里的示例错了，模型就会以一种看起来没问题的方式错」](../../game-creation-v1/issues/49-compile-game.md)
   是同一条教训的另一面。
4. **它要不要也是可断言的**？刻度里的数如果与关卡格式的约束冲突（比如写出一个过不了
   schema 的值），那就是第二个「提示词教模型写一个会被自己拒收的形状」。

⚠️ 它进的是**提示词**（对每一关都成立），**不是需求文本**。需求保住「一段自由文本」这个形状
是仓库已有的裁决。
