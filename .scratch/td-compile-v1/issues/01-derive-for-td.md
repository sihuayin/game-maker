## Question

真跑一次 `derive`（一段塔防需求 + `fixtures/style-spec.json`），看它产出的资源清单能不能满足塔防那一关。

**判据是这一个**：它会不会自己产出「**砖**」这个概念？

塔防的场地是**一格格砖**（`arena.tiles` 把字符绑到资源 id），而这是 2026-09-29 实测的结论：
这个管线画小物件稳、画 480×270 的整幅场景会退化成抖动条纹。如果 `derive` 按横版的习惯
产出一张「大背景图」，那么**塔防的 `arena` 根本表达不了它** —— 那一刻链条是断的，
而不是「差一点」。

要看的还有：它给不给得出五个角色（墙 / 地面 / 走道 / 装饰 / 入口）对应的五种砖。

**答案落在三种之一**：

- **能用** ⇒ 终点第一句成立，什么都不用改，只需把这份清单固化成 fixture。
- **差不多能用** ⇒ 要改 `derive` 的提示词（改什么，是下一张票）。
- **不能用** ⇒ 塔防这条链的资源清单**继续手写**（那是 `ops.ts:264` 明写着一等路：
  「配置是文件，人可以直接写一份」），终点那句改成「`pack` → `compile-td-game` → `site`」，
  而 `derive` 那条留在 **Not yet specified** 里等下一张图。

⚠️ **先跑，别先改** —— 这一票只回答「它现在给什么」，改提示词是它答案的下游。

## Answer

**✅ 2026-09-29 已决议 —— 「能用」**，但带一条**需求侧的前提**，而那条前提今天没有任何东西保证。

### 两次真跑（这是这一票的全部依据）

同一个 StyleSpec，只改需求里**描述场地的那一段**：

|  | **A**：需求点名要砖 | **B**：天真作者（只说「店铺的场地」） |
|---|---|---|
| 资源数 | 21（sprite×11 · animation×4 · ui×5 · background×1） | 16（background×1 · sprite×7 · animation×4 · ui×4） |
| **砖** | **5 块 15×15 的 sprite** | **一块都没有** |
| 场地 | 砖（`tile-floor` / `tile-walkway` / `tile-shelf` / `tile-wall` / `tile-shutter-door`） | 一张 **640×360 的三层大背景图** |
| 出包 | ✅ 真跑了 `pack`：21 资源 · 4 张图集 · 43 文件（1 次重试） | 没跑 —— 塔防的 `arena` **表达不了**它 |

⚠️ **关键在于 `derive` 的提示词里一点玩法知识都没有** —— 它只有四条关于
`sprite`/`animation`/`background`/`ui` 的**格式**规则，需求原样插进去。
所以它是一台**照需求列资源**的机器：需求说了砖，它就给砖；需求只说了「场地」，它就给一张大图。

A 甚至读对了「32 列 × 18 行，每格 15 像素」这半句，产出的砖是 **15×15、锚点 {0.5,0.5}**，
与 `arena` 要的形状严丝合缝。预览里五块砖**一眼能认出来**（走道有防滑凸条、货架有箱子、
卷帘门有帘片加警示斜纹），柜台与三台机关也读得出来。

### 三条附带发现

1. **A 里那张 `bg-shop-floor` 是零消费者** —— `td-config` 没有 `scene.background`，
   塔防的场地整个由 `arena` 的砖铺出来，那张图没有任何东西会引用它。
   ⚠️ **我原本猜它会撞上票 50 那条「最远那层必须画满」——量下来它 100.0% 画满，不撞。**
   所以这条只是「清单里多了一个用不上的资源」，不是「会被拦下」。
2. **两份清单都给全部 `ui` 套了 `ninePatch`** —— 两个 16×16 的图标、一块 15×15 的括弧都是。
   病根在提示词的**形状示例**：`ui → "ninePatch":{...}` 被写成了 ui 的样子，
   没说「只有要拉伸的才写」。⚠️ 这正是那张老图上「**提示词里的示例错了，模型就会
   以一种看起来没问题的方式错**」的同一条（票 40 / 票 49）—— 它产出的形状
   **过得了 schema**，只是语义错了。→ 已毕业成新票。
3. **两次跑的 id 不一致**（A：`trap-searchlight` / `enemy-mech-dog`；B：`trap-spotlight` / `enemy-mechdog`）。
   这是采样的固有性质，但它有一条对链条的推论：**`compile-td-game` 绝不能写死任何 id**，
   必须从给它的 manifest 里读 —— 而那正是它的设计（它拿的就是包）。这不是缺口，是一条**已成立的前提**。

### 落在三支里的哪一支

**第一支（能用）**，但要把它的条件说准：**不是「`derive` 能用」，是「`derive` + 一份说清楚的需求」能用**。
终点第一句因此成立，塔防这条路**不需要**改 `derive` 的玩法理解，清单也**不再手写**。

⚠️ **而这条前提的风险在于它失败得安静**：B 那份清单**完全合法**，`pack` 会照常出包，
一路到 `compile-td-game` 去绑 `arena.tiles` 时才会发现包里没有砖 —— 而那时它多半不会报错，
只会**拿别的图当砖铺满 576 遍**（`arena.tiles` 只要求引用解得开，**不要求砖的尺寸对**）。
那一半已毕业成新票。
