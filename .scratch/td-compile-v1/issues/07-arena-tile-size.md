# 07. `arena` 的砖尺寸要不要校验（以及那条需求侧前提落在哪）

Type: grilling
Status: resolved
Owner: amber（2026-09-29 认领）
Blocked by: —
Map: ../map.md
> 由 [`derive` 对塔防需求产出的清单能不能用](01-derive-for-td.md) **决议时顶出来的**。
> 那一票量到：需求不说清「场地是一格格砖」时，`derive` 会给出一张 640×360 的大图，
> **一块砖都没有** —— 而那份清单**完全合法**。

## Question

`arena.tiles` 今天只要求**引用解得开**。它**不要求砖的尺寸与 `arena.cell` 相当**。

于是最危险的后果不是「包里没有砖」（那会当场被引用族拒），而是——

> **拿一张 640×360 的 background 当成砖，铺满 576 遍。**

那条路**过得了今天全部校验**（引用解得开、几何族只管场地铺不满），
产出一张糊掉的图，而**没有任何东西会报错**。这正是仓库最怕的那一类失败。

要答的几件：

1. **加不加这条硬校验**？判据是什么 —— `size.w === cell && size.h === cell`？
   还是「在一个区间里」（比如 `0.75×cell ≤ size ≤ 1.5×cell`）？
   ⚠️ 门槛是仓库那条：**精确可算 + 错了一定不是设计**。砖比格子大一点点是不是设计？
   如果要留余量，那个余量凭什么？
2. **它算哪一族**？自洽族（硬失败）还是几何族？
   ⚠️ **2026-09-29 改**：原文在这里写「注意几何族住在 demo 包里，而 `compile-td-game` 在 assets 包里
   —— 这正是票 03 要解的同一个结」。**那个结已经解了**
   （[票 03](03-screen-space-seam.md)：校验函数住在 **contracts**、视口等参数传进去）。
   所以这一问现在只剩「算哪一族」，**不再有「放不放得下」的问题**。
3. **那条需求侧的前提落在哪**？「写塔防需求的人必须说出场地是砖」——
   (a) 写进 `inputs/README.md`（照 `docs/stylespec-extraction.md` 那份操作规程的样子）；
   (b) 靠上面那条校验**在构建期响亮地失败**；(c) 两者都要。
   ⚠️ (b) 单独一条**不够**：它拦得住「砖尺寸不对」，拦不住「作者根本没想到要写砖」——
   那时检验会在很远的下游才响，而响的时候人已经不知道是哪一步错了。
4. **`derive` 要不要为塔防做点什么**？⚠️ 先别急着答「要」——
   `derive` 的提示词是**玩法无关**的，教它「塔防要有砖」等于把玩法知识埋进一个
   声称与玩法无关的提示词里。而 A 那次证明**需求说清楚就够了**。
   所以这一小问多半是「不要，把要求写在需求那一侧」（(3) 的 (a)）。

### ⚠️ 2026-09-29 补一问（由票 05 顶出来）

[第一版塔防提示词 + 可断言的骨架](05-first-td-prompt.md) 真跑了一次，量到一件与这一票同源的事：

**需求里没有布局信息时，模型会照抄示例里那张地图。**
`inputs/counter-siege/PROMPT.md` 说了「五种砖」、说了「从东头卷帘门走到西端柜台」，
**但没说货架在哪、走道几折** —— 于是模型手上唯一的布局就是提示词里那个骨架，
而**它照抄是理性的**（我加的那句「不要照抄」完全没用）。

⇒ 所以「需求侧那条前提」不只是**砖**，还有**布局**。这一票的第 3 问要从
「写进 `inputs/README.md`」扩成：**塔防的需求要不要有一份可查的写法规程**
（像 [`docs/stylespec-extraction.md`](../../../docs/stylespec-extraction.md) 那份一样，
含可直接复制的提示词）—— 里面至少要交代「场地是砖」与「布局画在哪」。

## Answer

**✅ 2026-09-29 已决议。** 加这条硬校验，而且它比票面想象的**更准也更宽** ——
**锚点也在里面**，而「种类」那一半**已经在**了。

### 实验：那条静默失败真的会发生，而有一半被意外兜住了

把 `arena.tiles` 指向别的东西，看在今天的校验下会怎样：

| 指向… | 今天 |
|---|---|
| 一张声明成 `background` 的 480×270 大图 | ❌ **拦下了** —— 种类不对（`arena.tiles` 要 sprite/animation） |
| 一张**声明成 `sprite`** 的 480×270 大图 | ✅ **全过 —— 没有任何东西拦得住** |
| 40×32 的 `core-counter` 当走道砖 | ✅ **全过 —— 没有任何东西拦得住** |

⇒ 种类那一半**已经在**（引用族顺手挡掉了 background），而**尺寸与锚点完全没有人管**。
没有被挡住的那些，后果是：那 576 格**各画一张 480×270 的图叠在一起**，而不报错。

### 四条决议

| # | 决定 | 依据 |
|---|---|---|
| Q1 | **加硬校验**：砖的尺寸**精确等于** `arena.cell`（宽高都要）**且锚点在正中**；三种不行（比 cell 大 · 比 cell 小 · 锚点偏）**都是硬失败** | **两个真包的砖都是 15×15、锚点 `{0.5,0.5}`** ⇒ 这条判据**不误伤任何一个真产物**。比 cell 大 ⇒ 每格**盖住邻居**；比 cell 小 ⇒ 格子间**留缝、透出外壳底色**；锚点偏 ⇒ 整张地图**偏半格**。三条都不会是设计，且**三条都不会自己报错** —— 正好落在「精确可算 + 错了一定不是设计」那一侧 |
| Q2 | 算**引用族** | 它与**已经在那儿的那条**是同款：「`hud.panel` 必须是 `ui` 类」说的就是「你引用的那个东西的**性质**符不符合这里的要求」。种类是这条防线的一半，尺寸与锚点把它**补完整** |
| Q3 | **两份都做**：(a) 一份**塔防需求写法规程**（像 [`docs/stylespec-extraction.md`](../../../docs/stylespec-extraction.md) 那样，含可直接复制的提示词）+ (b) 上面那条校验 | 票 05 量到「**需求没说的，模型只能拿示例填**」—— 不只**砖**，还有**布局**（它照抄了骨架那张地图）。校验只拦得住「砖尺寸不对」，**拦不住「作者根本没想到要写场地」**，而那种错在很远的下游才响、响时人已不知是哪一步错了。规程把这道错**挪到写需求那一步** |
| Q4 | **`derive` 不为塔防做任何事** | 票 01 量过：它的提示词**一点玩法知识都没有**（只有四条格式规则）。教它「塔防要有砖」＝把玩法知识埋进一个**声称与玩法无关**的提示词里。而那一次也证明了：**需求说清楚就够了** |

### 一条副产品：`砖` 进了词汇表

这个词在仓库里到处在用，从没定义过。这一票给了它精确含义（三条构造上可判的性质），
