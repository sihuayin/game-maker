## Question

写一份**粗糙的**第一版，**真跑一次**，看它产出什么。要包括：

1. **五个角色的图例** —— 字符固定 `#` 墙 · `.` 地面 · `=` 货架 · `:` 走道 · `+` 卷帘门；
   每个角色绑到哪个资源 id 由模型在 `arena.tiles` 里填。图例要教到「模型只需要**画图**，
   不需要同时设计一套词汇」。
2. **那张 32×18 的地图怎么描述才画得对** —— 最难的一条是**「走道要从入口一直通到柜台」**，
   以及「不要把走道画碎」。⚠️ 校验器只判「路径穿过的格是走道砖」，
   它判不了「走道像不像一条路」—— 所以这一段文字是**唯一的**保障。
3. **九条「铁律」的塔防版** —— 照 `ops.ts:268–308` 那条先例（每条都会被校验器检查、
   违反直接拒收）。塔防这边至少要有：顶层十一块键、坐标是整数、`walkChar` 必须在 `tiles` 里、
   `path.points` 轴对齐且不许有点重合、插槽不许压在走道上、
   `core` 的位置**由路径终点派生所以不要写**、波次的 `enemy` 必须存在于 `enemies`。
4. **`tdConfigExample`** —— 带类型的导出（`packages/assets/src/` 里，与 `gameConfigExample` 并列），
   测试断言它过 `parseTdConfig`；资源 id 一律写占位符（像 `"<墙砖的 id>"`），
   否则示例会把某一关的 id 焊进提示词。**它里面那张 18 行地图是这一票最值钱的一段** ——
   逐字给出「一行多长、五个字符怎么摆」，比任何文字描述都准。
5. **数值参考刻度**（来自票 04）+ **资源包清单**（`resourceBrief` 的塔防版，
   要能说清「哪个资源是砖」）。

**跑一次要看的**：产出的地图**画得像不像一个铺子**（人眼）· 走道**连没连通** ·
它挑的砖**对不对** · 校验器**拒没拒** · 以及拒的时候那条消息**指不指得出它在说什么。

⚠️ **提示词住 `prompt.ts`**（画图时定的口径），骨架导出住它旁边 ——
但**不要把 `compileGame` 那份搬过去**。

## Answer

**✅ 2026-09-29 已决议（原型跑通了，但它交出两条坏消息）。**

第一版提示词**真的产出了一份关卡** —— schema 全过、零硬失败零警告、装得出站点、
在无头 Chrome 里真的在跑。**但**：它**照抄了骨架里那张地图**，而且那一关**打不赢**。

### 过程：跑了两次

| 次 | 结果 |
|---|---|
| 第 1 次 | ❌ **过不了 schema**，三条，全是**提示词没给形状**：`slow` 被写成数字 `0.75`（要 `{factor,ms}`）、`aoe` 塔带了 `projectile` 且 `speed: 0`（aoe 不抛东西，它要的是 `fx`） |
| 修法 | 骨架里**加一座 aoe 塔**，把 `slow` 与 `fx` 的形状逐字给出来；铁律里补「aoe 不写 projectile」 |
| 第 2 次 | ✅ **schema 全过 · 0 硬失败 · 0 警告 · 装得出站点 · 浏览器里在跑** |

⚠️ 这与老图上那条教训同源：**提示词没给的形状，模型会自己猜，而它猜错的方式看起来很正常**
（`slow: 0.75` 读起来完全合理）。骨架必须**逐字**给形状 —— 这正是 `tdConfigExample` 存在的理由。

### 票面那五问的答案

| 要看 | 结果 |
|---|---|
| 地图**像不像一个铺子** | 勉强 —— 读起来是「网格 + 一条走道 + 几条货架带 + 一个柜台」，与我手写的那关**没有可见区别**。**但它是抄的**（见下） |
| 走道**连没连通** | ✅ 连通（校验器也确认：路径穿过的每一格都是走道砖） |
| 它挑的砖**对不对** | ✅ 全对：`#`→`tile-wall` `.`→`tile-floor` `=`→`tile-shelf` `:`→`tile-walk` `+`→`tile-door` |
| 校验器**拒没拒** | 第一次拒 3 条，第二次 0 条 |
| 拒的消息**指不指得出** | ✅ 指得出：`towers.1.levels.0.slow: Expected object, received number` —— 直接点名到字段 |

### ⚠️ 坏消息一：「不要照抄示例」那句话**没用**，而根因不在话上

我在提示词里写了「骨架里那张地图**是行格式的演示，不是一张可以拿来用的地图**……照抄它 = 没有按需求设计」。
**它还是照抄了** —— 只在顶端多加了一行走道（两格宽的走道，而路径只走上面那一格）。

根因不是话不够硬：**是需求里没有布局信息**。`inputs/counter-siege/PROMPT.md` 说了「五种砖」、
说了「敌人从东头的卷帘门进来、沿着走道走到西端的柜台」，**但没说货架在哪、走道几折**。
⇒ **模型手上唯一的布局就是示例**，它照抄是**理性的**。

⚠️ 这与票 01 那条是同一个形状：`derive` 是「照需求列资源的机器」，**这一台是「照需求画关卡的机器」**
—— 需求没说的，它只能拿示例填。

### ⚠️ 坏消息二：编译出来的那一关**打不赢**，而**数值全在刻度内**

拿几何玩家跑一遍（票 02 那个决定的复现版）：

| | 结果 |
|---|---|
| 我手写的（9 插槽） | **won** · 声望 19/20 · 建 9 升 2 · 漏 1 |
| **模型编译的（6 插槽）** | **lost** · 第 5 波被抢空 · 声望 **0/20** · 漏 **20** |

而它的**数值一个都没出刻度**（伤害 4–20 · 血量 14–70 · 护甲 0 · 造价 40–70 · 开局 120 · 5 波）
⇒ **病灶不在数值那一维。**

定位（把两半拆开换）：

| 组合 | 结果 |
|---|---|
| 编译的波次 + **手写的 9 个插槽** | won，但**只活 2/20** |
| **编译的 6 个插槽** + 手写的波次 | **lost**，0/20 |

⇒ **两个原因各占一半**：**插槽只有 6 个**（而且都挤在上行走道那一侧，竖段没人管），
以及**第五波堆得太狠**（总血 **660** vs 手写的 522，只多 26%）。

⚠️ **而这与票 04 量出来的那条严丝合缝**：余量只有 **1.3–1.6 倍**，而模型**一次就把余量用光了**。
⇒ 刻度只教了「数值该多大」，**没教「覆盖」与「峰值」**。→ 已毕业成新票。
