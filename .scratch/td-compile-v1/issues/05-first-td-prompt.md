## Question

写一份**粗糙的**第一版，**真跑一次**，看它产出什么。要包括：

1. **五个角色的图例** —— 字符固定 `#` 墙 · `.` 地面 · `=` 货架 · `:` 走道 · `+` 卷帘门；
   每个角色绑到哪个资源 id 由模型在 `arena.tiles` 里填。图例要教到「模型只需要**画图**，
   不需要同时设计一套词汇」。
2. **那张 32×18 的地图怎么描述才画得对** —— 最难的一条是**「走道要从入口一直通到柜台」**，
   以及「不要把走道画碎」。⚠️ 校验器只判「路径穿过的格是走道砖」，
   它判不了「走道像不像一条路」—— 所以这一段文字是**唯一的**保障。
3. **九条「铁律」的塔防版** —— 照 `ops.ts:268–308` 那条先例（每条都会被校验器检查、
   违反直接拒收）。塔防这边至少要有：顶层十一块键、坐标是整数、`walkChar` 必须在 `tiles` 里、
   `path.points` 轴对齐且不许有点重合、插槽不许压在走道上、
   `core` 的位置**由路径终点派生所以不要写**、波次的 `enemy` 必须存在于 `enemies`。
4. **`tdConfigExample`** —— 带类型的导出（`packages/assets/src/` 里，与 `gameConfigExample` 并列），
   测试断言它过 `parseTdConfig`；资源 id 一律写占位符（像 `"<墙砖的 id>"`），
   否则示例会把某一关的 id 焊进提示词。**它里面那张 18 行地图是这一票最值钱的一段** ——
   逐字给出「一行多长、五个字符怎么摆」，比任何文字描述都准。
5. **数值参考刻度**（来自票 04）+ **资源包清单**（`resourceBrief` 的塔防版，
   要能说清「哪个资源是砖」）。

**跑一次要看的**：产出的地图**画得像不像一个铺子**（人眼）· 走道**连没连通** ·
它挑的砖**对不对** · 校验器**拒没拒** · 以及拒的时候那条消息**指不指得出它在说什么。

⚠️ **提示词住 `prompt.ts`**（画图时定的口径），骨架导出住它旁边 ——
但**不要把 `compileGame` 那份搬过去**。
