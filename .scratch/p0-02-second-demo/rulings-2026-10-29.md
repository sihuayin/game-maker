# P0-02 HITL 裁定记录（2026-10-29）

> 来源：wayfinder 票「预算授权」（`issues/01-budget-authorization.md`）。
> 本文记录用户逐字裁定；代理未代替用户选择。

## 1. 第一轮预算授权（Q1–Q5）

**用户逐字：**

> - Q1：c — 暂不授权付费，继续规划。22 次是冻结 run 的参考调用量，不是对新设计的可靠硬上限；新设计可能改变生图次数，且调用次数不能直接代表货币成本。后续预算票应明确金额上限或提供可验证的成本护栏，再决定是否授权。
> - Q2：a（有条件） — 计划沿用冻结 run 的文本与生图 provider，但执行前必须确认 provider 配置可用；不得读取、输出或记录密钥内容。若无法确认可用性，执行票阻塞。
> - Q3：b — 允许管线内部默认重采样，但必须在每次付费调用前检查剩余预算。若无法保证下一次调用不会突破已批准上限，则先停并报告；不做手工重试。
> - Q4：b — 当前不批准付费生图。只有在预算获得明确授权后，才能另行批准在上限内生成 A 的新视觉世界资源包。
> - Q5：a — 第二次完整运行必须另行取得 HITL 批准；仅允许更换输入，不改生产代码，也不得将两次运行的证据拼接成一次全绿结果。
>
> 预算票结论：暂不授权付费。 可以记录以上裁定并收口当前预算票，但 P0-02 的付费执行仍处于阻塞状态。下一张预算授权票应提供可核实的货币上限、调用成本估算及超限前停止机制；不能把“22 次调用”当作已获批准的支出额度。

## 2. 裁定要点（gist，非逐字）

- **第一轮预算：未授权**；P0-02 付费执行继续阻塞。
- `22 次调用`只是冻结 run 的参考量，不是新设计的硬上限，也不能直接代表货币成本。
- provider 计划沿用冻结 run；执行前确认可用性，但**不读取/输出/记录密钥内容**；无法确认则执行票阻塞。
- 允许管线默认重采样；每次付费调用前检查剩余预算；无法保证下一次不超限就停；无手工重试。
- 当前不批准付费生图；只有预算授权后才能另行批准。
- 第二次完整运行须另行 HITL 批准；只换输入、不改代码、不拼接两次运行。

## 3. 下一张预算授权票必须提供

1. 可核实的**货币上限**（金额/币种）；
2. **调用成本估算**（文本 token 单价 + 生图单次单价；按冻结 run 的实际用量）；
3. **超限前停止机制**（provider 硬限额或 effort 侧 watcher；不改生产代码）；
4. provider 可用性确认方式（不读取密钥内容）；
5. 明确批准/不批准付费生图，以及第二次运行规则。
