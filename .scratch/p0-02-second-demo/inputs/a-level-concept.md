# A · 屋顶信使 · 关卡概念

> 坐标与尺寸是概念稿；最终以 `game-config/v1` 生成结果为准，但必须满足下方硬约束。

## 世界

- 视口 / 世界高：`480 × 270`；`world.size.h` 必须等于 `270`。
- 世界宽：约 `2400`（5 屏），横向滚动。
- 背景层：天空 / 远景城市 / 中景建筑，三层各 `480 × 270`。
- 地面/平台：`solid` 屋顶、雨棚、水塔平台、天线平台；无 `hazard` / `danger` / 移动平台。

## 路线（概念）

| 段 | x 范围 | 高度（y，0 顶部） | 内容 |
|---|---|---|---|
| 起点屋顶 | 0–420 | 屋顶面 y≈220 | 玩家出生 x≈60；第 1 封信 x≈320、y≈180（需跳上雨棚） |
| 缺口 1 | 420–465 | — | 水平缺口 ≈45px（< 66px 上限） |
| 中段屋顶 | 465–960 | y≈220；雨棚 y≈170 | 第 2 封信 x≈900、y≈140（经雨棚/水塔） |
| 缺口 2 | 960–1010 | — | 水平缺口 ≈50px |
| 水塔区 | 1010–1480 | 水塔顶 y≈150；屋顶 y≈220 | 第 3 封信 x≈1480、y≈180；可选信箱 x≈1200、y≈180 |
| 缺口 3 | 1480–1525 | — | 水平缺口 ≈45px |
| 天线区 | 1525–2040 | 天线平台 y≈180 / 220 | 第 4 封信 x≈2100、y≈120（经两级平台） |
| 终点屋顶 | 2040–2400 | y≈220；钟楼门 y≈180 | `goal` 钟楼门 x≈2320；收集齐后到达即胜 |

## 硬约束对照

| 约束 | 本概念 |
|---|---|
| `world.size.h = 270` | 是 |
| 跳跃顶点 ≈ 60.5px | 所有向上台阶 ≤ 50px |
| 同高横跨 ≈ 66px | 所有缺口 ≤ 55px |
| 至少 1 个 pickup | 4 个 |
| gate 必须是 `kind:"goal"` | 钟楼门 |
| `pickupCount` 数 pickup + chest | 4 封（+ 可选 1 信箱；最终以 config 为准） |
| 玩家动画 `idle` / `run` / `jump` | 是 |
| 背景 480×270 | 是 |
| HUD panel + pip | 是 |
| 无 hazard / danger / moving | 是 |

## 可通关性自检（概念级）

- 每一段至少有一条连续路线；所有向上台阶 ≤ 50px、水平缺口 ≤ 55px；
- 4 封信都在路线可达的平台/雨棚上；gate 在最后一段屋顶；
- 可选信箱若生成，必须位于可达平台，且最终 scenario 会按 config 的 `pickupCount` 调整；
- 不保证 LLM 生成的最终布局一定可通关——这是 P0-02 要检验的风险之一。
