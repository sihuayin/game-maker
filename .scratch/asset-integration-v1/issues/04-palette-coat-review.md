> 派生自最终包的内容验收：32 色把外套的绿量化成棕。

## Question

裁定色板与角色配色的关系：

- 当前 32 色来自图 43；角色 DNA 的 palette 又是暗棕系 ⇒ 模型画的绿外套被量化成棕。
- 选项：A) 接受（风格 / DNA 一致，棕是正确结果）；
  B) 调整 DNA / 角色色板，让它从一开始就是棕（零付费数据改动，影响后续生成）；
  C) 调整 32 色提取（保留绿系），影响所有资源的量化，可能需要重生成。
- 若选 C / 重生成，另出付费报告 + 点头；本票只裁方向。

## 验收

- 一条明确裁定；若需要施工 / 重生成，另立票并注明范围。
- 记录对已交付包的影响（是否重建、哪些资源）。

## 边界

- 本票不跑付费上游；不改 `game-maker.local.json`。

## Answer（2026-10-20 · 人裁）

**Q1 = C · 追加 1–2 个橄榄/卡其色槽，从现有 raw 免费重新量化并重建。不发起任何上游调用。重建后进行一次视觉 QA，重点检查 `scavenger` 的外套与背包区分，以及 `scrap-resource` 的颜色变化。**

**Q2 = B · 允许以确定性提取色板为底进行人工策展。每次策展必须记录新增或替换的颜色、颜色值、色板下标、调整理由及可复现的重建依据。不得把策展后的色板描述为纯粹由图 43 确定性提取而来。**

**裁定原则（逐字）：**

> 色板是游戏的绘制词汇，而不只是参考图的颜色统计结果。若现有色板无法表达玩家外套与背包的视觉区分，可以通过有记录、可复现的人工策展弥补这一缺口。

**本轮边界（逐字）：**

> 本轮只裁定方向，不直接施工。追加颜色、重建资源包及视觉 QA 均须等待后续施工授权；不改变现有包，不触发付费生成。

### 证据（2026-10-20 本地量测）

- 最终包 32 色无绿色槽；图 43 的绿色像素只占 0.14%（1,427 / 1,048,576），且是正绿（如 `#36673a`），不是外套的橄榄色。
- 玩家 raw 的外套是橄榄色 `#59503b`（hue≈42°），占玩家非背景像素 **27.0%**；当前色板最近的是 `#685247`（暖棕，RGB 距离≈19），其次 `#58554e`（冷灰）。量化后 `scavenger-actor.idle1` 只剩 16 色，46.6% `#523730` / 24.9% `#321905` / 6.8% `#685247`。
- **重跑提取救不了这件外套**：把参考绿（`#36673a`）加进色板后，`#59503b` 仍吸附到 `#685247`（橄榄离参考绿≈42、离棕≈19）。要恢复外套，必须追加**橄榄/卡其色本身**（参考图里没有）。
- 追加橄榄槽的受影响面（按 raw 橄榄色像素占比，上限估计）：`scavenger-actor` 27.0%、`scrap-resource` 9.1%、`extraction-point` 1.5%、`office-debris` 1.2%，其余 ≤0.4%。
- 追加到色板末尾（32→33/34）不移动任何现有 `palette:N` 下标；色板契约只要求有序、无重复，不限定 32。
- 预览：`.scratch/asset-integration-v1/issues/04-evidence/player-raw-current-olive.png`（左 raw / 中 当前量化 / 右 追加 2 个橄榄槽）。
