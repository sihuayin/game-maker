## Question

给 frames 模式的动画加「同一动画共用一个裁框」，消掉逐帧 ink 包围盒漂移造成的抖动。

已核实（2026-10-20）：

- v7 是 frames 模式：6 个动画资源 / 61 帧，每帧独立生图、独立 `importFrames` ⇒ 每帧各自裁框。
- `ImportOptions.trimBox` 已有，但 frames 模式要共享裁框，**不是暴露字段即可**：必须先把同一动画所有帧（抠底 / 去线 / 去碎点后）缓存起来，再统一裁 ⇒ 两阶段控制流改动。

票内要定：

- 框策略：并集 vs 中位；是否按动画分别计算。
- 作用范围：只对新 2.1 批次生效；**不重裁 v7**（除非另行裁定）。
- 与 03 的「每帧紧裁、统一填满目标框」重新对齐：共享框会牺牲单帧填满，必须在票内明确接受或另定缩放策略（如 letterbox）。
- 任何付费复测另出预算报告 + 逐字点头；本票施工本身零付费。

## Answer（2026-10-21 · 人裁 C）

**裁定：C 成立；11 关闭，不施工。**

### 数据

- 并集共享框：2.1 alpha 差 **17.9% → 7.1%**（约 −60%），RGB 平均 L1 **32.99 → 19.03**；
  仍是 2.5 基线 **0.4%** 的 ~18 倍。
- 平均共享框：**8.0% / 22.78**，略差。
- 干净 bbox 宽度：2.1 **650 vs 474**（~37%）；2.5 **455 vs 454**（~0.2%）。
- ⇒ 共享框改善坐标对齐，但消不掉模型本身的姿势 / 轮廓宽度 / 明暗差异。

### 边界（逐字）

> 并集共享框显著改善了坐标对齐，但无法修复模型本身生成的姿势、轮廓宽度和明暗差异。
> 因此，问题不是简单的裁框实现缺陷。共享框能减少后处理造成的抖动，却不能保证生成模型在同一动画中保持角色形态一致。
> 这也意味着目前没有足够依据把问题交给 Q7 的共享裁框施工来解决。可以保留该技术方向，但不应把它作为接受 2.1 的前置修复承诺。

- 本票**不施工**；共享框保留为技术方向，未来若引入新的动画模型，可另行评估。
