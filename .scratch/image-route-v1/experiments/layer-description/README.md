# 实验：给每一层**自己的**描述，模型会不会就只画它自己那一层

[票 02](../../issues/02-layer-has-no-description.md) 的实测现场。四张图**不是**拿来用的素材，
是**证据** —— 缩到 480×270（背景的目标尺寸），看的是「这一层画了什么」。

## 跑什么

```sh
node .scratch/image-route-v1/experiments/layer-description/run.mjs            # 处理组
node .scratch/image-route-v1/experiments/layer-description/run.mjs --both     # 两臂一起
node .scratch/image-route-v1/experiments/layer-description/run.mjs 只画自己   # 再补一句
```

⚠️ **它要花钱**（一个臂 3 笔 Gemini 调用）⇒ **不进 CI**，与 `probe/*.mjs` 同一条规矩。
⚠️ 原图（1344×768）落在 `out/__layer-exp/`，那份不入库。

## 两臂是什么

| 臂 | 每一层的 `description` | 那意味着 |
|---|---|---|
| `control` | **摘掉** ⇒ 回落 `spec.description` | 每一层都被要求画**整张场景** |
| `treatment` | 配方自己那三句 | 每一层只被要求画**它自己那一段** |

其余（模板 · 上游 · 尺寸 · 抠图参数）**逐字相同** ⇒ 差的就是那三句话。

## 看到什么（入库的四张）

| 文件 | 哪一臂 · 哪一层 | 看到了什么 |
|---|---|---|
| `control-sky.png` | 对照 · 最远 | **整个车站**：天空 + 山脊 + 外墙（窗、壁灯）+ 站台 + 铁轨，铺满画布 |
| `treatment-sky.png` | 处理 · 最远 | **只有天空 + 山脊**，铺满画布 ✓ |
| `treatment-wall.png` | 处理 · 中景 | 正好**它自己那一条**墙带（窗、挂画、灯）✓ |
| `treatment-ground.png` | 处理 · 近端 | 正好**它自己那一条**站台 + 铁轨 ✓ |

⇒ **逐层描述是那个修法**，而且它**同时**解决了两件事：内容不再越层、最远那层照旧铺满。

⚠️ **再补一句「更近的那几层不要画」两臂都试过，结果一样** —— 那句话**不必要**
（它也没把最远层压成一条带，我第一版这么猜过，见下）。

## ⚠️ 这个脚本量错过一轮，而那正是最该记下来的一件

第一版把 `imagePrompt(spec, style, target)` 的 `target` **平着传**了
（`{name, index, total, tileX}`），而它的形状是 `{ layer: {...} }` ——
于是 `target.layer` 是 `undefined`，`imagePrompt` **一路落到单物体那份模板**上。

量到的因此完全不是这条路。而它给出的结论**看起来非常合理**：
「模型的默认解释是**从这一层往前**，不是只有这一层」。我照着它写了答案、入了库、还改了两处注释。
⚠️ **提示词原件就躺在旁边那几份 `.prompt.txt` 里** —— 读一眼开头是
「画一张游戏用的**单个物体**贴图」就会发现。我没读。

⚠️ 这四张图旁边那份 `.prompt.txt` 是**那一刻逐字发出去**的提示词 —— **先读它，再读结论**。

## 那个「不透明率」列在这条路上读不出东西

六张图**一个像素都抠不掉**：模型给的底色从来不是提示词要的那个纯色
（见[票 03](../../issues/03-key-color-drift.md)）。⇒ 这一票的结论**来自看图**，不是来自那个数。
