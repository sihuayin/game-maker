> **由 [`跑一次完整生图包走通 site`](04-image-pack-e2e-through-site.md) 的第三次真跑兑现出来的**
> —— 也正是 [`失败时报的「已经花掉的」是下界`](05-failed-run-cost-is-a-lower-bound.md) 补完之后
> **第一次真实验收**的那一刻。

## Question

那一跑的账长这样：

```
已经花掉的（3 次调用 · 3 次往返）：
  · image player-traveler · **还没回来** · 往返 1
  · image bg-dusk-halt · **还没回来** · 往返 1
  · image prop-luggage-pile · **还没回来** · 往返 1
```

「3 次调用」是对的（票 05 刚修好的那一半 ✓）。**而「3 次往返」是错的**：
报错自己写着「（**3 次内**）」—— 那一笔在**一个 unit 里**重试了 3 趟，账上却记 `往返 1`。

机制（读代码就成立）：三个生图生成器各自 `for (let i = 1; i <= attempts; i++)` 重试
（`image-gen.ts:152 / 298 / 459`），而 `call`（含 `attempts: i`）**只在成功那条路上构造**。
⇒ 失败时什么也不报。而 `pack.ts` 里那条「发出即记」只写得下 `attempts: 1`（发出时的真值 ✓）。

⚠️ **对照之下文本那一条是报的**：`generate.ts:209` 在**抛出之前**补记一笔
（`attempts: trips`，且**不记 `model`** —— 上游根本没应答，记了就是谎）。
⇒ 两条路在这一点上**不一致**，而**生图那一条才是钱多的那一条**。

⚠️ 它顶的是仓库那条明文纪律（`CONTEXT.md` 的「调用 / 往返」）：

> 重试烧掉的额度要能单独看见，**否则失败的归因是错的**。

要答的：

1. **往哪修**？
   - **(a) 给生图那条补一个失败交账**（像文本那样：抛出前报一笔 `attempts: trips`）。
     ⚠️ 代价：`pack.ts` 的账是**它自己**在 push 的（生成器没有 `onCall` 端口）⇒
     要么给生成器开一个回调，要么让 pack 接得住。
   - **(b) 让失败**把事实带走**：`ImageGenerationError` 带上 `attempts` / `ms`，
     `pack.ts` 在 catch 里把那条「还没回来」的记录**补成事实**再抛。
     ⚠️ 与「发出即记」是同一个动作的两半（一个是发出、一个是失败收尾），落点也同一处。
   - **(c) 不改，把话说清**：在账头那句「N 次往返」旁注明它是**下界**。
2. **判据是什么？**「一笔重试了 N 趟然后失败 ⇒ 账上那一笔的 `attempts` 是 N」——
   ⚠️ 可断言：一个**前 N-1 次抛、第 N 次也抛**的桩上游（真发出去 N 次）。
3. ⚠️ **它与票 05 是同一条线上的第二处**：票 05 修的是「发出去了但没回来」，
   这一票修的是「发出去了、**回来了（以失败的方式）**，而它烧了几趟没人记」。
