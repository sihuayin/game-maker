## 1. 图的边界声明

### 1.1 受支持的移动模型

时序判定用于排除垂直规避的移动模型，**只**包含 `packages/contracts/src/playability/graph.ts` 的四种边：

| 边 | 语义 | 依据 |
| --- | --- | --- |
| `walk` | 相邻列、同一高度，走过去不撞 | `graph.ts:203` |
| `walk-off` | 相邻列走出去（脚下悬空），落到该列下一个落脚点 | `graph.ts:204-208` |
| `fall` | 从自由空中格竖直下落，只作为 `walk-off` 的组成原语 | `graph.ts:183-216` |
| `hop` | 抛物线跳跃，按真抛物线采样（`n = clamp(6, 120, ⌈t·60⌉)`） | `graph.ts:225-272` |

玩家参数取 `DEFAULT_PLAYER_MOVE`（`speed 90 / jumpVelocity 330 / gravity 900`，`game-config.ts:134`）或 config 显式值；`maxJumpHeight = v²/(2g)`（`:274-275`）⇒ 默认 60.5px。

### 1.2 不支持的移动

- 精确跳跃时序、下落与重力的**时间耦合**、空中变向的连续控制；
- 贴墙 / 爬墙 / 蹬墙跳；
- 任何依赖实体状态转换的移动（开关、门、可破坏体）；
- 世界边界碰撞（`graph.ts:246` 与 `reach.ts:199` 约定世界外当真自由空间）。

### 1.3 过近似声明

`graph.ts:24-30`：模型**偏向玩家更强**——walk / walk-off / fall 都是真实会发生的移动，hop 弧线按真抛物线采样。这是「不可达 ⇒ 证明」的正当性来源。

**残差风险**：`hopSamples` 用 `Math.round` 对弧线取整（`graph.ts:241-247`），可能把一条合法 hop 误判为撞墙，从而**低估**玩家能力。低估会让图提前断开 ⇒ 存在假 `PROVEN_UNPLAYABLE` 的风险。

**因此增加一条硬性验证义务**（见 §5.4）：PU 结论必须通过「hop 采样加倍不变性」检查。

## 2. 门区（gate）的定义

沿用 P0 的永久封锁门（`MODEL.md`「证明义务」），并补上玩家几何：

- `L = max_T P(T) − anchorX · width`
- `R = min_T P(T) + (1 − anchorX) · width`
- **不带 lag pad**：这是所有可能位姿的**交集**，不是并集。
- **正宽度**：`R − L > ε`（ε 按 I00-05 Q3 的单一常量）。
- **y 区间**：hazard 盒的 `[hy, hy + height]`。

## 3. forbidden region 的构造与注入

1. 取门区矩形 `G = [L, R] × [hy, hy + height]`。
2. **按玩家盒子外扩**：`G'` 覆盖所有「玩家盒子与 `G` 严格相交」的脚点位置。
3. 通过 `buildMovementGraph(..., { forbiddenBoxes: [G'] })` 注入（`graph.ts:79,127-132`）。
4. `forbidden` 语义必须是「不可穿越、也不提供支撑」（`reach.ts:6`）——注入前必须验证所用图构建路径保持该语义。

## 4. 判侧规则

起点脚点必须整体落在 `L` 左侧、终点脚点在 `R` 右侧（或完全反向）。跨侧不成立 ⇒ 门不是必经点 ⇒ 不得据此判 PU。

## 5. 证明义务（全部满足才可 `PROVEN_UNPLAYABLE`）

1. **门区恒覆盖**：`R − L > ε`，且 `G` 在任意相位、任意合法 lag 位姿下都被 hazard 覆盖（交集，不带 pad）。
2. **几何全部 `checked`**：参与判定的全部 terrain / solid / hazard 几何 coverage 为 `checked`；hazard 帧几何通过 I00-02 的信任链（`verifyPack` + 同一份 Atlas 字节的 SHA-256 + 逐帧比对）。
3. **图割不连通**：在**含 hop 边**的图上，起点脚点无法到达终点脚点。
4. **hop 采样加倍不变性**：把 `hopSamples` 的 `n` 加倍后重算，连通性结论不变。若改变 ⇒ 该关卡的 PU 证明不成立，降级 IE。
5. **模型外规避已排除**：不存在本模型未覆盖的移动方式；无法排除 ⇒ IE。
6. **两档 lag 结论一致**（与 R1 Q2 一致）。

## 6. 降级条文

以下任一情况 ⇒ `INSUFFICIENT_EVIDENCE`：

- 任一参与判定的几何非 `checked`；
- hazard 帧几何无法通过 I00-02 的信任链；
- 门区非正宽度，或判侧不成立；
- 含 hop 边的图上起点与终点仍连通；
- hop 采样加倍后连通性结论改变；
- 存在模型外规避可能，或无法证明不存在；
- 两档 lag 结论不一致。

## 7. 禁止条文

1. **不得**接受调用方提供的 `verticalEvasionImpossible = true` 作为证明（G-04 原文；P0 原型的做法在集成中作废）。
2. **不得**把 hop 的**时间维度**引入时序判定——hop 只提供可达性上近似（R1 Q6 / I00-10）。
3. **不得**以「图割实现复杂」为由跳过或不完整执行 §5。
4. **不得**把「图割不连通」当作不证自明：它必须附带 §5.1–5.6 的全部证据。
5. **不得**在几何未 `checked` 时用图割结论输出 PU。

## 9. 与 G-01 的耦合

**G-01 不成立时，G-04 自动不成立**（§5.2 是 §5 的前置）。因此任何「先做 G-04、G-01 后补」的实施顺序都不成立；I-01 必须先于 I-02 的 PU 证明部分。

## 10. 需 I-02 验证的未决点

- `forbiddenBoxes` 在 `reach.ts` 的弧线采样路径上是否保持「不可穿越且不提供支撑」——需 I-02 用 N1/N2 验证。
- `hopSamples` 的 `Math.round` 在极端几何（1px 宽平台、贴边障碍）下的误拒率——需 I-02 的加倍不变性测试量化。
