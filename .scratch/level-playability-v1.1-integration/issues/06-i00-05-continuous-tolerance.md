## Question

连续时间求交的边界与容差必须冻结，否则同一关卡会因为网格 / 浮点差异给出不同结论。P0 原型用 `dt = periodMs / N`（`dt=20ms`）、`maxStepPx=3.2`、严格 AABB（相切不算碰撞）、折返点切段后解析求交。

### 必须裁定

1. **相切算不算碰撞**：`overlapsStrict` 与 `overlapsInclusive`（`packages/contracts/src/playability/geometry.ts`）在时序路径上分别用于什么；边界接触的语义。保持与 V1 一致还是另立规则。
2. **正宽度门的最小宽度**：P0 用 `L < R`（严格）。是否引入最小宽度阈值（例如 ≥ 1px 或 ≥ 玩家半宽）？阈值过大会制造假 IE。
3. **浮点容差**：比较用绝对容差、相对容差还是整数化坐标？在什么量级上会不稳定。
4. **网格与步长**：`xStep` / `phaseSteps` 是否进入契约（可配置）还是固定；它们与 `periodMs`、`distance`、`maxSpeed` 的关系；结论对步长的稳定性如何测试。
5. **数值稳定性测试**：如何证明「步长减半不改变结论」（在什么容差内），以及这种测试放在哪一层。

### 产出

裁定记录（本票 `## Answer`）+ 一份可执行的稳定性测试设计（不写生产测试）。可在 `scripts/` 内用 P0 模型做敏感性试算。

## Answer

用户 2026-11-09 裁定：**六个问题全部采纳推荐方案**（Q4 按 I00-06 的新证据收紧）。

### Q1 相切语义

- 时序路径**沿用 `overlapsStrict`**（贴着不算撞），与 `geometry.ts:14` 的 V1 约定及 Runtime AABB 一致。
- 契约条款写明「时序判定与 `overlapsStrict` 同义」。
- **附加义务**：必须补一条 Runtime 直接证据——Phaser Arcade 的 overlap 是否把边界算作接触。若该证据推翻 strict，改的是 **Runtime 语义基线**（I00-03 范围），不是本票的容差。

### Q2 正宽度门的最小宽度

- **不设语义阈值**（≥1px / ≥玩家半宽一律不采用）；只设数值 epsilon。
- 判据：`R - L > ε`。理由：恒被覆盖的正宽度区间对任意宽度玩家都不可穿越，玩家越宽只会更不可能；像素阈值只会制造假 IE。

### Q3 浮点容差

- **单一具名常量，按世界跨度缩放**：`ε = max(1e-9, 1e-9 * (xMax - xMin))`，只在一个模块里定义；时序路径不得各自写 epsilon。
- 门边界 `L` / `R` 的高精度交叉校验属于 I-02 的实现选择，契约只钉住「同一 ε、同一处定义」。

### Q4 网格与步长

- **(c) 契约冻结导出规则，不公开可调**：分辨率必须保证「单步位移 ≤ 像素上界」与「每周期步数 ≥ 下界」；具体值由审计在预算内自选，并写入 `stats`。
- **据 I00-06 收紧**：契约必须保证 `maxSpeed · periodMs / N ≥ xStep`，否则落 `INSUFFICIENT_EVIDENCE`。固定 `phaseSteps = 200` 在默认 90px/s 下 19/19 语料全部 `maxStepPx < xStep`，BFS 退化为只能等待——不得静默给出走不动的网格。

### Q5 稳定性判据

- **(a)(b)(c)(d) 全要，但分层**：
  - **(d) 确定性**是每次运行的硬门槛（同一输入重复运行结果相同）。
  - **(a) PU 分辨率不变**、**(b) NB 不被更细分辨率推翻为 PU**、**(c) IE 单调收窄** 是 I-02 的验收性质，用一组对抗夹具测，**不要求对所有输入证明**（全输入单调性过强，会逼实现做保守近似）。

### Q6 几何词汇唯一性

- **语义复用、实现可分**：契约写「与 `overlapsStrict` 同义」；实现必须解析求交（不得逐点调用退回采样）。
- 验收方式：边界用例断言「解析判定 == 切分后在区间上的 `overlapsStrict` 语义」。
