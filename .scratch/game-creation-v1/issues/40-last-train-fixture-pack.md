# 40. 产出 last-train 的 fixture 资源包

Type: task
Status: resolved
Blocked by: 42
Map: ../map.md

> 由[票 31](31-first-demo-game.md) 毕业。它定了「第一个 demo 是什么」，
> 但决议离「真有一个包」还隔着一整条管线。本票就是那一段。

## Question

产出 **`fixtures/packs/last-train/v1/`** —— 既是 R6 说的**仓库内置 fixture 资源包**
（产物 B 不吃生图能力的那个前提），也是第一个 demo 实际吃的那个包。
票 31 的裁决 6 把这两件事定成了**同一份东西**，理由是分开的两份必然漂移。

**这不是决策票，是把已经定死的东西造出来。** 形状全部来自票 31，本票不重开任何一条。

### 要产出的东西

1. **需求文本**（`inputs/last-train/PROMPT.md` 或 `fixtures/` 下同类位置）——
   黄昏山间小站，横版跳跃，30 秒单关，捡齐 3 件走到信号灯，一个危险物踩到退回起点。
   ⚠️ **警告一次**：这份需求是 `derive` 的输入，而模型默认会把角色的每个动作拆成一条资源
   —— 那正好打掉帧间一致性。票 28 已在 prompt 里写了规则，但**人过目这一步不能省**。
2. **跑 `derive`** —— 需求文本 + `fixtures/style-spec.halt-dusk.json` → 资源清单。
   清单是**最后一个能廉价改主意的地方**。
3. **人过目清单**，重点看：**锚点**（票 28 实测：两次跑货箱给了 `(0.5,1)` vs `(0.5,0.72)`，
   而票 26 裁定锚点**不能自动推** —— 这是两阶段里人最该盯的字段）、
   玩家的多动作**有没有被收成一个资源**、四类是否齐（含 `ui`）。
4. **跑 `pack`**（`source.kind = "drawlist"`）→ 一个通过校验的包。
5. **`verify` 全对**，并核对：`provenance.mode = generated`、
   玩家的 `paletteBinding = exact`、四类各至少一个真实产物、`ui` 资源的 `scale9Borders` 非零。
6. **固化**：把包连同清单搬进 `fixtures/packs/last-train/v1/`。
   ⚠️ 搬完要**复跑一次 `verify`**（路径一变，包内的相对引用就得重新对账）。
7. **顺带**：同一份清单 + 同一份 StyleSpec 走**生图路线**再产一个包，留在 `out/`
   （不进 `fixtures/`）—— 它是票 31 裁决 7 要的对照包，用来证明「换包不重建」。
   ⚠️ **非阻塞**：上游不可达就是不做，**不要为它引入任何回退**（R10 修正已拆掉降级链）。

### 完成条件

- `fixtures/packs/last-train/v1/` 存在，`game-maker verify` 全对。
- 同一个包**两次生成逐字节相同**（票 38 的确定性那条性质，在实际产物上再验一次）。
- 玩家 14 帧是同一个角色（或按清单帧数），**锚点逐资源显式为真**。
- ⚠️ **`dither` 用量要专门看一眼** —— 票 22 的抽查抓到过「用过头，读起来是噪点」，
  而这个世界的 StyleSpec 明写 `material: 无渐变`。这是本票唯一需要**审美判断**的地方，
  也是唯一可能要把清单退回去改一轮的地方。

### 不归本票

- **game-config**（关卡布局）—— 依赖外壳的视口与玩家尺寸，归[票 33](33-runtime-assembly.md)。
- **外壳与装配** —— 归票 32 / 33。本票产出的包**不被任何东西消费也能独立验收**。

## Answer

**结论：包产出来了 —— `fixtures/packs/last-train/v2/`，9 个资源 · 4 张图集 · 31 个文件，
`verify` 全对，交付态是创作态的决定函数（22/22 帧逐像素相同）。**
⚠️ 是 **v2** 不是票面写的 v1 —— 第一版跑出来量到玩家锚点悬空 4.6px，修了成因后重跑，
两版都留在 `out/`（永不覆盖）。三次提交前它还对不上，见 §3。

### 1. 产出

```
inputs/last-train/PROMPT.md              需求文本（人写的，derive 的输入）
fixtures/recipes/last-train.json         清单（9 个资源，source 全是 drawlist）
fixtures/packs/last-train/v2/            包本体（manifest + delivery/ + authoring/）
```

清单过目时动了**三处**（票面要求的那一步，清单是最后一个能廉价改主意的地方）：

| 改动 | 依据 |
|---|---|
| **天空的 `parallax` 0.3 → 0** | **算出来的**：天空是唯一**不平铺**的层，而 `p` 的层要满足 `c·p + 480 ≥ c + 480` 对全部 `c ∈ [0, 960]`，即 `p ≥ 1` —— 只有 `p = 0` 成立。墙与地面没事，因为它们 `tileable`。⚠️ **包自己管不了这条**（它不知道世界多宽），已记进票 33 |
| **加 `hud-pip`（第二个 ui 资源）** | `ui` 类**不允许声明动画**（票 27），一个 ui 资源只有一张图 —— 「点亮的格子」表达不了。**票 09 定的 `hud.slot: {asset, anims:{empty,filled}}` 形状建不出来**，见 §5 |
| 清单 `id` 改 `last-train`、`styleRef` 指 `../style-spec.halt-dusk.json` | 固化进 `fixtures/recipes/`，与另外四份配方同一处、同一条相对路径规则（**不复制一份 StyleSpec** —— 两份必然漂移） |

### 2. 三条验证

| 验证 | 结果 |
|---|---|
| `verify` | ✅ 31 个文件的 checksum 全部对得上（固化到 `fixtures/` 之后**复跑过**，路径一变就得重新对账） |
| **锚点 vs 墨迹**（逐帧量） | 19/22 帧 ✅；玩家站姿帧 **−0.6 ~ +0.4px**；`jump2` −2.6px（**收腿腾空，本来就该离开那条线** —— 票 26 那条判据的现场复现） |
| **交付态 = 创作态的决定函数** | **22/22 帧逐像素相同**（把包内 `authoring/` 的 drawlist 重新光栅化，与交付态图集逐像素比对） |

### 3. 施工抓到的四件

1. 🔴 **`framePlan` 有两份实现，而且已经漂移了。** 它同时存在于 `prompt.ts` 与 `pack.ts`，
   而票 42 给「分层背景」加那一支时**只改了 `pack.ts` 那份** —— 于是**提示词告诉模型「只需一帧」，
   组装侧却期待三帧**。这正是本仓库反复警告的「两边各写一份必然漂移」，这一次漂的是
   **提示词与组装之间**。已收成一份（`prompt.ts` 的，`pack.ts` 改为 import）。
2. 🔴 **`tileable` 的两个轴都必填，而提示词的示例写的是 `{"x":true}`** —— 等于
   **教模型写一个会被自己拒收的形状**（`derive` 第一次跑就是这么挂的）。
   已给两个轴各自默认 `false`（省略的轴 = 不平铺，唯一说得通的默认）。
3. 🔴 **锚点从来没进过提示词。** 于是模型自己挑了个位置画，而清单声明的锚点在另一处，
   壳子对齐的是**声明的那条线** —— 角色就悬空了 4.6px。把归一化锚点换算成「第几行第几列」
   写进 `assetTask`，并明说**腾空的帧是例外**（不然 jump 会被画成站在地上、腾空动作消失）。
   修后站姿帧从 −4.6/−5.6px 收到 **±0.6px**。
4. ⚠️ **票面的一条判据做不到，已修正**：「同一个包两次生成**逐字节相同**」在 LLM 产出 drawlist
   的路线下**不可能**（v1 与 v2 的四张图集 checksum 全不同，这就是证据）。
   票 38 验的是**组装**的确定性（生成器是注入的桩）。这里改验**更有意义的那个**：
   给定创作态，交付态是**决定的**。

### 4. 记下的两条偏差（不影响可用性，但要有人说）

- **背景三层各自把画布画满了**（提示词要求「没东西的地方留空」）。实测不透明占比：
  `sky` 全画布 100%、`wall` 在平台带以下 100%、`ground` 只在自己带内。
  结构上无害（近层盖住远层，横向平铺也不受影响），代价是每层带着看不见的像素。
- **玩家的美术一般**：棕色方块头 + 蓝格纹躯干，8 帧是同一个角色、只有腿在动（帧间一致性达标），
  但「帽子旁边那个黄色方块」读起来有点游离。⚠️ **整包重建**（票 18 已裁定不做增量），
  **不能只重抽一个资源** —— 这一条在评审时会由人拍。

### 5. 交给别的票的输入

1. → [固定 runtime 外壳](32-runtime-shell.md)：这个包把外壳要读的形状都定死了 ——
   背景 `layers` 三项（`sky@0` / `wall@0.6+T` / `ground@1+T`）、
   `hud-lost-slots` 的 `scale9Borders {x:4,y:4,w:64,h:24}`、玩家的 `anims` 三个名字、
   以及**信号灯是 `animation` 类带 `red`/`green` 两个动画**（票 26「一个状态就是一个单帧动画」
   的番茄先例在这里第一次落到真产物）。
2. → [资源包 → 运行时的装配](33-runtime-assembly.md)：**一条包自己管不了的几何约束** ——
   **不平铺的层必须 `parallax = 0`**，否则盖不住比它宽的世界（算法见 §1）。世界多宽只有 game-config 知道，
   所以这条检查只能落在装配期。
3. → [把 game-config 契约落进 packages/contracts](41-game-config-landing.md)：
   ⚠️ **票 09 的 `hud.slot: {asset, anims:{empty,filled}}` 建不出来** —— `ui` 类不允许动画。
   落地时要改成**两个 ui 资源的引用**（这个包里就是 `hud-lost-slots` + `hud-pip`）。
4. → [`palette` 是占比摘要还是绘制词汇](39-palette-role.md)：第一批**有明确玩法意图**的真实样本，
   8 色板。量下来：玩家用 6/8、背景 8/8、皮箱 4/8，而 `#1c1c28`（最暗色）在多数资源里占 34~62% ——
   **「角色比背景沉」这个现象在这个包里又出现了一次**，可以拿它再量。

### 6. 没做的：生图版对照包（票面第 7 项，标了非阻塞）

**它不只是「上游可能挂」—— 生图路线今天根本产不出这个包。**
`pack.ts` 的生图支对非 animation **只出一张图**，而三层背景有 3 项 ⇒ `results[i]` 越界成
`undefined`，一路带到 `buildAtlas` 才炸成一个**说不清是哪里错**的 TypeError。
已在那一支加了显式拒绝（说清原因并指向新票），**实现归票 43**。
