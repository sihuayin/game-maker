## Answer

**结论：装配写出来了，而且**端到端通了** —— 一个真资源包 + 一份 game-config → 装配器 → 浏览器里跑起来。**
`pnpm check` 绿 · 全套 **331/331** 绿 · 装配器 **13 条**测试 · 探针两个场景全绿。
站点 = **三份数据 + 一份共用 bundle**；校验跑到**五族**；硬失败**一个目录都不产出**。

### 1. 射程：本票只做 `site`（另一件已划出去）

票 09 §5 把 `compile-game` 也写成「产物 B 的对外操作」，而票 32 把本票收窄成**构建期装配**。
两处对不上，这一条一直没人承载。**已毕业成[票 49](49-compile-game.md)** —— 理由写在那儿：
它是**生成**操作（一次 LLM 调用 + 提示词迭代），按依赖图住在 `packages/assets`；
本票交付的是**装配**，不产一行提示词。⚠️ **这是本票唯一没做的一件事，明写在这里。**

### 2. 站点形状（票 32 §2 的字面实现）

```
out/<gameId>/
  pack/v<M>/          资源包（**拷进 out 树**；同一个版本已存在就不动）
  site/v<N>/          站点（N 是站点**自己的**计数器，绝不覆盖）
    index.html        ← 装配器写；**经典 script**（票 03：module script 撞 CORS）
    shell.js          ← 仓库的构建产物，**所有站点共用同一份字节**（R8 字面兑现）
    site.json         ← { "shell": "1", "pack": "v2" } —— **站点自己说明自己是怎么来的**
    game-config.json
```

⚠️ **起服务时 HTTP server 的根必须是 `out/<gameId>/`**（`pack/` 与 `site/` 的父目录）。
这条**写进了 `summary`**，不只在文档里 —— 根指到 `site` 里面就是 404，而 **Phaser 静默失败**。

### 3. 校验：从三族加到**五族**

| 族 | 查什么 | 谁提供 | 严重度 |
|---|---|---|---|
| 引用 / 自洽 / 可通关 | 票 09 的三族 | `contracts`（票 41 + 48） | 硬失败 / 警告 |
| **第四族 · 几何可行性** | **层盖不盖得住世界** | 本票 —— 要**同时**知道世界多宽（config）与视口多大（外壳） | **硬失败** |
| **第五族 · HUD 屏幕空间** | HUD 在不在**视口**内 | 本票（票 41 的抬头点名） | **硬失败** |

**第四族算的是精确条件**，不是背口诀：

```
镜头走到尽头时这一层还剩   drawn − parallax × (W − V)   必须 ≥ V
```

- 平铺的层 `drawn = W` ⇒ `(W−V)(1−parallax) ≥ 0` **恒成立** ✓（所以墙与地面没事）
- **不平铺的层只有在 `parallax = 0` 时才恒成立** —— 票 40 手算过的那条，**从公式里自己掉出来**，
  不是抄进代码的规则 ✓

**第五族判成硬失败**（票 41 的抬头留着让我判）：理由与其它几何检查**不同**且我认下来 ——
「越不过这块台阶」**可能是设计**（玩家该绕路），而 **HUD 摆到看不见的地方没有「另一条路」这回事**，
且它**精确可算**。尺子是**视口不是 `world.size`**：世界宽 1440、屏幕只有 480，
摆在 `x: 1000` 的 HUD 过得了世界校验却在屏幕外 —— 这条错误信息里逐字说了。

⚠️ **两族的检查跑在 `buildWorld` 的产物上**，不是另算一遍 ——
于是「校验过的」与「外壳要画的」是**同一份描述**，不可能漂移。

### 4. 票 48 留给本票判的那条：近端边 → **警告**

盒子探出世界的**左边/上边**，判**警告**不是硬失败。理由：**远端**越界意味着
「这东西压根不在世界里」，而**近端**探出只是**被裁掉一角** ——
一堵从画面外伸进来的墙、半截的装饰，都可能是**有意**的。
与票 27 立的规矩一致：**精确的硬失败、有解释余地的报警告**。

### 5. 硬失败**不产出任何目录**，而且**一次报全**

票 30 抓到过「校验不过时退出码是 0」，于是篡改过的包骗过了校验脚本。
这里反过来：`auditGameConfig` 的 error + 第四/第五族的 error **合并成一条 `invalid`**，
**一条都不落盘**（测试直接断言 `site/` 目录不存在）。
⚠️ 而且**一次报全** —— 两个坏引用就报两条，不让人改一跑一次。

### 6. 顺带做的一处结构搬家：`CommandResult` 进 `contracts`

`site` 住在 `@game-maker/demo`，而依赖图里 **demo 只能依赖 contracts**（R6）——
`CommandResult` / `EXIT` / `CommandError` 原本住在 `assets`，demo 拿不到。
若不搬，demo 只能自己再写一个「长得差不多」的回报形状 —— 正是本仓库反复吃的那个亏。

已搬到 `packages/contracts/src/command.ts`，**`assets` 原样再导出** ⇒ 两个壳与既有调用方一行都没改。
