## Question

1. **到底做哪个**？
   - (a) **Cozy Farm**（Q5 原定）：采摘番茄的核心循环，写实圆润风。
     `docs/文档.md` 的每个例子都围着它写（番茄三态、牛、谷仓、拖拉机），
     文档即规格，省一大笔定义成本。
   - (b) **横版跳跃**（实验实际在做的）：平台、危险物、拾取物、玩家动画。
     好处是**已经有真实产物**（6 份 drawlist + 一套 6 帧走路动画），
     且横版跳跃是**固定 runtime 外壳**最容易保证「能跑」的类型（物理引擎现成）。
   - (c) 换一个，理由另说。
2. **选择的影响面**（本票要一并交代，因为后面的票都挂在这上面）：
   - **R4 的四类资源**（sprite/animation/background/ui）在候选游戏里各自有没有真实用例？
     若某个候选类在游戏里用不上，那 R4 就有一类是纸面上的。
   - **R8 的「固定 runtime 外壳」**：哪个候选让外壳**最短**？
     横版跳跃的物理与碰撞是 Phaser 现成的；农场的「作物生长」是需要自己写的游戏逻辑。
     外壳越短，R8 的「能跑」越有结构性保证。
   - **`docs/文档.md` 的复用度**：选 (a) 的话文档里的例子全都still有效；
     选 (b) 的话第 31 节的尺寸例子、番茄三态等都要换。
   - **参考图的匹配度**：现有实验资产是从 `demo/test.png`（反乌托邦商店）来的。
     选 (a) Cozy Farm 的话，参考图要不要换一张？换了的话现有实验资产作废。
3. **demo 的规模**：一个能玩 30 秒的关卡？还是完整核心循环？
   Destination 的验收是「打开就能玩」，**玩多久算玩**。

## Answer

**结论：第一个 demo = 横版跳跃 × 黄昏山间列车小站，30 秒单关，名字 `last-train`。**
共十条裁决：三条回答票面的三问，七条是本轮 grilling 新定的。另有四条输入要交给别的票。

### 1. 票面的三问

**问 1「到底做哪个」—— (b) 横版跳跃，但世界换成 `halt-dusk`（黄昏山间列车小站）。**

不是 Cozy Farm，也不是反乌托邦商店（`test.png`）。三条判据，**其中一条推翻了票面自己写的前提**：

| 判据 | 结论 |
|---|---|
| **参考图匹配** | ✅ **决定性**。`halt-dusk.png` 是当前 fixture 参考图，[票 04](04-reference-image.md) 已拍板 fixture 资源包属于这个世界，而 R6 说 fixture 资源包是产物 B 的输入。选另一条世界线 ⇒ fixture 参考图与 fixture 资源包指向**两个世界** |
| **「文档即规格，省一大笔定义成本」** | ❌ **证伪**。`docs/文档.md` 里 Cozy Farm 只出现 **3 处，全部落在已出局的章节**：§16 的 GameplayTestPlan 例子、§18 的语义动作例子、§67 的 Benchmark 候选名单。番茄 / 牛 / 谷仓的规格**曾经活在 QA 与 Benchmark 两节里**，随 R2 整体出局了。今天文档能给的只剩契约章节（11–28、52–63），那些章节不含游戏内容 |
| **外壳最短（R8）** | ✅ 横版跳跃的物理与碰撞是 Phaser 现成的；农场「作物生长」是要自己写的游戏逻辑 |

**一条没被预料的契合**：`halt-dusk` 的 StyleSpec 写着 `material: 哑光纯色/无渐变/无高光`、
`shapeLanguage: 横平竖直/矩形主导/无描边色块`、`characterStyle: 像素方块人/几何简化面部` ——
而 drawlist 路线的产物形态（几何方块人）**跟这个世界的契合度比跟反乌托邦商店高得多**
（商店世界是「半写实成人比例 ~6 头身、聚类明暗阶梯」，方块人放进去本来就不像）。
换世界顺带把「drawlist 出来的东西像不像」解决了一半。

**参考图的匹配度（票面问 2 的末条）**：现有实验资产（`style-transfer-from-test-png/` 的 6 份 drawlist、
`animated-player/` 的 6 帧走路）**全部作废** —— 它们是商店世界的。这个世界从零重造。

**问 2「R4 四类在候选游戏里有没有真实用例」—— 有，四类全有。**
这一条同时把[票 27](27-asset-spec-kinds.md) 留的空白补上了（此前 `ui` 只有规格层验过）：

| 类 | 这一关里的用例 | 要走的路径 |
|---|---|---|
| `animation` | 玩家（赶末班车的旅客）的 idle / run / jump | 帧间一致性 · 锚点逐资源声明 |
| `sprite` | 拾取物 · 危险物 · 终点信号灯 | `boundsOfOps()` 尺寸校验 |
| `background` | 站台：天空 / 墙面 / 地面 三层 | `layers` + `tileable` |
| `ui` | HUD 面板 + 槽位图标（空 / 亮 两态） | **`ninePatch` + `scale9Borders` —— 从没被真实产物走过的路径** |

**问 3「规模」—— 30 秒单关。**
验收线：**捡齐 3 件 → 走到站台尽头的信号灯即胜**。一个危险物，踩到**退回起点**，
**不引入血量系统**（血量会让外壳变长，而 R8 说外壳越短「能跑」越有结构性保证）。

### 2. 本轮 grilling 新定的七条

| # | 裁决 |
|---|---|
| 1 | **fixture 资源包走纯 drawlist**（不是生图，不是导入） |
| 2 | **玩家是新角色**（一个赶末班车的旅客），**不是**参考图里那个站务员 |
| 3 | **背景三层视差**：天空（静态）· 墙面（缓移，`tileable`）· 地面（快移，`tileable`） |
| 4 | **HUD = 一个九宫格面板 + 一个两态槽位图标**；**「赢」不新增资源** |
| 5 | **这一关的「难」= 地形 + 时机，各一个** |
| 6 | **fixture 资源包**就是**这个 demo 用的包**，固化进 `fixtures/packs/last-train/v1/` |
| 7 | **顺带产一个同世界的生图版对照包**（非阻塞） |

**为什么 fixture 包走 drawlist**：fixture 包**存在的理由**是让产物 B 能在不碰生图能力的前提下被验收
（R6）。一个只能靠付费 API 重建的 fixture 包把这条理由自己吃掉了 —— 而这条 API 今天刚整段挂过
≥10 分钟。drawlist 给的是**零网络、零成本、逐字节确定**，且 `paletteBinding: exact`
（色板不变量构造恒真，不渲染就能判）——「风格一致性」这条最难的验收，它是**最硬的证据形式**。
⚠️ 已知代价：票 22 的抽查抓到 drawlist 的 dither **用过头**（「读起来是噪点」），
而这个世界明写「无渐变」—— **dither 用量是这条路上真正要调的旋钮**，不是结构性缺陷。

**为什么玩家是新角色**：Destination 把「包括参考图里**根本没出现过**的新事物」单列成验收第 2 条，
并自己注明这是「最容易失败、也最容易被忽略的维度」。玩家角色是画面上最大最显眼的一块 ——
把它设成图里已有的站务员，等于**把最难的那道题从验收里删掉**。

**为什么三层视差**：参考图本身就是**三条横带**（天空 / 候车室内景 / 站台），各带一套光照 ——
1:1 对得上。外壳的代价只是每层一个 `scrollFactor`，而**它是数据**，不破坏 R8。
`tileable` 让一张 64 像素宽的站台长条铺满整关，**资源体积与关卡长度解耦**。

**为什么「赢」不新增资源**：drawlist **没有文字 op**（六个 op 全是纯数值图元），
HUD 上「3/3」**根本画不出来**，靠 Phaser 内置字体会脱出世界风格。
所以胜负用图形表达：**终点信号灯由红转绿 + HUD 三个槽位全亮**。
约束反而逼出一个更干净的表达，这条同时验证了「AI 只产数据」这个边界是站得住的。

**为什么顺带生一个生图版包**：拿**同一个 game-config 换包跑一次**，是 R6「A 与 B 完全解耦」
唯一真正有力的证明（换的是包，游戏代码一个字没动）。它是**顺带，不阻塞** ——
上游挂掉就不做，**不影响本票任何一条裁决**。

### 3. 交给别的票的四条输入

1. → [game-config 契约](09-game-config-contract.md)：这一关要求 game-config **能表达会运动的实体**
   （那个周期性威胁）。**若那张票判定「不表达运动」，本票的裁决 5 退回纯静态地形。**
   另有一条悬着：**视差因子住在 `AssetSpec.layers` 还是 game-config**，由那张票定。
2. → [固定 runtime 外壳](32-runtime-shell.md)：外壳要能表达三层视差 + 一个周期性威胁 +
   「踩到退回起点」的失败规则；并**自带一个最小空场景的启动测试**（票 32 第 3 问那条）。
3. → [资源包 → 运行时的装配](33-runtime-assembly.md)：**要真跑装配，仓库里就得先有那个包** ——
   已连阻塞边到新票 **40**；那份 last-train 的 **fixture game-config** 也归它产
   （它依赖外壳的视口与玩家尺寸，所以只能在外壳之后写）。
4. → [`palette` 是占比摘要还是绘制词汇](39-palette-role.md)：`last-train` 会是**一个新的真实产物样本**
   （这个世界此前零产物），重音色用量的问题可以拿它再量一次。
