## Question

1. **到底做哪个**？
   - (a) **Cozy Farm**（Q5 原定）：采摘番茄的核心循环，写实圆润风。
     `docs/文档.md` 的每个例子都围着它写（番茄三态、牛、谷仓、拖拉机），
     文档即规格，省一大笔定义成本。
   - (b) **横版跳跃**（实验实际在做的）：平台、危险物、拾取物、玩家动画。
     好处是**已经有真实产物**（6 份 drawlist + 一套 6 帧走路动画），
     且横版跳跃是**固定 runtime 外壳**最容易保证「能跑」的类型（物理引擎现成）。
   - (c) 换一个，理由另说。
2. **选择的影响面**（本票要一并交代，因为后面的票都挂在这上面）：
   - **R4 的四类资源**（sprite/animation/background/ui）在候选游戏里各自有没有真实用例？
     若某个候选类在游戏里用不上，那 R4 就有一类是纸面上的。
   - **R8 的「固定 runtime 外壳」**：哪个候选让外壳**最短**？
     横版跳跃的物理与碰撞是 Phaser 现成的；农场的「作物生长」是需要自己写的游戏逻辑。
     外壳越短，R8 的「能跑」越有结构性保证。
   - **`docs/文档.md` 的复用度**：选 (a) 的话文档里的例子全都still有效；
     选 (b) 的话第 31 节的尺寸例子、番茄三态等都要换。
   - **参考图的匹配度**：现有实验资产是从 `demo/test.png`（反乌托邦商店）来的。
     选 (a) Cozy Farm 的话，参考图要不要换一张？换了的话现有实验资产作废。
3. **demo 的规模**：一个能玩 30 秒的关卡？还是完整核心循环？
   Destination 的验收是「打开就能玩」，**玩多久算玩**。
