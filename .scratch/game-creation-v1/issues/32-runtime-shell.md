## Question

1. **外壳的成分清单**：按 Q15 的精神，属于「手写固定」的有 ——
   Phaser 主 scene、游戏循环、输入处理、碰撞、资源加载、相机、
   以及「读 game-config 并按其装配世界」的那段胶水。
   **逐项列出来，并判每项是不是真的能固定**：有没有哪一项是
   「看起来能固定、实际每换一个游戏就得改」的？
   （候选嫌疑犯：相机跟随策略、输入映射、UI 布局。若某项真固定不了，
   它就得变成 game-config 里的**数据** —— 那正是 R8 的边界所在。）
2. **`docs/文档.md` 第 6 节目录结构 / 第 55 节 Phase Interfaces 里，
   哪些属于外壳、哪些属于管线**？现有 `demo/src/runtime/orchestrator.ts`
   是「编排器」，R2 之后它编排的东西没了 —— 它变成什么？
3. **「一定跑得起来」怎么被结构性保证**：
   - 外壳自己跑一个**内置的空场景**（零数据或最小 fixture 数据）能不能起来？——
     这是最有价值的性质：**数据全错也不会白屏**。
   - 数据错了怎么办：报错、跳过该实体、还是渲染占位符？三种的用户体验差很远。
   - 这条性质要不要有一个**测试**守着（外壳 + fixture 数据 = 启动成功）？
     这不属于 R2 砍掉的 QA，属于**外壳自身的单元测试**。
4. **视觉风格从哪来**：外壳是固定的，但每个 demo 的 UI 外观不同 ——
   UI 资源（R4）与 game-config 怎么让外壳长出不同的界面？
   （候选：外壳只提供布局容器，样式全部来自资源包里的 UI 资源 + game-config 的摆放。）
5. **分辨率与缩放**：固定外壳意味着固定的画布策略（像素风用 `Phaser.Scale.NEAREST`、
   整数倍缩放）。这是外壳的常量还是 game-config 的字段？

## Answer

**结论：外壳 = 一组写死的行为原语的实现 + 一层薄渲染**，它的形状被三条判据锁住 ——
**视口是常量 480×270（1 交付像素 = 1 屏幕像素）· 相机写死 · 坏数据渲染占位符**。
另有两条结构性决定：**「读 game-config → 世界」必须是纯函数**（外壳可测的全部理由），
**站点入口是三份数据 + 一份共用 bundle**（R6 的换包不重建靠它成立）。

### 1. 六条裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **视口 = 外壳常量 480×270**（`Scale.NEAREST`，屏幕 2× 整数放大） | 于是 **1 交付像素 = 1 屏幕像素**字面成立，整数坐标从创作态一路到屏幕不被任何东西重采样。视口同时管着 **UI 的屏幕空间坐标系**与缩放策略 —— 那是外壳的事，不该被一个资源包改动 |
| 2 | **相机写死**：水平居中跟随玩家 + clamp 到世界左右边界，垂直不动 | 30 秒单关不需要死区；而「手感参数进 config」那条理由（票 09 裁决 11）限定在「关卡几何与玩家能跳多高是同一件事的两半」—— **相机不是那一类**。要更好的相机时票 18 已给出路：新版本的外壳 |
| 3 | **坏数据 → 渲染占位符 + 控制台警告**，游戏继续；**零数据也必须起得来** | 构建期三族校验已挡住**引用错误**，运行时剩下的只有**校验够不到的那些**（loader 静默失败、文件丢了）。报错让一个坏像素变成整场黑屏，跳过让它变成一场没人发现的错误演示 —— **只有占位符让「坏了」自己显形**。⚠️ 这条直接对冲票 03 那条实测：Phaser 的 loader **静默返回空且不报错** |
| 4 | **「读 game-config → 世界」做成纯函数**，Phaser 只负责把它画出来 | 这是外壳**可测的全部理由**。与票 21 的「零 DOM 依赖」、票 38 的「生成器是注入的端口」同一条纪律 |
| 5 | **站点入口 = 三份数据 + 一份共用 bundle**：`index.html` / `shell.js` / `site.json` / `game-config.json` | 见 §2。**(b) 内联 game-config 会让 R6 的「换包不重建」当场失效**；**(c) 构建期注入包版本**则让 bundle 变成每个站点一份，与 R8 冲突 |
| 6 | **外壳要一个显式版本号**，写进 `site.json` | 票 18 说「外壳版本被站点版本号隐式承载」—— 但**站点产物不在 git 里**（Q9），拷走之后就**必须自己说明自己是怎么来的**。与资源包把 StyleSpec 的 checksum 写进 manifest 同一条道理 |

### 2. 站点的形态

```
out/<gameId>/
  pack/v<M>/              资源包（票 24 的形状）
  site/v<N>/              站点（票 18：N 是站点**自己的**计数器）
    index.html
    shell.js              外壳 bundle —— **所有站点共用同一份，逐字节相同**
    site.json             { "shell": "1", "pack": "v2" }
    game-config.json      关卡数据
```

`shell.js` 是**仓库的一个构建产物**（像 `cli` 的 `dist/cli.mjs`），站点装配只是**拷一份 + 加数据**。
R8 的「外壳永不改变」在这里是**字面意义**的：同一份字节。

⚠️ **包基址必须参数化**（票 03 实测的 `loaderBaseURL` 钩子，源码原话
「Useful if allowing the asset base url to be configured outside of the game code」）——
写死路径的下场是 404，而 Phaser 的 loader **静默失败**。

⚠️ **一条构建风险先记下**：票 03 的探针验的是 **Vite 8 + Phaser 3.90**，而仓库里的 Vite 是
**7.3.6**（vitest 带进来的）。两者能不能共存、要不要为 demo 单独升到 8，是**实现那张票施工时要撞的第一件事**。

### 3. 空场景最小数据集（票面的产出要求）

按「**故意什么都缺**」起草 —— 要考的性质是「数据全错也不会白屏」：

```json
{ "format": "game-config/v1",
  "world":  { "size": { "w": 480, "h": 270 } },
  "scene":  { "background": { "asset": "__不存在__" } },
  "player": { "asset": "__不存在__", "anims": { "idle": "idle", "run": "run", "jump": "jump" },
              "at": { "x": 40, "y": 270 } },
  "terrain": [], "entities": [],
  "hud":    { "panel": { "asset": "__不存在__", "at": { "x": 8, "y": 262 }, "size": { "w": 72, "h": 32 } },
              "pip":   { "asset": "__不存在__", "at": { "x": 12, "y": 250 }, "step": { "x": 20, "y": 0 } } },
  "objective": { "kind": "collect-then-reach", "gate": "__不存在__" } }
```

⚠️ **它过不了构建期校验**（`objective.gate` 指向不存在的终点、三处资源引用解不到）—— **这是故意的**：
它考的是校验够不到的那些失败，所以它是**直接注入外壳**的测试夹具，**不走 `site` 命令**。
判据四条：**出画布 · 不抛 · 占位符可见 · 控制台有警告**。

**两层守护**（票面第 3 条的第三小问）：
- **守门的**：纯函数装配的 vitest 单测（每次 `pnpm test` 都跑，零浏览器）；
- **可复跑的探针**：起 `python3 -m http.server` + Chrome 的真冒烟，照 `experiments/vite-build-hosting-probe/probe.mjs` 那个样子（回答「真的能起来吗」，而不是每次 CI 都跑）。

### 4. 外壳成分清单（逐项判「真能固定 / 必须变成数据」）

| 成分 | 判 | 落在哪 | 判据 |
|---|---|---|---|
| Phaser 实例与 canvas | **固定** | 外壳 | 视口 480×270、`Scale.NEAREST`、2× 整数缩放，全是常量（裁决 1） |
| 主 scene 与游戏循环 | **固定** | 外壳 | 一个 scene，`update` 只做「推进物理 + 同步相机 + 刷 HUD」 |
| 资源加载（图集 + 逐帧锚点） | **固定** | 外壳 | 交付态是 TexturePacker JSON Hash，Phaser 原生读；锚点逐帧生效（票 25） |
| **读 game-config → 世界** | **固定，但必须是纯函数** | 外壳 | 裁决 4 |
| 输入映射 | **固定** | 外壳 | ←→/AD 跑，空格/↑/W 跳。R8 点名手写固定 |
| 物理与碰撞 | **固定** | 外壳 | Phaser 现成的；`terrain` 与 `solid` 只是喂给它的矩形 |
| 相机跟随 | **固定** | 外壳 | 裁决 2 |
| 失败规则（碰到危险物 → 退回起点、计数保留） | **固定** | 外壳 | 票 31 裁决 12；无血量 |
| 胜利规则（封闭枚举） | **固定**（形态） | 外壳 | 票 09 裁决 8；**参数**（终点是谁、要几件）在 config |
| 坏数据的表现 | **固定** | 外壳 | 裁决 3 |
| **视口尺寸 · 缩放倍率** | 常量 | 外壳 | 裁决 1 |
| **背景三层视差** | **数据** | 包 | `layers` 的 `parallax` / `tileable` —— 票 09 判给包，票 40 的真产物里有 |
| **UI 的摆放与尺寸** | **数据** | config | 票 09 的**唯一例外**（九宫格天生要被拉伸） |
| **手感**（速度 / 跳跃力 / 重力） | **数据**（有默认） | config | 票 09 裁决 11 |
| **危险物的运动** | **数据** | config | `motion` 块（V1 只有 `cycle`） |
| **关卡布局** | **数据** | config | R4：map 归 game-config |

**一条贯穿的判据**：凡是「换个游戏就得改」的都成了数据；凡是「换个游戏也不改」的都是代码。
