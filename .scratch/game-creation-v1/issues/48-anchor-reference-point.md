## Question

`Entity.at` 与 `player.at` 是「**资源锚点的落点**」还是「**盒子的左上角**」？
契约里**没有写明**，而[票 41](41-game-config-landing.md) 落地的 `auditGameConfig`
**在同一个函数里用了两种读法**：

| 用处 | 现在怎么读 | 代码 |
|---|---|---|
| 越界检查 | **左上角** | `inWorld(where, e.at, s.w, s.h)` → `at.x + w > W` |
| 台阶高度 | **底边** | `step = groundY - e.at.y` |
| 出生点卡在 solid 里 | **左上角**（注释自称是近似） | `inside()` |

### 方向其实已经定了 —— 由**包**定的

`fixtures/packs/last-train/v2/` 里每个资源每帧的 `anchor`：

| 资源 | anchor | 读法 |
|---|---|---|
| `player-traveler` | `{x:.5, y:.95}` | **脚** |
| 世界里的道具（行李堆 / 雨棚台阶 / 皮箱 / 车厢 / 信号灯） | `{x:.5, y:1}` | **底边中心** |
| `hud-lost-slots` | `{x:0, y:1}` | **左下角** |
| `hud-pip` | `{x:0, y:0}` | 左上角 |

⇒ **`at` 是「锚点落在哪」**，盒子由「锚点 + 尺寸」推出来。

旁证：票 09 那句「锚点落在这一点上（角色的**脚**在这里）」在锚点语义下
**不是特例，而是通则的一个例子** —— 玩家因此不需要任何特殊处理。
[票 44](44-implement-runtime-shell.md) 的外壳已经**整体**建在这个方向上（纯层的 `boxAt()` 是唯一算盒子的地方）。

### 现在的读法会**拒掉合法的 config**

一个底边锚点、站在地面线上的东西（世界里的绝大多数），正确写法是 `at.y = 地面 y`；
而越界检查算的是 `at.y + h` —— **凭空多出一个 `h`**。
于是「世界高 270、地面线 250、东西高 40」这种再正常不过的摆法会被报「落在世界之外」。

### 要做的

1. **`auditGameConfig` 的盒子统一由「锚点 + 尺寸」推出来。**
   它已经在读 manifest（`sizeOf`），再用一次 `anchor` **不是新依赖**。
   `inWorld` / `inside` / 台阶高度**全部用同一个盒子**（台阶用盒子的**底边**）。
2. **撤掉票 41 那次「修夹具」。** `packages/contracts/tests/game-config.test.ts` 里
   HUD 面板的 `at.y` 当时被按左上角近似从 `262` 改成了 `230` ——
   锚点语义下 `{x:0,y:1}` + `262` = 底边离地 8px，**262 本来就是对的**。改回去。
   同一份夹具里 `luggage` 的 `at.y = 210`（盒底 210、地面 250）也要重新过一遍。
3. **补反例**：
   - 底边锚点的东西摆在地面线上**不许**被报越界（现在会被报）。
   - 真越界（盒底超过世界底）**必须**被报。
   - ⚠️ 加一条**直接断言锚点语义**的测试。这一条之所以能悄悄错这么久，
     就是因为**没有一条测试问过「盒子是从哪儿算的」**。
4. ⚠️ **schema 一个字都不动**（`.strict()` 照旧）—— 变的只是校验器怎么算盒子，形状没变。
