## Question

**把「一段需求」变成「一份 game-config」。** 与 `derive → pack` 完全同构（票 09 裁决 2）：
**一次 LLM 调用编译 → 先落盘成文件 → 人过目 → 再装配。**

⚠️ 产物 B 的输入在 Destination 里写的是「**一个资源包 + 一段需求**」。
今天「需求 → game-config」这一步**只能靠人手写** —— 那条路是正当的（R7 两条路都开），
但**推导这条路根本不存在**。

### 要产出的东西

1. **`compileGame()` 落在 `packages/assets`** —— ⚠️ **不是 `demo`**。
   它是**生成**操作，与 `deriveRecipe` 同类；而依赖图里 **demo 只能依赖 contracts**，
   生成器（LLM 客户端）住在 `assets`。demo 只消费结果。
2. **输入要带资源清单** —— 模型必须看到**真实的资源 id 与动画名**，
   否则它写出来的每一个引用都解不到。清单是 `derive` 的产物，正好接上。
3. **输出落盘** `out/<id>/game-configs/v<N>.json`，**绝不覆盖**（与清单、资源包同一条规矩）。
4. ⚠️ **落盘前先跑校验**：三族（契约）+ 几何（票 33 的 `auditGeometry`）。
   不过就报出来 —— **别把一份坏 config 落盘让人以为它是好的**。
   hmm，但「先落盘再人过目」是票 09 的裁决……这里要判一次：
   **落盘但校验不过时明确标出**（人过目的前提是他知道哪儿不对），还是**不落盘**。
5. **对外面**：CLI `compile-game` + MCP `compile_game`（与既有五个同款）。

### ⚠️ 提示词是这票的真活

票 40 抓到过三条「**提示词教模型写一个会被自己拒收的形状**」。
这一票有**同样的风险**，而且是新的：

- `at` 是**锚点落点**，不是左上角（[票 48](48-anchor-reference-point.md) 刚定死）。
  教错了 ⇒ 全世界的道具浮空。**「站在地面线上」= `at.y = 地面 y`。**
- `hud.*` 活在**屏幕空间**（视口 480×270），不是世界空间（世界宽 1440）。
  教错了 ⇒ 第五族校验拒收，或者更坏 —— HUD 跑到屏幕外。
- `world.size` 的高度**必须等于视口高**（裁决 13「关卡单屏高」）。

**提示词里的示例必须逐字是能过校验的形状** —— 而且最好**拿真跑一遍来证明**，
不是靠读。`fixtures/game-configs/last-train.json` 就是一份现成的正例（票 33 产）。
