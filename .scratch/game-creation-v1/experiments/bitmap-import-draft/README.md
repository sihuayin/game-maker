# bitmap-import-draft —— 票 23 的原型：一张真实位图怎么落到目标像素网格

素材：`fixtures/import/wan-player-1024.png`（1024×1024 像素风角色，模型按参考图风格条件生成）。

```bash
node compare.mjs       # → out/compare.png（8× 并排）与 out/strategy-{A,B,C}-{quantized,unbound}.png
```

依赖 `packages/assets/dist`（先 `pnpm build`）。

## 它推翻的隐含假设：模型给的图**没有像素网格**

| 测量 | 结果 | 含义 |
|---|---|---|
| 边缘位置对 k 取模的集中度 | k=2: 0.500（均匀是 0.500）· k=16: 0.064（均匀是 0.063） | **没有任何周期**，网格不存在 |
| 相邻像素平均色差 | 15.07 | 纯像素画的整数边界应接近 0 |
| 前景颜色数 | **61152** | 抗锯齿/重采样过的连续图 |
| 背景四角色 | 4 种不同颜色 | **不是平色**，抠背景只能按容差 |

所以「像素风」是**风格**不是**事实**。这条通道做的不是「重采样回原网格」，是**重建**一个网格 ——
像素化，不是缩放。目标网格 25×48 对应 **16.9 倍**降采样。

## 三种降采样策略

| | 上排：量化到世界色板 | 下排：保留自带颜色（unbound） |
|---|---|---|
| **A 最近邻抽样** | 保住眼睛与帽子纹理，边缘偏噪 | 最接近原图，**651 色** |
| **B 面积平均**（裁决采用） | 眼睛在但偏软 | **771 色** |
| **C 色板投票** | 网格最干净，**但眼睛被投没了** —— 小于一格的细节直接消失 | 9 色（构造上就是色板色） |

**裁决：B 面积平均 → alpha 阈值 → 量化。** 理由：标准且稳健，是三种里唯一不靠运气的
（最近邻的好坏取决于恰好采到哪个源像素，换个目标尺寸结果就变）。
C 构造上保证 ∈ 色板、网格最干净，代价明确：它会丢掉小于一格的细节。

下排那两列的数字是「必须量化」的直接论据：**1200 个格子、651~771 种颜色**，几乎每格一色 ——
那不是像素画，是照片。

## 踩过的坑

第一版联系表把半透明像素的 alpha 原样写进 PNG，看图器把它合成到**白底**上 ——
于是面积平均那一列看起来像套了一圈白边，我差点当成策略的问题。
修法是按 alpha-over 合成到联系表底色。**半透明像素的渲染结果取决于谁合成它**，
像素风资源因此要 alpha 二值化。
