# A 方案：母版 → 逐个动画（Gemini）

```bash
node run.mjs       # 出母版 + 3 张单行 sheet，并量等分切片的效果
node segment.mjs   # 改用**间隙切片**再量一遍
```

上游：Gemini `gemini-2.5-flash-image`（配置在 `game-maker.local.json`）。5 次调用、约 76 秒。

## 它回答了票 23 的问题 1（帧一致性 / 网格 sheet 能否切）—— 答案是：

**能，但前提是别按等分切。**

| | 等分切片 | **间隙切片** |
|---|---|---|
| `run`（问 6 帧，实际 5 块） | 头宽极差 **144** | 身高级差 **1** · 头宽极差 **4** |
| `idle`（问 4 帧，实际 5 块） | 头宽极差 **90** | 身高级差 **0** · 头宽极差 **2** |
| `jump`（问 4 帧，实际 4 块） | 头宽极差 **158** | 身高级差 88 · 头宽极差 158 |

（判据是 `import.test.ts` 用的同一条：**同一个特征在各帧里被画成多宽**。逐帧各画各的 ⇒ 抖。）

**模型不按等分格排版，但它会在角色之间留干净的缝。** 所以等分切会把相邻角色切进同一格
（`run` 那张 1344 宽切 6 格 = 224/格，实际 5 个角色摊在 1344 里），而按列的零墨区间切
就能切得几乎完美。

## 它同时证实的：角色一致性**不是**瓶颈

`run-sheet.png` 里 5 个角色是同一个人的不同动作 —— 绿毛线帽、络腮胡、夹克、胸口那块
发光的 CRT 屏逐帧一致。这是「母版当**内联参考图**」换来的，而这一手只有 Gemini 能做
（DashScope 的 `image_edit` 硬要公网 URL，本机文件传不进去）。

顺带一提：母版那条路上的角色明暗层次也比 Wan 那张参考图好 —— 后者实测 73% 的像素是
同一个颜色（糊成剪影），这里帽子/胡子/夹克/裤子/靴子分得开。

## 还没解决的三条

1. **帧数不可信**：要 6 帧给了 5 帧，要 4 帧给了 5 帧（还夹着一个 1 像素的噪声块）。
   这个**必须报出来**，不能静默接受 —— 否则 manifest 里的帧名与动画分组会对不上。
2. **`jump` 有一帧是离群的**（头宽 293 vs 137）。要么那一步动作本身让轮廓变了，
   要么两块被并成了一块。没有进一步诊断。
3. **背景抠图的容差是个静默杀手**：这批用的 40 是对的；同一批图用 200 会把物体啃掉大半
   （实测商品箱从剩 44% 掉到剩 13%），而**包照样 verify 全过、checksum 全对** ——
   现有指标一个都不会因此变红。

- `out/report.json` / `out/segment-report.json` —— 两次测量的原始数字
