## Question

把 PRD §8.1 的「确定性 QA」清单，用领域词汇表「判据 vs 观察」逐条分档，并钉死验收标准。

候选检查项（PRD §8.1 表）：SVG 可解析 · 画布尺寸一致 · 对象 ID 不重复 · 对象引用有效 · 对象边界与规格一致 ·
资源安全（不含禁止内容）· 预览成功生成 · 文件完整。逐条判：
- 哪些是**判据**（构建期硬失败，「错了一定不是设计」）？例如 SVG 语法错、ID 重复、边界与 VDS 不符、含禁止元素。
- 哪些是**观察**（只报、不阻断）？例如某个 palette 色没被用。
- 每条判据的**验收标准**（能机械写出来的失败信息，PRD §7.2 的失败诊断要定位到阶段+对象）。
- 这条验证器归哪：是 VDC 编译器的一部分（PRD 的 `validator` 模块），还是复用现有 QA 族？与现有
  `audit*`（`game-config.ts` 那批）是什么关系 —— 并行还是复用？

HITL：grilling + domain-modeling，把「验证」从 PRD 的模糊清单钉成可实现的判据表。

## Answer

确定性验证 = §8.1 **八条全判据**，无观察（观察留在 §8.1 之外：`palette` 色没人用/同层重叠/主观 §8.3）。人裁 2026-10-24 锁三件事：**判据等级、模块归属、验证顺序**。

**判据表**（每条 = 阶段 + 失败信息要点，PRD §7.2 定位到阶段+对象）：

| §8.1 检查 | 档 | 阶段 | 失败信息要点 |
|---|---|---|---|
| SVG 语法 | 判据 | SVG 验证 | `scene.svg` 第 N 处 XML 解析失败 + 具体语法错 |
| 画布尺寸 | 判据 | SVG 验证 | `width/height/viewBox` = X ≠ VDS `viewport` 480×270 |
| 对象 ID 重复 | 判据 | SVG 验证 | `<g id="X">` 重复 |
| 对象引用有效 | 判据 | SVG 验证 | SVG `<g id="X">` 无 VDS 对家 / VDS object X 无 SVG 对家 |
| 对象边界一致 | 判据 | SVG 验证 | `<rect>` x/y/w/h 与 object X 的 `bounds` 不符（哪个坐标差多少） |
| 资源安全 | 判据 | SVG 验证（**前置**） | 元素/属性不在白名单（票 05 的 3 元素+10 属性） |
| 预览生成 | 判据 | 渲染 PNG | scene.svg → PNG 失败 / 输出尺寸 ≠ viewport |
| 文件完整 | 判据 | 输出 | 缺 `run/vN/visual-design/{design-spec,svg/scene.svg,preview/scene.png,qa/report}` |

**模块归属**（Q2）：VDS↔SVG 是**编译器内部一致性**，VDS↔design/config 是**跨契约验证** —— 两类不能因都叫 QA 就塞同一模块。

- VDS↔SVG 内部一致性（语法/白名单/画布/ID/引用/边界）= **VDC 自有 validator**（自产自验，与 `audit*` 并行不复用）。
- PNG 生成 + 尺寸 = VDC 渲染/验证阶段。
- `sourceIntent`↔design 覆盖 = 中性跨契约函数（遵循 `audit*` 模式），位置按现有 contracts 架构确认。
- `role`↔`kind` 交叉 = 中性跨契约函数，位置 + QA 归属 → **票 07**。
- 报告编排 = VDC QA 流程。
- ⚠️ **「遵循 `audit*` 模式」≠「现在就放 contracts」**：本轮锁**职责**；最终代码接缝（依赖方向/包边界/调用方式）由对应 ticket 确认。

**验证顺序**（Q3，白名单前置门）：**语法 → 安全白名单 → 一致性四项 → PNG → 文件清单**。

- 一致性是**四项**（画布尺寸/ID 重复/引用有效/边界一致）—— 语法、安全不算一致性。（修正 Q3 口误「五条」）
- 两条实现约束：① 安全失败后**不继续**处理不可信 SVG（连 ID/边界一致性都不跑，不只是跳过 PNG）；② XML 解析**禁用外部实体 + 外部资源加载**（安全检查本身不许引入风险）。
- 「白名单保证渲染必成」= **实现假设**，不是免除失败处理；渲染器运行时异常仍须产生明确失败报告。

**文件完整**：`commitRun` 原子提交（票 02）是主要保证，validator 兜底核对清单。
