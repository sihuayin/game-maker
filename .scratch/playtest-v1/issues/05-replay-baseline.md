# 05. 可重放测试 + 回归基线

Type: grilling
Status: open
Map: ../map.md
Blocked by: 02

## Question

裁定「可重放测试与回归基线」（范围内第 4 条）。至少定：

1. **「可重放」的层级**：重放什么 ——（a）**输入级**（记录按键/时序，原样重放）vs（b）**动作级**（记录语义动作序列，
   重放时按当前状态重新决策）vs（c）**证据级**（重跑同一场景，比较产出证据是否一致）。哪种是「可复现试玩报告」想要的？
2. **确定性**：同一场景两次跑，什么**必须**一致（判定一致？轨迹一致？事件序列一致？），什么**允许**抖动（物理帧时序、
   截图字节）？重放如何保证可复现（固定种子 / 固定输入脚本 / 固定时序）？
3. **回归基线**：基线是什么（某版本场景的**黄金产物**——判定 + 事件序列 + 证据指纹）？存哪（`out/` / 本 effort 目录 /
   入库 `fixtures/`？）、怎么绑版本（场景 + pack/site 版本）、回归怎么比（精确 diff / 容忍阈）？基线从哪来
   （真实产物第一次跑存为基线，还是手写）？
4. **回归失败语义**：比基线差了算什么 —— 判据（阻断）还是观察（只报）？会不会引入新质量门禁（对照
   [[观察 / 判据]]边界，别擅自加判据）？

> **与票 02 的接口（2026-10-27 补）**：票 02 已定——`baselineEligible` 是场景**独立声明**的维度，**不由确定性保证**。
> 本票尊重场景声明的资格、按独立论证裁定，不自行假设「确定性 ⇒ 可基线」。

> **与票 04 的接口（2026-10-27 补）**：票 04 已定——「同一证据输入 + 同一版本绑定下归因确定一致」是回归比较的前提；
> 基线身份应复用同一组绑定（场景格式版本 + 实际 site/pack/config/shell 身份 + harness 版本），
> 不要求真实游戏每次原始轨迹逐字相同。

HITL：用户逐字裁定。
