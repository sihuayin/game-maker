### U9 四项的关键决策

**判据 ①（s 合法性）**
- `isValidWaitingCell` = 整数脚点 ∧ `corridor.footY === spawn.footY` ∧ 在静态走廊 `[xLo,xHi]` 内 ∧ `graph.standableAt(footX, corridor.footY)`。走廊本身是「spawn 脚点 y 的 `standable` 连通段按合法范围裁剪」，因此同时覆盖「同一脚点 y 水平连通段」与「standable」。
- 候选 `s` 只从该过滤器取；不在走廊 / 不可 standable 的 x 永不进入证书。

**判据 ②（接近段，`∀φ0`）**
- 先对**全部** `N` 个半开相位格跑 `verifyResidualWait`（U2-02 整格保守、跨折返点切段）；任一格失败 ⇒ `failed` / `no-witness-found`（`failure: "residual-wait"`），不再消耗预算求 W。
- 对齐后的 spawn 状态是 `(spawn.footX, (k+1) mod N)`，对 `k` 遍历恰好是 spawn 列的整列。`W_{→s}` = `solveWinningCore({ targetFootXs: [s], stopWhenRanked: spawn 整列 })`。
- 接近段 `covered = residualWait.verified ∧ rank(aligned) ≥ 0`；`N` 格全部 covered 才进入判据 ③。
- 策略输出只含从 N 个对齐状态出发、沿 rank 递减后继可达的闭包（按状态索引升序），不输出与证明无关的 discovered 状态；每条转移 `verified: true`，rank 严格 −1。
- `T_arr` 由策略给出：`alignedStart(k) + rank·dt`，其中 `alignedStart(k) = witnessPhaseCellBounds(grid,k).t1`（`k=N−1` 时恰为 `P`，不用 `N·dt` 避免浮点漂移）。

**判据 ③（停留段，全周期）**
- 区间 `[T_arr, T_arr+P]`；只在 `m·P/2` 切段（`monotoneBoundaries`），每段 `pieceSlope` 单调；**不按 `dt` 采样**。
- 每段用该段方向的 `lagPad = |slope|·lagMs`（`hazardSpeed = 2·distance/P`，速度恒定 ⇒ 全程同一数值）；上升段向右加宽、下降段向左加宽、静止段 pad = 0。pad 的锚点换算式与 U2-02 S2 逐字一致。
- `intersectContinuous` + `overlapsStrict`，`intervalTolerance = 0`；只把 `end > start` 的正宽度开区间记为碰撞。任一子段正宽度碰撞 ⇒ `verified: false`（相切 / 零测度安全，**不设最小安全窗口**）。
- `T_arr` 取各相位抵达时刻的**最大值**作代表：`[T,T+P]` 恰好覆盖一次完整 Hazard 周期，检查结果与抵达相位无关；这样所有相位的等待区间都被同一份全周期证据覆盖。
- 每个子段记录 `t0/t1/direction/slope/lagPad/cutPoints/analyticSegments/collisionIntervals/collided`；顶层记录 `hazardSpeed/lagPad/turnarounds/verified/failure`。
- `s` 是 standable 脚点 ⇒ 玩家盒不压 solid（与 U2-02 残差等待同一论证），不重复 S1。

**判据 ④（出口段，`∃ψ`）**
- 候选收窄已保证 `∃j`：只保留「至少一个相位 `(s,j)` 在 `W_{→goal}`」的 x。出口选择在 `j ∈ [0,N)` 中取 **rank 最小、同 rank 取相位最小**（确定性，且出口路径最短）。
- 出口策略是 `(s,j)` 沿 rank 严格递减后继到 rank 0 Goal 状态的转移链（`buildU9Exit` 重新校验 `transition.from === 当前状态`、后继 rank = 当前 − 1、终点 rank 0 且无后继；任一不满足返回 `null`，候选被跳过，不输出未验证链）。
- **`∃ψ` 的不对称保留**：实现从不要求所有相位在 `W_{→goal}`。附注：对一个 U9 安全的 `s`，单格 `wait` 转移本身被全周期证据覆盖，因此「任一相位能出去 ⇒ 通常所有相位都能等到那个相位再出去」；这不是实现把 `∃` 改成 `∀`，而是等待格解耦抵达 / 通过相位的结构后果。代码与输出仍按 `∃` 取证。

### 候选与效率

- 先生成一次全相位 `W_{→goal}`（目标集 = `arrival.goalStates`），把候选收窄到「至少一个相位 winning」的 x；再按 **x 升序**对候选求 `W_{→s}`，第一个四项全过的 `s` 即返回。顺序完全确定，不做依赖遍历次序的优化。
- `W_{→s}` 用 `stopWhenRanked` 提前停在 spawn 整列全 ranked；已发现 rank 仍精确，未发现状态不参与 → 不改变最小不动点语义。
- 若某候选的停留段失败，继续下一个候选；失败候选的 `approach.policy` 被丢弃，**失败 / 耗尽侧不携带任何部分证书**。
- 已知性能边界：Hazard 完全切断走廊、左右不连通时，候选会落在不可达一侧，逐个候选的 `W_{→s}` 可能耗尽共享 `maxStates` ⇒ `insufficient`（合法 IE）。本票按票面要求不引入额外前向可达性预过滤；预算硬化 / 性能归 U5。

### 前置条件与原因码

- `preconditions.temporalCoverage !== "checked"` ⇒ `insufficient` + `geometry-untrusted`（`failure: "temporal-coverage"`）。
- `preconditions.playerGeometryTrusted !== true` ⇒ `insufficient` + `geometry-untrusted`（`failure: "player-geometry"`）。
- 选择 `geometry-untrusted` 而非 `model-out`：两者都是 D9 既有闭集；这里失败的是**输入可信性前置**（coverage 未 checked / 玩家几何不可信），不是运动模型越界。D10 §1.1 明确把两者放在同一段「U9 降级 IE」，因此共用一个原因码、用内部 `failure` 区分。**未新增 D9 原因码**。
- 输入前置优先于预算：即使预算已耗尽，仍返回 `geometry-untrusted`。
- 搜索完成但无 `s` 四项全过 ⇒ `failed` + `no-witness-found`（`failure: "no-waiting-cell"`）；预算耗尽 ⇒ `insufficient` + 实际预算原因码（state / edge / cut / wall-clock）。两者都只导出 IE，代码不产生 PU。

### 预算

- 调用方传入同一个 `WitnessWorkBudget`；`W_{→goal}`、每个候选的 `W_{→s}`、残差等待、停留段检查全部从它记账，**不新建 / 不重置 / 不重发**。
- `maxStates`：Goal / 前驱 enqueue 与 visit 都计；`maxEdges`：每条候选边经 `verifyTransition` 计；`maxCutsPerCheck`：每次 `intersectContinuous`；`maxCutsPerBranch`：`recordCheck` 按 `segments = cutPoints + 1` 投影；墙钟只 abort。
- 任一 `BudgetStop` 或收尾 `finish()` 新触发的 abort ⇒ 立即 `insufficient`，不保留部分 U9。
