# 真实交付与来源证据的准入判据

## Question

什么事实和证据足以证明 config、pack、manifest、Atlas 属于同一次可追溯的真实交付？如何区分真实交付、历史产物、合成测试及自动配对；证据缺失时如何标记而不推断？

## Resolution

用户于 2026-11-19 确认以下判据：

1. **真实交付**须有可追溯的实际游戏需求或真实使用目的及对应交付记录；明确标为合成、测试矩阵或专为证明算法而构造的场景不算。外部用户接收不作为硬性条件。
2. **交付关系**须由 site 的交付记录、配置或 manifest 引用将具体 config 与具体 pack 版本关联，并通过文件摘要核对。目录邻近、资源 ID 匹配或自动配对只能作线索，不能单独证明交付关系；未证明时标记“关系未证实”，不进入正式验证。
3. **证据不足**时保留候选，标记“来源证据不足”，指出缺少的具体关联；不将其作为合格真实交付，也不据此断言它是合成案例。

以上判断不替代对使用授权的核验，也不证明 Atlas 可信、模型适用或 witness 完整。实际追溯与验证不在本地图范围。
