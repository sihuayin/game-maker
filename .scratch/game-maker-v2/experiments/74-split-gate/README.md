# 票 74 探针：把「`mechanics` 非空」从 gate ④ **拆出去**之后，会发生什么

**为什么要有它**：票 74 的 Q1 是「归 schema（现状）还是归 R12（拆）」。
票 67 的第一轮量的是**今天**（② 判决 / ⑨ 价签 / ⑩ 退码），本探针量的是**拆之后那一支**。

⚠️ **它不必真的改契约就能量出来**，理由是：

> `buildDesign` 的三族拒绝里，会因 `mechanics` 变空而变的**只有** `intentCoverage` 一族，
> 而它**只按 `id` 比**（`intent-coverage.ts`：`hasId(design.mechanics, m.id)`）。
> ⇒ 拿一个**保证不与任何意图机制 id 相同**的哨兵 id 填进 `mechanics`，
>   「非空且一条都对不上」与「空」在它眼里是**同一个集合差**。
> ⇒ 于是「拆 gate 之后 `mechanics: []` 会拿到什么」可以在**今天的真代码**上跑出来。

§2 每一格都带**恒等校验**（空 vs 哨兵两种构造的缺项列表必须逐字相同），校验不过就打印作废警告。

**免费**：只 `require` 已构建的 `dist` + 盘上真的 run 产物 + 读源码文本。
`fetch` 由探针自己顶（§4 走的是真 `compileDesign`，但不发一个网络请求）。源码一个字节没动。

## 三条最要紧的读数

1. **拆 gate 的收益全在「机器那一侧」**：3 发 → 1 发 · 账从 `["schema"×3]` 变成 `null` ·
   报文从笼统一句变成**逐条点名带用户原话**。⚠️ 而它**不改模型读到的任何一个字**（§5）
   —— 所以「照散文省掉」这一档**不会因为它变多或变少**。
2. **拆 gate 是零风险的**：唯一障碍就是那一格（§1）；意图层那条 gate 保证不开洞（§3）；退码不变（§4）。
3. **真正被这一票撬动的是「散文 vs 机器」那处矛盾**（§5′）：票 54 修好了散文内部的打架，
   而剩下那句「至少一条」是 gate ④ 的镜像。**两条路只能选一条** —— 要么拆 gate（散文说得对），
   要么把散文那句删掉（可删掉之后模型**没有诚实的出路**，只能顶替，而顶替 R12 是瞎的，票 67 ⑤）。
