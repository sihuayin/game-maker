## 本探针证明不了什么

- **补上那句话之后模型会不会更少写空壳** —— ⑤ 量到今天 **0 处空壳**（13 份里一个都没写过），
  所以这一问本来也不该指望它；真跑一律进**票 23**，另出报告 + **逐次明确同意**。
- **`{}` 会不会真的被模型写出来** —— 免费手段证不了（这是**分布**问题，不是**契约**问题）。
- **Q1 该不该补那句话** —— 本轮只量「缺了什么 / 缺口有多大 / 补在哪有先例」，
  **不替它选**。
- ⚠️ **⑨ 那四格是「假 `fetch` 驱动真 `analyzeIntent`」** —— 走的是真代码（真循环、真 `parseToolUse`、
  真契约、真账），由探针**替上游**回话 ⇒ 它量的是**链数了几次**，不是**模型会怎么写空壳**，
  更不是**真跑里空壳会不会出现**（⑤ 说今天 n=0）。⇒ 它给的是**价签**，不是**疗效**。
- ⚠️ **⑪ 只证明「今天没有任何判据看着那句话」** —— 它**不**主张「一条一测」的制度坏了：
  ② 与 ⑤c 也没有各自的 `it`（前者的意思与 ① 同在一句、后者可能只是没跟上）。
  它主张的是：**④ 这一句被删掉时，没有任何现有测试会变红**（唯一管这件事的 `:63` 里没有 ④）。
- ⚠️ **⑬ 量的是「那一句候选句」的落地价签，不是「任意一句」** —— 换一个**带禁词**的写法照样会红
  （两次对照跑就是给这件事兜底）。它证的是「**加字不会撞红**」这条结构性质，
  **不证**「加哪一句都对」。
- ⚠️ **⑬ 候选句本身是探针拟的，不是提案** —— 它只是拿一个**长度合理、措辞与本文件同族**的句子
  去压那 28 条断言，好让「+87 字 / 红 0 条」这两个数有个实物；**它不主张这么写**（措辞是人裁的活）。
- ⚠️ **⑭ 只证明「第 5 条按字面够不着 `progression`/`challenge`」** —— 它**不**主张模型真的会那样误读
  （那是分布问题，免费手段证不了）；它证的是**摆在那里的字**没有把这层射程说开。
- ⚠️ **⑮ 量的是「先例的实物形状」，不是「哪个先例对」** —— ⑤b 与 ⑤c 不统一是**史实**
  （票 54 升格、票 52 没有），不是判决；本票**不替**它们中任何一个站台。
- ⚠️ **⑯ 那条「`challenge` 会因『同上』自动继承」是读句子的结论** —— 它证的是**文本结构**
  （`challenge` 行正文里没有独立句子），**不证**模型读「同上」时会怎么补全。
- ⚠️ **⑰ 量的是字符串层面的相容性** —— 它证「三个锚不相交、可以同批落地」，
  **不证**「三句话合起来读着通顺」，也**不证**「合并之后模型会照做」。
