## 量的是什么

盘上 **13 份真意图**（`find . -name game-intent.json -not -path "*/node_modules/*"`），
逐份过**今天**的 `GameIntentSpecSchema`（`packages/contracts/dist/game-intent.js`），
并把每一条 `mechanics[]` 分成**真机制 / 实体名 / 布景 / 胜利条件**。

| 节 | 问 |
|---|---|
| ① | 逐份（按时间）：今天这道 gate 怎么判它、漏掉哪几条 |
| ② | 按「先分家」散文落地时刻（票 54 · `a455bf3` · 2026-10-13 12:24）切一半，前后各长什么样 |
| ③ | 全盘合计：gate 逮住谁、漏掉谁 |
| ④ | 「`mechanics[].name` 撞世界 / 胜利条件 / 实体那几张表」这条**可计算**的判据，逮得住错格吗、误伤真机制吗 |
| ⑤ | ⚠️ 诚实检查：④ 那个 0/47 是**语料**的性质还是**规则**的性质 |

## 建在什么之上 · 与已有读数怎么对上

- `packages/contracts/dist/game-intent.js` 是**构建产物**（`mtime` 2026-10-14 13:38，晚于
  `src/game-intent.ts` 的 2026-10-13 23:01）⇒ 对着的是**今天**的契约。
- 分类（实体名 / 布景 / 胜利条件）**是人读 `mechanics[].name` 那一串中文读出来的**，
  **不是机器的判断** —— R3 的门不收「这串字是不是一条机制」（它**不可计算**，这正是本票要裁的东西）。
  机器只回答两件事：**今天拦不拦**、**第 ④ 条规则会不会响**。

## 三条最要紧的读数

1. **那些「杂物」逐字就是需求自己那张清单** —— `fixtures/e2e/wasteland-platformer/intent.md:7-15`
   那张「游戏需要有：」的七条，与第八跑那份意图的七条 `mechanics[].name` **逐条相同、顺序都一样**。
   13 份语料用的是**同一份需求**（`md5` 逐份比过）。
2. **散文前后 6/7 → 0/6** —— 而散文之后那 6 份不是少写几条，是把那张清单**读懂了**
   （`宝箱`→`open-chest`，而 `废土背景` / `最终目标` 正确地没进 `mechanics[]`）。
3. ⚠️ **「名字撞表」那把尺子：17/17 逮住、47 条真机制 0 误伤 —— 但 3/6 条自然真机制名被误报**
   （`在废土中前进` / `废土生存` / `探索废弃城市`）。⇒ 那个 0/47 量的是**这 13 份语料**，不是规则本身。
