## 0 · 一句话

链上两处提示词**各自教的形状都合法**，而**合起来被自己的判据必拒**：

```text
段 A  教  sky 不铺 + parallax 0.3        （"天空不平铺"，且样板自己写了 0.3）
段 B  教  world 宽 1440、只横向滚         （骨架 :618 逐字 w: 1440；铁律 8 又说「世界可以宽 1440」）
判据  算  不平铺的层画 480，镜头走 960 ⇒ 只剩 192 < 480 ⇒ 拒
```

⭐ **而本轮量到的最要紧的一条是：那个 `0.3` 在本仓出现两次 —— 一次是「教模型写的」，一次是「测试造出来证明会拒的」。**
`packages/demo/tests/site.test.ts:104-107` 拿那份**合规**夹具 `bg-dusk-halt`，
把 sky 的视差**从 0 改成 0.3**，然后断言它「盖不住世界」；而 `prompt.ts:494` 那句样板逐字写着
`{"name":"sky","parallax":0.3}`。

## 1 · 立案现场（三处原文逐字对读 · 行号本轮全部复核过）

### 段 A —— `packages/assets/src/prompt.ts:491-497`（`recipeShapeSpec()`）

```text
  background → "layers":[{"name":"sky","parallax":0.3},
                         {"name":"ground","parallax":1,"tileable":{"x":true,"y":false}}]
               ← **数组**，每项是对象，**从远到近**排序；层名会拼成帧名 `<资源 id>.<层名>`
               ← 不平铺的层**别写 tileable**（三层里通常只有墙与地平铺，天空不平铺）
```

⚠️ **两句合起来读**：样板展示的是「**不平铺 + parallax 非零**」，而下面那句注释**把「天空不平铺」
说成一个通则** —— 于是模型拿到的是「远层不铺」这个模型，而不是「远层不铺**就必须 p0**」这条规矩。

### 段 B —— `packages/assets/src/ops.ts`（骨架 `:618` · 铁律 4 `:848-849` · 铁律 8 `:856-857`）

```text
骨架 :618   world: { size: { w: 1440, h: 270 } },

铁律 4      `world.size.h` **必须等于视口高 270**（这个游戏单屏高，只横向滚动；视口是 480×270）。
            `world.size.w` 自己定（横向滚多远）。

铁律 8      ⚠️ `hud` 的坐标是屏幕空间（≤ 480×270），不是世界空间。
            世界可以宽 1440，但屏幕只有 480 宽 —— HUD 写到 x > 408 就跑出屏幕了，直接拒。
```

⇒ **整段提示词在把世界往宽里推**：骨架就是 1440，铁律 8 又把「世界可以宽 1440」当成**前提**在讲。

### 判据 —— `packages/contracts/src/layer-coverage.ts:49-64 · 94-109`

```ts
layerDrawnSize:  可平铺的轴 ⇒ worldSize，不平铺的轴 ⇒ 资源**标称尺寸**
coveredExtent:   drawn − parallax × travel
auditLayerCoverage:  不平铺且 parallax > 0 的层，配一个比视口宽的世界 ⇒ 报 error
                     报文末句逐字：「—— **不平铺的层只有 parallax = 0 才恒成立**（票 40 算过的那条）」
```

⚠️ **判据与渲染器同源**：`packages/demo/src/draw.ts:223` 调的**就是** `layerDrawnSize`，
非平铺层按标称尺寸**只画一次**（`:225-228`）。⇒ **判据不是保守估计，它算的就是外壳要画的东西。**

### ⭐ 那个 `0.3` 的第二次出现 —— `packages/demo/tests/site.test.ts:104-112`

```ts
it("**第四族**：不平铺的层给了非零视差 → 硬失败（票 40 算过：盖不住）", () => {
  // 天空是唯一不平铺的层。给它 0.3 的视差 ⇒ 镜头走到尽头时屏幕上只剩 192px，而视口要 480px。
  const h = harness();
  const manifest = readJson(path.join(PACK, "manifest.json"));
  const sky = (manifest.assets as ...[]).find((a) => a.id === "bg-dusk-halt")!;
  (sky.layers as ...[])[0]!.parallax = 0.3;          // ← 把合规夹具**改成**致命形状
  ...

```

⭐ **同一个数、同一个层名**：一处**教**模型写 `sky parallax 0.3`，一处**造** `sky parallax 0.3`
来证明它必须被拒 —— 而这两处从没被放在一起看。

⚠️ **顺带纠正票面 §「已经量到的」里的一句**：票面写「`recipeShapeSpec()` 是一个**导出的、被测试钉住的**
字符串 ⇒ 改它不是改一句散文，是一份**有测试看着的契约面**」。
**前半句对，后半句要收窄**：`prompt.test.ts` 钉的是**九宫格那三句**（`ui` / 面板 / 害处），
而**样板里那条 `background` 行一条测试都没有**（全仓 grep：`prompt.ts:494/497` 是那串字的**唯二**出处，
没有任何测试断言它）。⇒ **改动它不会被任何测试拦下** —— 这既降低了改它的成本，

⚠️ **另两处行号是陈的**（本轮复核过）：票面 §Question 写「`ops.ts:808-809` 规则 4 · `:816-817` 规则 8」，
**今天是 `:848-849` 与 `:856-857`**（骨架那一行 `:618` **是对的**）。⚠️ 票面不改，只在这里记一笔。
⇒ 这一小节里引的铁律 4 / 铁律 8 **是按今天的行号引的**。

### ⭐④ 样板只画了**两层**，而两份真产物都写了**三层** —— 而中间那层同样是致命的

⇒ **只把 `sky` 那一个数改成 0，中间层还会照错**。这一条直接决定「改数字」够不够（见 Q1）。

❓ **Q2 — 修完之后「谁看着它」？**（票面的第 2 问）

⚠️ **今天确实没有任何东西看着这两份样板合起来的样子** —— 而且本轮把它量实了：
**那条 `background` 行一条测试都没有**（§1 末），而**两份真产物各自独立地抄错了同一个形状**。
⇒ 这也是「**靠重跑验证**」这条路被否掉的理由（人裁逐字：「**不能只靠重跑验证**」）。

三条路：

- **(a) 只做「跨阶段一致性」测试**：一条测试把**两处样板**读出来，断言它们的组合过 `auditLayerCoverage`。
  ⚠️ 但样板是**一段字**（`recipeShapeSpec()` 里的散文）—— 要读它就得**解析字符串**，
  而「读源码文本的见证测试」本仓有先例（票 72 的 `shell-hud-declared-size.test.ts`），
  代价也记着：**语义等价的重写也会红**（票 72 实测的变异 4）。
- ⭐ **(b) 先让样板那一格变成数据，再钉它**：`recipeShapeSpec()` 里那三层是**字符串里的散文**，
  而 **`recipeShapeSpec` 这个函数本身当年就是从内联模板串里提出来、才被测试钉住的**
  （`prompt.ts:480-490` 逐字记着票 08 的这条理由：「**能被测试钉住的前提是它是数据、不是一段埋在模板串里的散文**」）。
  ⇒ **同一条教训，今天差一层**：样板**层**还是散文。把它提成一份导出的数据，
  测试就能**直接把它喂进 `auditLayerCoverage`**（不必解析字符串，也不必靠正则）。
- **(c) 两者都做**：先提数据，再钉一条断言它的组合过判据。

➡️ **推荐 (c)，但把它裁成「另立施工票」** —— 三个理由：
① 它是**新东西**（票面自己写着「那**也是新东西**，得单独裁」）；
② ⚠️ 它是**结构改动**（把样板层提成数据会动 `recipeShapeSpec()` 的**返回形状**，而那是一个
   **被测试钉住、被 `prompt.ts:802` 消费**的导出）⇒ 比改一行字大；
③ ⚠️ **本票的边界只到「在哪一侧修正契约」**（人裁边界第 2 条逐字），**不含「加一条新判据」**。
⚠️ 若裁「本票内一并做」，那是**明确放宽本票边界**，请照你的话裁。
