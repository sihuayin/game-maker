## 二、这一轮要你裁的

### ❓ Q9 — 配方提示词那一句的逐字措辞，以及「唯一来源」抽到哪一档

**拟插进 `assetPlanPrompt`**（位置：那「四条硬规则」之后、`⚠️ 四个槽的 id` 那两句之前）：

```
⚠️ **玩家那件资源有一条硬要求** —— 外壳按三个固定键播三种动作，缺一样就编不出一份能跑的配置：

   1. 玩家角色的 <idle> / <run> / <jump> **三路动画必须合成一件** `kind:"animation"` 的资源 ——
      这一件的 `animations[]` 里**同时**有这三个名字，**名字照字面**（就是这三个词，不许改写）。
   2. 每一路**至少 2 帧**（1 帧是静帧，不是动画）。
   3. 这一件**必须写** `characterId`（= 上面设计层那个玩家的 id）。
   4. ⚠️ 玩家名下 `kind:"animation"` 的资源**只许这一件** —— **别把三路拆成三件**：
      拆开之后配置那一步就没办法确定该引用哪一件，而且会多花三笔生图的钱。
```

（`<idle>` 那三个词由 `game-config.ts` 那个具名导出**插值**出来，不是手打 —— 见下面 (a)/(b)。）

**而「唯一来源」抽成哪一种**：

- **(a) 三个词全仓只写一遍，四处派生**：在 `game-config.ts` 里立一个字面量
  （`const PlayerAnimsShape = { idle: z.string().min(1), run: …, jump: … } as const`），
  `Player.anims` 由它 `z.object(...)` 出来，`PLAYER_ACTION_NAMES = Object.keys(PlayerAnimsShape)` 喂提示词与闸门，
  v4 镜像与骨架也由它派生。
- **(b) 只抽一个名字数组，键照旧手写 + 一条漂移测试钉住两边**（照 `config-tool.test.ts` 那个先例的样式）。

➡️ **推荐 (a)**。理由：① 你那条边界要收的是**三处**（事实 ④），(b) 得写三条漂移测试才等价，(a) 一处字面、结构上不可能漂；
② 它是**给既有字面量起个名字**，不新增概念（你 Q2 推荐 (a) 时的同一句话）；
③ 序列化出去的工具 `input_schema` **一个字不变**（三个键照旧），所以模型看到的东西没变。

⚠️ **代价如实说**：(a) 让契约里 `Player.anims` 那三个键**不再逐字写在 schema 字面量上**，
读代码时要多跳一层；若你更看重「schema 一眼读完」，那就是 (b)。
