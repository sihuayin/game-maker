## 1 · 四问

❓ **Q1** · **这算不算病？而「病」是哪一句？**

这问今天有了一个**票面没看见的分岔**（读数 ④）：

- **(a) 窄定义**：病 = 「`entities[].id` 等于**它自己的 `type`**」。→ **层内可算**（`id` 与 `type` 躺在同一格）、
  免费可测。⚠️ 但它的**射程比直觉窄**：`chest`（类名，`type` 是 `interactable`）**不**触发它。
- **(b) 宽定义**：病 = 「`id` **应当描述这一个，不是描述这一类**」（人裁票 42 Q3 的原话）。
  → **射程对**，但**今天写不出可算的判据** —— 「这是个类名」没有层内的定义，
  硬写只能靠一张类名词表，那正是 R3 的门要挡的噪声。
- **(c) 不是病**：它是味道，零尸体（读数 ⑤：下游代价 0）⇒ 不值一条判据。
- **(d) 不是病，且什么都不做**（连提示词也不加）。

⚠️ **把话说全 —— (a) 的代价**：判据上线后，当用户**只说了一类东西**（「废土里有敌人」）时，
模型会被**禁止**写 `{id:"enemy", type:"enemy"}`，只能**另起一个更具体的名字** ——
即判据会**逼模型编一个用户没给的细节**。而本仓对意图层有一条反向的规矩（票 09：
「凭空加一个 Boss 是**错的**」）。
⚠️ **但这条代价比它看上去小**：意图层的 id **本来就是编的** —— `enemy` / `chest` / `scavenger`
**一个都不是用户说的字**，模型每一步都在发明标识符。判据要求的是**换个形状**，不是**多记一个事实**。

➡️ **推荐 (a) 窄定义**，理由四条：① 这条判据的**字面是人自己写的**（票 42 Q3：「id 应当描述这一个，
不是描述这一类」）；② 它**层内可算**且**免费可测**，不需要一次真跑就能证「不误杀」；
③ **先例**：色板不得重色（`game-intent.ts:227` 自己引的那条）同样是**形状口味被判据化**；
④ (b) 今天落不了地，选它等于把病记进雾、不治。
⚠️ **并且说清它不是全部**：读 ④ 已量到 **(a) 拦不住 `interactables` 那一整类类名** ⇒
它是**一档**，不是「治好了这个病」。

❓ **Q2** · **（若 Q1 = 病）判据加在哪一层？**

- **(a) 意图层** —— 那里是**产地**（7/9 份都是它起的），`type` 就摆在同一格；
  「`id` 不许等于它自己的 `type`」**层内精确可算**。
  ⚠️ 代价：意图层是「**记录用户说了什么**」那一层，给它加口味与定位有张力（见 Q1 末）。
  ⚠️ 它**改不了老数据**：改判据只影响新跑。
- **(b) 设计层** —— ⚠️ **与「原样沿用 · 不许改名」正面打架**（`game-design/src/prompts.ts:187`）：
  模型会被要求沿用 `enemy`、同时被禁止填 `enemy`。走这条**必须同时松开票 03 Q2(b) 的引用族**，
  **那要另开票**（R17）。
- **(c) 只改提示词**（意图层工具说明加一句「`id` 要说得出是**哪一个**，别写成它自己的 `type`」）——
  ⚠️ 形状上**没有护栏**（票 35「散文里禁止、形状里邀请」的先例），且**未经实测**
  （票 64 Q10 明文不选「加入未经独立验证的额外提示词约束」· 票 40 的教训）。
- **(d) 先不动。**

➡️ **推荐 (a) 意图层，并且配一句提示词。** 两条理由：
① **(b) 的代价高一个数量级**（要动票 03 的引用族）；② ⚠️ **光有判据 = 盲重采样** ——
R16 的重采样**重发同一个 `body`、模型看不到理由**（票 65 否掉「甲」时的原话），
所以判据必须**配一句话**让那一发有的放矢。
⚠️ **但那句话的定位要说死**：它是**让重采样有机会改对**的辅助，**不是**一条被声明有效的独立手段
（与票 64 Q10 的边界一致）。

❓ **Q3** · **（若 Q1 = 病）判据管哪个字符串形状？**

读数 ① / ② 给的现状是 **单数类名 7/9 · 复数桶名 1/9**。
⚠️ 但这两个形状**在意图层其实是同一条规则**：意图层**没有「桶」这个概念**
（`enemies` / `resources` 是**设计层**的四个数组名），`enemies` 就是 `type + "s"`。

- **(a) 只管单数**（`id !== type`）。
- **(b) 只管复数**（`id !== type + "s"`）。⚠️ 九份里只有一份能触发 —— 且它是**最早**的那批。
- **(c) 两个都管**。

➡️ **推荐 (c)，但写成一条规则**：`entities[i].id !== entities[i].type` **且** `!== type + "s"`。
理由：它**不引入意图层没有的概念**（「桶名」那个词甚至写不进这一层的判据里），
而多管的那半（`+ "s"`）**零额外风险**（一个正常 id 不会恰好是 `type+"s"`）。
⚠️ 顺带一条**该记下的趋势**：复数那一档**只在第七跑出现过，13x 那四份一次都没有** ——
它可能是**旧提示词的残留**，不是稳定行为（但这只是一条观察，**没有做过单变量实验**）。

❓ **Q4** · **（若 Q1 = 病）判据要不要钉测试？钉哪几条？**

➡️ **推荐要，阳性 + 阴性各一条**（照票 03「意图 ⊆ 设计」· 票 42 Q4 = A 的惯例）：
- **阳性**：`{id:"enemy", type:"enemy"}` **必须被拒**（含 `+ "s"` 那一档：`{id:"enemies", type:"enemy"}`）。
- **阴性**（⚠️ 尤其要紧）：`{id:"scavenger", type:"npc"}` / `{id:"enemy-wasteland", type:"enemy"}` /
  `{id:"resource-node", type:"resource"}` **一个都不许误拒** ——
  最后那条**是 13b/13g 的真实产物**，拿真产物当阴性用例。

⚠️ **并且在这一问上把本票的能力边界说死**（票面 §4 已写，本轮复核为真）：
本票落地后**只有免费手段证明「不误杀」**；
**「拦得住」证明不了** —— 那要靠**真跑**，而真跑是**票 23**的事，**另出报告 + 逐次明确同意**。
⇒ **不许**把「判据写了」当成「模型听话了」。
