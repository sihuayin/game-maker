### ⭐ ① 那些「杂物」**逐字就是需求自己那张清单**

需求第 7-15 行写着：

```text
游戏需要有：
- 横版移动
- 跳跃
- 宝箱
- 资源
- 敌人
- 废土背景
- 最终目标
```

而第八跑（13a，2026-10-13 10:21）那份意图的 `mechanics[].name`，**七条、逐条相同、顺序都一样**：

```text
横版移动 · 跳跃 · 宝箱 · 资源 · 敌人 · 废土背景 · 最终目标        ← 逐条相同：true
```

⇒ **坏的不是「模型爱乱写」，是这份需求自己把四类东西（怎么玩 / 有个东西在那儿 / 那个地方什么样 /
最终目标）塞进了同一张名叫「游戏需要有」的清单里**，而意图契约里唯一长得像「游戏需要有」的那个数组
正是 `mechanics[]`。⚠️ **抄，是这一层的局部合理读法。**

### ⭐ ② 散文落地前后：**6/7 → 0/6**

按票 54（commit `a455bf3` · **2026-10-13 12:24**）把 13 份切两半（逐份按 `mtime` 归位）：

| | 份数 | **带错格的** | 错格条目 |
|---|---|---|---|
| **「先分家」散文之前** | 7 | **6 份 ⇒ 6/7** | **17 / 34 条** |
| **之后** | 6 | **0 份 ⇒ 0/6** | **0 / 30 条** |

⭐ 而后半那 6 份**不是「少写了几条」，是每一份都把那张清单读懂了**：7 条清单 →
5 条真机制（`横版移动`→`side-scroll-move` · `跳跃`→`jump` · `宝箱`→**`open-chest`** ·
`资源`→`collect-resource` · `敌人`→`avoid-enemy`），而 `废土背景` 与 `最终目标` **正确地没进 `mechanics[]`**
（它们各自的家是 `world` 与 `winConditions[]`）。
⇒ ⭐ **散文正好治在它被写出来要治的那个陷阱上。**

⚠️ **反面读照实摆**：这 6 份是**同一份需求跑了六遍**，不是六份不同的需求 ⇒
**它对「换一份需求会怎样」一个字都没说**。而 `game-intent.ts:31` 那条「自由文本是故意的」
决定的正是「换一份需求」这一档。

### ③ 今天那道 gate 逮得住谁、逮不住谁（全盘 64 条机制逐条过 `GameIntentSpecSchema`）

| 今天被 ⑤b **逮住**的（跨数组撞名） | | 今天**漏掉**的 | |
|---|---|---|---|
| `chest` | 实体名 ×4 | `final-goal` | **胜利条件 ×2** |
| `resource` | 实体名 ×3 | `resource` | 实体名 ×2 |
| `treasure-chest` | 实体名 ×2 | `resource-pickup` | **实体名 ×1** |
| `enemy` | 实体名 ×1 | `enemy-threat` | **实体名 ×1** |
| | | `wasteland-bg` | **布景 ×1** |

⚠️ **同一个词两种命运** —— `resource` 既被逮住 ×3、又被漏掉 ×2，分界线**只是实体那张表有没有把它拼成同一个字**：

```text
逮住  entities: scavenger, enemy, chest, resource      ← 实体 id 也叫 resource
漏掉  entities: scavenger, chest, resources, enemies    ← 实体 id 叫 resources
```

⇒ **⑤b 逮的是「抄得一模一样」，不是「这是不是一条机制」。**
⚠️ 于是**布景与胜利条件这一类永远逮不住**（它们根本没有能撞的实体），
而**实体名只要随手改一个字就漏**（`resource` → `resource-pickup`）。

### ④ ⭐ 「名字撞表」这条**可计算**的形状判据，可行吗

阈值：`mechanics[].name`（trim）与 `world.theme` / `world.setting` / `world.atmosphere` /
`winConditions[]` / `loseConditions[]` / `entities[].role` 中的任一条**互为子串**（长度 ≥ 2）就报。

```text
错格 17 条：逮住 17 · 漏 0
真机制 47 条：误伤 0 · 放过 47
```

**看起来是一把好尺子。** ⚠️ 但——

### ⭐⑤ 而那 0/47 **是语料的性质，不是规则的性质**

拿**同一份需求**能自然写出来的真机制名去试同一把尺子：

| 候选真机制名 | 判 |
|---|---|
| `探索废弃城市` | ⚠️ **误报** —— 撞 `world.setting`「废弃城市」 |
| `废土生存` | ⚠️ **误报** —— 撞 `world.theme`「废土」 |
| `在废土中前进` | ⚠️ **误报** —— 撞 `world.theme`「废土」 |
| `收集宝箱里的资源` | ✅ 放过 |
| `躲避危险` | ✅ 放过 |
| `跳跃越过废墟` | ✅ 放过 |

⇒ **3 / 6 条自然真机制名被判死。** 而这条尺子**没有更窄的写法**：
把它改成**全等**（`wasteland-bg` ≠ `废土`）⇒ **一条都逮不住**；子串正是它唯一能响的方式。
⚠️ **根因**：`world.theme` 是「废土」这种**两个字的通用词**，而中文机制名带世界词是**常态**。

**分池看，三个池的成色不一样**（同一把尺子，只换比对池）：

| 池 | 错格 17 条 | 真机制 47 条 | 候选真名 6 条 |
|---|---|---|---|
| `world.*` | 逮 1（只有 `wasteland-bg`） | 误伤 0 | ⚠️ **误报 1** |
| `winConditions` / `loseConditions` | 逮 3 | 误伤 0 | 误报 0 |
| `entities[].role` | 逮 14 | 误伤 0 | 误报 0 |

⚠️ 而 `entities[].role` 那个池的「误报 0」同样是**短语料**——角色写得越短（比如就把 role 写成「敌人」），
任何提到敌人的机制名都会撞上去。
