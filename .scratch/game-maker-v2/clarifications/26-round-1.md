❓ **Q1（根问题）** - **多参考图要解决的，到底是哪件事？**

这一问票面**从来没有问过**，而它下面的所有问题都挂在它上面。两种语义：

- **(A) 同一件事的多个来源** —— 你手上有两三张**废土**参考图（同一个世界的三张截图 / 一个 mood board），
  它们都在说「这个世界长什么样」。⇒ **核心问题是「融合 / 谁说了算」**，
  而 `role` **没有意义**（它们全都是「风格图」，今天的 `role: "global"` 正是这个意思）。
- **(B) 不同的事各一个来源** —— 一张定**色**、一张定**角色**、一张定**环境**。
  ⇒ **核心问题变成「谁读哪一个」**，而**冲突在构造上不存在**（每个 role 喂给不同的产物）。
  ⚠️ 但这条路与 R18 之前的裁决**相抵**（`characterImages` / `materialImages` 被判「零消费者，不进」，见 ⑥-3）。

我量到的、指向 **(A)** 的：字段名就是 **`style*References*`**（全是风格参考）· 所有真实调用方都写 `role: "global"` ·
契约里那份被 omit 掉的模型面向 schema 里**没有** role 的位置 · 终点写的是 `Style Image + Game Intent`（**单数**）。
指向 **(B)** 的：**R18 自己的理由文字**（「一图一角色」是个合理方向）+ `00-overview.md §1` 的
「Style Reference Image**(s)**」。

➡️ **我推荐 (A)**。理由一句话：**(B) 需要的那三件事，仓库已经用「字段」表达过一次并被判出局**
（`characterImages` / `materialImages`，理由是零消费者）—— 把它们换个名字塞进 `role` 里，
**消费者一个也没多出来**，只是把同一个未决问题挪了个地方。
⚠️ 若你要 (B)，那 Q3 之后的整棵树都会长得不一样（`role` 必须成枚举、且每个 role 要**指名一个读者**）。

❓ **Q2** - **本票的产物是什么：只出决定，还是决定 + 实现？**

这是 **R5 与 R18 正面撞车**的地方，而两条都是 R：

- **R5**（本图的 Notes）：「票解出来的决定**当场实现**」。
- **R18**：「N 图的权重融合与冲突解决**没有任何实测**，**不许在这一阶段实现**」。
- ⚠️ 而 **R17** 说：**要改 R 表必须重新开票**。

三个选项：

- **(a) 本票只出决定**（决定写进 Answer，实现**另开一张施工票**）。
  ⚠️ 代价：R5 那句话在本票上不兑现。
- **(b) 本票决定 + 实现**（按 R5）。⚠️ 代价：那是**改 R18 的字面** ⇒ **按 R17 得先开一张改 R18 的票**，
  而且它要动**契约 + vision + assets（ops 的静默丢图 + image-gen 的两个硬编码槽位）+ CLI + MCP + 测试**，
  体量**远超一张票**。
- **(c) 本票决定 + 实现**，但**只实现「契约与入口」那一层**（让 N 张能**表达**、能被**拒**得明白），
  真正的多图融合**留到有实测之后**。

➡️ **我推荐 (a)**：**先把「什么是合格的多图设计」定死，再谈施工** ——
因为 0.2 那三条「没有实测」今天一条都没变，而 (b) 等于**用施工替被测**。
⚠️ 若你选 (b)/(c)，请顺带说一句「R18 那句话怎么办」（改字面 ⇒ 另开票）。

❓ **Q3** - **那条「多给一张就拒绝」的边界：改代码对齐文档，还是改文档？**

事实是 **一句话、两个说法**（0.1 的 ③）：

- **文档**（契约注释 · `docs/v2/01-contracts.md:119` · 本票 §4）说：**由调用方执行 · 退出码 2**。
- **代码**说：契约**不拦**（0/1/3 张都合法）；真正的拦阻在 `analyzeReference` **深处**，
  是个**普通 Error ⇒ 退出码 1**；而**退出码 2 只出现在 CLI 的 `--style` 给两次那一条路上**。

- **(a) 改代码对齐文档**：把「>1 张」的检查**提到调用方边界**（CLI / MCP / pipeline 入口），
  报 `CommandError("usage")` ⇒ **2**；`vision` 那条 assert 降级成**兜底**（只为防 API 直调）。
  ⚠️ 好处：文档那三处**一个字都不用改**，而「调用方执行」第一次**字面为真**。
- **(b) 改文档对齐代码**：把那三处改成「vision 深处拒 · 退出码 1」。
  ⚠️ 但这与 R4-Q3 那句「**调用方**执行」的设计意图相反，而且 CLI 那条路的 2 会留在那里**自相矛盾**。
- **(c) 不管**（本票只出决定，实现时再说）。

➡️ **我推荐 (a)** —— 但 ⚠️ **它与 Q2 绑定**：若 Q2 选 (a)（本票只出决定），
那这一条就**只记成一条待办**，实际改在施工票里做。
