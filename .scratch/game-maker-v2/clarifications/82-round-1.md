## 0 · 本轮**新量到的**（票面 §1/§2 之外的东西 —— 票面没写、也没有任何一票量过）

### A ⭐ 真跑里 HUD 锚点的**普查** —— 20 件 `ui`，`{0,1}` 出现 **0 次**

票面 §2 说的是「盘上的锚点不止一种」，读的是**两份入库夹具**（都是人写的）。
本轮把**模型自己写的**那两个包也算了进来 —— 它们躺在 e2e 实验的 raw 目录里，包里带 `ledger.json`
（⇒ **真跑**，不是桩）：`experiments/e2e-wasteland/raw/run-out-2026-10-13{e,h}/ruined-city-scavenger/pack/v1/`。

| 跑 | `kind=ui` 的锚点 |
| --- | --- |
| **13e**（4 件） | **全部 `{0.5, 0.5}`** —— 含那张九宫格面板 `hud-bar-backdrop` |
| **13h**（6 件） | `{0.5,0.5}` ×4 · **`{0,0}` ×2**（`ui-pickup-counter` · `ui-hp-pips`） |

⇒ 模型选锚点的分布：**中心 16/20 · 左上角 4/20 · 左下角 0/20**。
⚠️ 而 **13h 那一跑是绿的**，它的 `run/v1/game-config.json` 逐字：

```json
"hud": { "panel": { "asset": "ui-pickup-counter", "at": { "x": 8, "y": 8 }, "size": { "w": 64, "h": 16 } }, … }
```

面板锚点 `{0,0}` + `at = {8,8}` ⇒ 盒子 `(8,8) 64×16`，**落在视口左上角，全绿**。
⇒ ⭐ **「HUD 面板是左下角」这句话，对着**真跑**的现实是 0/20。**

### B ⭐ **归属倒置**：写锚点的那一层没被告知，被告知的那一层不写锚点

| | 谁 | 看不看得见那条约定 |
| --- | --- | --- |
| **锚点是它写的** | `assetPlanPrompt`（`prompt.ts:779`） | ❌ **只有一句 JSON 形状**：`"anchor":{"x":0..1,"y":0..1}`（`:814`）—— **一条按 kind 的规矩都没有** |
| **锚点是它读的** | `CONFIG_TOOL_DESCRIPTION`（`prompt.ts:867`） | ✅ 「…HUD 面板是**左下角**」 |
| **锚点提示是它收的** | `compileRuntime` 里那段「# 锚点的意思（照这个摆）」（`ops.ts:875-876`） | ✅ 同上，且**按 kind 去重后印** |

⚠️ 配置侧**从不写锚点**（它写 `at`）· 创作侧**从不被告知**那条约定。
⇒ ⭐ **这条约定写在不能执行它的地方，缺在决定它的地方。** 这是盘上三种锚点的**成因**，票面没记这一条。

### C ⭐ 若要走「配方层」，**今天没有键**：(b) 不是贵，是**不可表达**

票面 §3.1 的 (b) 写的是「`kind === "ui"` 的**某几类**必须 `anchor = {x:0,y:1}`」。本轮的读数：

- **`kind` 太粗**：`ui` 一个值同时覆盖**面板 · 棋子 · 图标 · 提示 · 结算面板**；
- **`role` 不是键，是模型自由写的散文**：
  · 13h → `'HUD · 收集数计数条'` / `'HUD 图标 · 废料'`
  · 13e → `'ui-bar'` / `'ui-resource-icon'`
  · 入库夹具 → `'屏幕左下角 HUD 面板，三个槽位显示失物收集进度'` ⚠️ **约定本身被写进了那串散文里**
- 全仓 89 件 `ui` 的 `role` 取值一共 **8 种**：**6 种是模型自己写的散文**（如「界面：机关按钮的底板，九宫格可拉伸」），
  2 种是随手起的名（`hud` · `icon`）。

⇒ ⭐ **「某几类」今天指不出来。** 唯一现成的键是**配置侧的槽位名**（`config.hud.panel.asset`）——
而那正是 `td-config.ts:416` 那条判据的形状（从配置知道「它是砖」，再去包里读锚点）。

### D · 先例：契约层**已经**有一条「锚点必须是某个值」的判据 —— 但它判的是**砖**

`packages/contracts/src/td-config.ts:416-418` 逐字：

> 砖 "…" 的锚点是 `{x:…, y:…}`，而外壳按「**格心 + 锚点**」摆精灵 ⇒ 锚点不正中，整张地图会**偏半格**，
> 而没有任何东西会报错。砖的锚点必须是 `{x:0.5, y:0.5}`

⚠️ 它成立的理由是「**外壳有一个写死的公式**」，**不是**「这是我们家的写法」。

### E ⭐ 而 HUD 那一侧**没有**那个公式 —— 约定今天**不承重**

`packages/demo/src/world.ts:171` 逐字：

```ts
const hudPanel = resolveDraw(pack, cfg.hud.panel.at, { asset: cfg.hud.panel.asset }, issues, "hud.panel", …);
```

面板走的是**与所有实体同一条通用规则**（锚点从包里取）。`screen-space.ts:94/115-124` 读 HUD 锚点，
也只是为了**算盒子**去比视口，**不判锚点本身**。

⇒ ⭐ **砖的锚点变了会坏；HUD 的锚点变了只是换一种写法**（`at` 跟着补偿即可）。
—— 这一条差别，是「(b) 该不该做」的真正分界线：**判据要有可承重的东西垫着**。

### F · `auditAssetSpec` **从不读 `anchor`** —— 而它的文件头点名承诺它会读

`packages/contracts/src/audit.ts:37-40` 逐字：

> **spec ↔ 产物对账**：`AssetSpec` 说要做成什么样，包里实际做出的是什么。
> 这是「需求 vs 产物」**唯一**的对账点。没有它，`AssetSpec` 里的
> `size` / `animations` / `anchor` 就只是写给自己看的注释。

而函数体逐条查了 `kind` · `size` · `animations` · `layers` · drawlist `viewBox`，
**`anchor` 一次都没读**（`grep -n "anchor" packages/contracts/src/audit.ts` ⇒ 只有 `:40` 那句注释）。
⚠️ 今天这个缺口被**构造遮住**：`pack.ts:1032` / `:1089` 把 `b.spec.anchor` **逐字节复制**进 manifest ⇒ 两者恒等。
⇒ **它今天不会红 —— 但「不会红」不等于「被守着」。**

### ❓ Q1 · 这条约定**是不是一条判据**？（R3 的门：**精确可算** ＋ **错了一定不是设计**）

这是本票真正的前置问题 —— 票面 §3.1 那三个选项全都预设了它是判据。

- **(a) 是判据**：横版 HUD 面板必须 `{0,1}`；
- **(b) 不是判据**：它是**授权侧的一种写法**，不是「错了就一定是 bug」；
- **(c) 分玩法**：横版是、塔防不是（或反向）—— ⚠️ 票面 §3.3 问的就是这个；
- **(d)** 别的。

➡️ **推荐 (b)**。两条本轮量到的硬理由：**A** —— 真跑 20 件 `ui` 里 `{0,1}` 出现 **0 次**，而那两跑**全绿**；
**E** —— 外壳对 HUD **没有固定公式**（砖有）。按 R3 的第二条，「锚点写成左上角」在盘上**是一份合法的另一套写法**，
**过不去**「错了一定不是设计」那一道门。
⚠️ **反方论据（供裁）**：票面 §「咬合」那条 —— 锚点决定负盒子出不出现，`td-config.ts:446` 查负数；
把塔防 ui 锚点改成 `{0,1}` 而骨架 `at` 不动会当场点火。但那说的是**改了会坏**，不是**不改就错**。

### ❓ Q4 · `anchorHint` 那句**按 `kind` 去重** —— 要不要动？

现场（`ops.ts:875-876`，住在 `compileRuntime` 的**配置侧**提示词里）：

```
# 锚点的意思（照这个摆）
${[...new Set(manifest.assets.map((a) => `${a.kind}：${anchorHint(a.anchor)}`))].join(" · ")}
```

⇒ 入库夹具印出来是 **`ui：左下角 · ui：左上角`** —— **同一个 `kind` 的两条互相矛盾的话同时摆在模型面前**。
⚠️ 而 `resourceBrief` **每一行已经带着真实锚点**（`ops.ts:690`：`… · 锚点 {x:0, y:1} · 动画：…`），
⇒ 这一句是那批**逐行事实**的一个**去重摘要**，而摘要比原文更粗、还会互相矛盾。

- **(a) 改成逐资源印**（不再按 `kind` 去重）；
- **(b) 整句删掉**（保留逐行那一份就够了）；
- **(c) 不动**（记为已知）；
- **(d)** 别的。

➡️ **推荐 (b)**。⚠️ 改它属**改提示词**，要**另一次授权**。

### ❓ Q5 · 契约那句把 HUD 与地面线捆在一起的散文 —— 要不要改？

`packages/contracts/src/game-config.ts:412-416` 逐字：

> ⚠️ `at` 是「资源锚点落在哪」，不是左上角（票 48）。**这条由包定死**：
> 角色的锚点是**脚**（`{x:.5,y:.95}`）、世界里的道具是**底边中心**（`{x:.5,y:1}`）、
> **HUD 面板是左下角（`{x:0,y:1}`）**。所以站在地面线上的东西写 `at.y = 地面 y`，
> 而它的盒子是**从 `at` 往上长**的 —— 不是从 `at` 往下。

⚠️ 两处与今天的盘不符：

1. 「**这条由包定死：… HUD 面板是左下角**」—— **包没有定死这一条**（§0-A：20/20 都不是 `{0,1}`）。
   这是一句**关于代码库的错话**，而我们**要求模型照着它写 `at`**（同一句在提示词里有一份，`prompt.ts:867`）。
2. 「而它的盒子是**从 `at` 往上长**的」—— 那只对 `y = 1` 的锚点成立；
   真跑 13h 的面板锚点是 `{0,0}`，盒子**从 `at` 往下长**。

- **(a) 改**（把 HUD 那一项从句子里摘出来 · 把「往上长」限定成「锚点 `y = 1` 时」）；
- **(b) 不改**（本票**只作裁定**，改散文属另一次授权）；
- **(c) 只改第 1 处**（那句对盘错的话），第 2 处留着。

➡️ **推荐 (c)，且把它登记成下一张施工票的内容**（本票只登记，不动手）。
