## 乙 · §7 那条「要就地核的」：输入切分的答案

**问题**：`auditGeometry` 那段循环同时吃着三样东西 —— 外壳的绘制解析结果（`l.draw.missing` /
`l.draw.frame`）· 算好的盒子（`l.box`）· 视差（`l.parallax`）。而 `contracts` **碰不到** `WorldDescription`。

**答案（建议的施工形状，不是裁定）**：`contracts` 新增**两件**，`demo` 与 `config` 各调一次。

| 谁 | 新增/保留 |
|---|---|
| `contracts` ① | `layerDrawnSize(layer, worldSize)` —— **`draw.ts:221` 那条规则本身**（`const w = tileX ? W : nom.w`），`draw.ts` 改成调它 ⇒ 一条规则、两个调用者（§4③ 的 (A)） |
| `contracts` ② | `auditLayerCoverage(viewport, entries)` —— 吃**算好的 primitive**：`{ where, name, drawnW, drawnH, parallax }`，产出 `ConfigIssue[]`。`coveredExtent` 搬进这里 |
| `config` 侧 | `ops.ts:884` 那个 `issues` 数组里加一行（票面写 883，**今日实读 884**）；入参从 `config.world.size` + `manifest` 里那件背景的 `size` / `layers[]` **现拼**出来，`drawn` 由 ① 算 |
| `site` 侧 | `site.ts:39` 那段 `world.background.forEach` 换成**同一个 ②**；入参从 `world.background[i]` 的 `{ draw.frame, box, parallax }` 拼 |
| **留在 demo** | `draw.missing`（→ `"(解不到的层)"`）· `layers.length !== frames.length` 与「第 i 层没有帧」那两条 issue · **另外两条 coverage 判据**（最远层必须满 / 非最远层不准满，§4① 明说不碰） |

⚠️ **为什么这个形状不是 §4③ 表里被否掉的 (B)**：那张表否的是「**只**把算好的尺寸当接口、规则自己再抄一份」。
而 (A) 把**规则**提到 `contracts` 之后，config 侧算 `drawn` 用的是**同一份规则**（①），不是抄的
⇒ (B) 的反对理由**消失了**，剩下的只是一个自然结论：**规则共享 + 审计函数吃 primitive**。

⭐ **顺带一个白拿的**：`frame.name` 按契约就是 `<背景 id>.<层名>`（`assetpack.ts:68` 逐字）
⇒ config 侧用 `${assetId}.${layer.name}` 拼得出的名字，与 site 侧 `draw.frame` **逐字相同**
⇒ 验收条件 4 的**第二种证法**（两侧 message 逐字相等）**成立**，不必只靠「改坏 helper 两侧同时红」。

## 丙 · 一处对不上的（要你裁）

**§4② 逐字**：「报出去的那条 message 必须自带数字（世界尺寸 · 逐层 parallax · 最坏时剩多少 px · 视口多少 px）。
✅ 好消息：**现成那条 message 本来就带着这四样**（§1 那段原文）⇒ **一个字都不用重写**」。

⚠️ 而 §1 引的那条 message，**四样里只有三样**：

```text
层 "bg-ruined-street.sky" 盖不住世界：画出来 480×270px，视差 0.1 会跟着镜头退掉 96×0px，
最坏时屏幕上只剩 384×270px，而视口要 480×270px。
       ↑ 480×270 = 这件资源的标称尺寸，**不是世界**
```

**世界尺寸 1440 一个字都没有** —— 它只**藏**在 `96 ÷ 0.1 = 960` 里：读的人得自己除一次，
才推得出世界宽 = 960 + 480 = 1440。而 §4② 立这条要求的**理由**恰恰是
「config 抛 ⇒ **不落那份坏配置** ⇒ 失败现场里没有 `game-config.json` 可读」（第十五跑正是靠它读出 1440×270）
⇒ 要读者自己做一次除法，与「自带数字」**不是同一件事**。

而 §6 验收条件 7 的字面是「§1 那四样（**世界尺寸** · 逐层 parallax · 最坏 px · 视口）**一个不少**」。

⇒ **§4② 与条件 7 对不上**，两条都写在票面上，施工时必有一条要改口。

### ❓ Q2 — 那句话要不要补世界尺寸

一次「补」包含两件：改 `site.ts:55` 那条 message 的模板；把**新增的世界尺寸**也钉进判据。
⚠️ **两侧一起改**（同一个 helper），所以不存在「只有一侧带」的中间态。

- **(a)** **补**：在句子尾部带上一句世界尺寸（如 `而这个世界是 ${W.w}×${W.h}px（横向要滚 ${travelX}px）`），
  条件 7 按字面满足。
  ⚠️ **代价**：message **字节变了**；而**验收条件 9 那句「`site` 语义逐字不变」得改口**
  （改成「**成功路径**的站点产物逐字节不变 · 失败路径那两条 message 判据照旧绿」）——
  `site.test.ts:104` 那条是**正则**（`/盖不住世界/` · `/不平铺的层只有 parallax = 0/`），**不会红**。
- **(b)** **不补**：§4② 优先，条件 7 改口成「四样**可由 message 里现有的数推出来**」。
  ⚠️ 代价是「自带数字」这条**设计要求的理由**（不落盘 ⇒ 只有 message 可读）被读松了一格。
- **(c)** **只补 config 侧**：❌ **不推荐** —— 这会让两侧 message **不再逐字相等**，
  直接废掉验收条件 4 的第二种证法，为省一句话的字节付一条判据的代价。

➡️ **推荐 (a)**。理由：这一票的价值三件里有一件就是**失败账目/现场能够定位**（§2），
而 config 侧**确实拿不到那份配置**了 —— 把关键数留给读者去反推，正好是这条判据想消掉的那种事。
