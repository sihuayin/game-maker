❓ **Q1** - **母版那条零容差的长宽比判据怎么办？**

这是本跑**唯一的断点**，也是「再跑一次会不会又断在这」的关键。五条路：

- **A. 宽容差**（比如 ±3%）。依据可以是实测的：上游是**跳格子**的，请求落在格子之间必然有几 % 的误差（实测 1.6%~2.8%）。⚠️ 但「容差多少」没有原理，下次漂得更远照样卡。
- **B. 降格成观察**（R3 的判据/观察之分）：报出来、记进账、**不拦**。依据是 **R3 那条准入条件今天被实测打死了** —— 这条判据量的**不是设计**，是**上游的手气**（读数 A）。
- **C. 改判「角色本体的包围盒」**（抠完底量前景）：判我们真正在乎的头身比。⚠️ 但读数 B 说**这会让它更容易响**（同一目标量到 0.495~1.281）—— 不是修，是把判据挪到一个**更不稳**的量上。
- **D. 保持零容差 + 只发上游守得住的请求**：读数 A 证明「守不守得住」**不是比例的属性** ⇒ D **没有可执行形式**。
- **E. 删掉这条判据。**

➡️ **推荐 B（降格成观察）**。理由：R3 已经给了判据的准入条件，而这条**今天被实测判为不合格** —— 上游守不守不是设计能控的东西，正是「观察」那一类。⚠️ **明确不推荐 C**：它是这回探针扫出来的**反直觉点**（会更常响）。⚠️ 配套：把实测的漂移量（哪一发 · 请求什么 · 回来什么）写进账，**降格 ≠ 瞎**。
⚠️ 想给 A 找依据时我去查了官方那张「比例 → 分辨率」表，**网络被挡了**（`ai.google.dev` / `docs.cloud.google.com` / `raw.githubusercontent.com` 全部取不到）⇒ 上面**全是实测**。你要 A 有依据的话我另想办法取。

❓ **Q2** - **再开跑要不要恢复走「两段」（去掉 `--yes`）？**

`create` 本来就是**两段**（USAGE 逐字：**R9，人工点只有一个，在清单处**）：

> 不带 `--yes` ⇒ 跑到清单为止就**停下**（退出码 0、`status: "awaiting"`），把「这一步要生几张图」打给你看；人看完或改完清单，再跑 `game-maker build <那个 run 目录>` 接着往下。

带 `--yes` = **跳过那个检查点**（一路跑到站点）。
⚠️ **最近三跑的驱动全都带了 `--yes`。** ⇒ 「上限报不准」这件事，**有一半是我们自己跳过了那个本来会报数的地方**。

- **A. 恢复两段**：第一段只花文本钱（理解层 5 发），拿到清单**报准数**，人批了再跑第二段。
- **B. 继续 `--yes`**，只在报告里把不确定性说清楚。

➡️ **推荐 A**。零代码、是 R9 已经写下的设计、而且把「批准一个**估计**」变成「批准一份**清单**」。代价：多一条命令 + 人得看一眼清单。
⚠️ **但 A 单独不够** —— 见 Q3：检查点报的那个数**本身就用错了尺子**。

---

❓ **Q3** - **检查点报的数要不要对齐成「图单元数」？**

读数 C：检查点报 **11**（image 源**资产**数），而 `pack.ts` 真会发出去 **24** 次（20 图单元 + 4 母版）。
⇒ 根因**不是**「清单是模型生成的所以数不准」（那只是次要原因），而是**两边用了两把尺子**：检查点按**资产**算，`pack` 按**单元**算（动画一帧一单元 · 背景一层一单元），**中间没有任何一步把两者对上**。
⚠️ 这与票 37 栽的是**同一种形状**：「我们声明了什么」≠「实际交付了什么」。

- **A. 检查点改报图单元数**（与 `pack.ts` 同一把尺），并写明分法（几个 animation 帧 · 几个背景层 · 几个母版）。
- **B. 两个数都报**（资产数 + 单元数）。
- **C. 不动检查点**，报告里人肉算。

➡️ **推荐 A**：**同一个数只能有一把尺子**。⚠️ 动手前要先看 `pack.ts` 那个分法（`u.frames === 1` / 每层 / 每帧）**有没有被导出成可复用函数**，还是内联在 `pack` 里 —— 内联就得先抽出来，而**抽的时候两处必须共用一份**，否则就是**第三把尺子**。

❓ **Q4** - **`--concurrency` 只能把 text / image 一起设，要不要单开一条路？**

裁定当时给的是「**image 2**」；而 CLI 只有 `--concurrency <n>` 一个数，落成 `{ text: n, image: n }`（`cli.ts:179` 与 `:446`）⇒ **CLI 上表达不出「image 2」**。第四/五/六跑实为 `text 2 / image 2`。
⚠️ 而**引擎那一层是支持的**：`ops.ts:1029` 的签名就是 `concurrency?: { text?: number; image?: number }` ⇒ 缺的**只是那个 flag**。

- **A. 加一条只设 image 的路**（比如 `--concurrency-image <n>`，或让 `--concurrency` 收 `text:2,image:2` 这种值）。
- **B. 改裁定**，承认「text 与 image 共用一个数」就是设计。

➡️ **推荐 A**（工程量小 · 引擎已经支持 · 而现在**每跑都在偏离一条已裁的规矩**）。⚠️ 若选 B，那要按 R17 **另开票改那条裁定**，不能就这么一直漂着。
