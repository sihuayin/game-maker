## 0 · 一句话

「配置里声明的 `hud.*.size`，外壳**画出来**是不是那个数？」——今天两代外壳给出
**三套不同的答案**，而**三套都没有任何判据看着**：

| 格子 | 声明值作数吗 | 怎么画的 |
| --- | --- | --- |
| 横版 `hud.panel`（**九宫格 + WebGL**） | **作数** | `add.nineslice(…, p.w, p.h)`（`scene.ts:214`） |
| 横版 `hud.panel`（**其余两种情形**：非九宫格 · 九宫格但 Canvas 回退） | **不作数** | `add.image` 画**原生像素**，⚠️ **没有 `setDisplaySize`**（`scene.ts:215`） |
| 塔防 `hud.panel` | **永远作数** | `:161` 九宫格；或 `:162` 普通 image **＋ `:166` 无条件补 `setDisplaySize`** |
| 塔防 `hud.buttons` · `hud.start` | ⚠️ **永远不作数** | 走 `img()`（`scene.ts:104-108`），**那个函数根本不使用传进去的 `w` / `h`** |

⚠️ **票面 §1 那张表写着「塔防：永远作数」—— 本轮逐行核下来，那句话只对 `hud.panel` 成立。**
塔防另外两格**比横版更差**：横版至少在 WebGL 下把九宫格的声明值画对了，
而塔防那两格**任何渲染器下都不拉伸**。

## 2 · 这一轮新量到的（每条都可免费复现 —— 请重点核这几条）

### 2.1 ⭐ 更正票面 §1：塔防并不是「永远作数」，`hud.buttons` / `hud.start` 从来不打折

票面 §1 只比了 `hud.panel` 一行，而塔防的 HUD **有三个带尺寸的格子**：

```text
packages/demo/src/shell/td/scene.ts:181   this.img(b.draw, b.box.x, b.box.y, b.box.w, b.box.h, b.towerId, …)   // hud.buttons
packages/demo/src/shell/td/scene.ts:187   this.img(sb.draw, sb.box.x, sb.box.y, sb.box.w, sb.box.h, "开波", …)   // hud.start
packages/demo/src/shell/td/scene.ts:104   private img(d, x, y, w, h, …) { … return this.add.image(x, y, d.atlas!, d.frame!)… }
```

⇒ **传进去的 `w`/`h` 在真图那一支被完全丢掉**。而 `hud.panel` 走的是另一条路
（`:160-166` 手写，不用 `img()`）—— 所以「塔防永远作数」是**两格对、两格错**的概括。

### 2.2 ⭐⭐ 那条缝有一个**活着的实例**，而且**校验器判它过**

盘上那份**入库的塔防夹具**（`fixtures/td-configs/counter-siege.json`，同一份形状在
`out/counter-siege/site/v1…v14` 另有 14 份）逐字写着：

```json
"start": { "asset": "ui-btn", "at": { "x": 444, "y": 4 }, "size": { "w": 28, "h": 22 } }
```

而 `ui-btn` 在包里是 **44×22**（`counter-siege/v4` manifest · 九宫格 `{x:3,y:3,w:38,h:16}`）⇒
**28×22 是一次合法的九宫格收窄**（正因为是九宫格，`auditPanelSize` 放行）。

于是同一格上面压着**三个不同的数**：

| 谁 | 用的是哪个数 | 结果 |
| --- | --- | --- |
| `auditPanelSize`（`contracts/src/game-config.ts:365`，塔防三格共用） | 九宫格 ⇒ **放行** | 不响 |
| `auditScreenSpace`（`screen-space.ts:116` 算盒 → `:56` 判） | **声明值 28×22** ⇒ 盒子 `(444,4) 28×22`，右边界 **472 ≤ 480** | **绿** |
| 外壳画出来的（`td/scene.ts:187` → `img()`） | **包里的原生像素 44×22**，从 `(444,4)` 起画 | 右边界 **488 > 480** ⇒ **出屏 8px** |

⚠️ 而**命中区用的是声明值**（`td/scene.ts:284-291` 的 `inside(world.hud.start.box)`），
⇒ **看得见的 44px 里，只有左边 28px 点得动**。

⚠️ **这两句是读出来的**（读代码 + 读盘上 JSON），**没有跑浏览器** —— 确证那一档见 **Q3**。
⚠️ 另：`hud.buttons` 那格声明 **44×22 = 包**，所以它**看不出问题**（那是**巧合**，不是规矩）。

### 2.3 ⭐ 横版那一侧的差异**今天一处也观察不到**（盘上 16 份横版配置）

全仓扫过（`fixtures/` + `out/`，可免费复现，见 §5）：

```text
  9 game-config/v1 | hud.panel | 声明 72x32 | 包 72x32 | 九宫格 true      ← 能配到包的 9 份
  1 game-config/v1 | hud.panel | 声明 72x32 | 包 __不存在__             ← 探针里的假资产
 15 td-config/v1   | hud.panel | 声明 480x30 | 包 96x26 | 九宫格 true     ← 塔防（③ 救了它）
 15 td-config/v1   | hud.start | 声明 28x22  | 包 44x22 | 九宫格 true     ← ⚠️ §2.2 那一格
 15 td-config/v1   | hud.buttons | 声明 44x22 | 包 44x22 | 九宫格 true    ← 巧合相等
```

⇒ **横版所有真配置的 `hud.panel` 都恰好「声明 == 包」**（`hud-lost-slots` 72×32 对 72×32）
⇒ ②那条「画原生像素」的路**今天画出来的就是声明值**，**一处都看不出错**。
⚠️ 也就是说：**横版那一格的差异是潜伏的，塔防那两格是活的。**

### 2.4 ⭐ 而「横版补 `setDisplaySize`」在**能过闸的配置上可证是空操作**

`auditPanelSize`（`game-config.ts:373-374`）今天把非九宫格那一支**钉死成「声明 == 包」**：

```ts
if (asset.scale9Borders !== undefined) return null;          // 九宫格 ⇒ 声明自由
if (declared.w === asset.size.w && declared.h === asset.size.h) return null;
return { severity: "error", … };                              // 非九宫格且不等 ⇒ 硬失败
```

而站点装配会**硬失败**在它上面（`demo/src/site.ts:191` 调 `auditGameConfig` · `:213` 有 error 就不产站点）
⇒ **能进浏览器的那一份配置，非九宫格 ⇒ 声明 == 包 ⇒ 画原生像素 == 画声明值**。
⇒ ②那条路上，**只有「九宫格 + Canvas 回退 + 声明≠包」这一种情形会画错**，
而它在横版**今天 0 例**（§2.3），在塔防**被 ③ 挡住了**。

### Q1 · 横版那一格怎么处置？

| 选项 | 内容 |
| --- | --- |
| **(a)** | **两代对齐：声明值永远作数** —— 横版在 `scene.ts:215` 那一支补 `setDisplaySize(p.w, p.h)` |
| (a′) | **只补九宫格回退那一支**（`s9 && !canNine` 才补），非九宫格原样 |
| (b) | **维持现状**，把这个差异写成规格（契约注释 / 外壳注释 / 散文三处挑一处） |
| (c) | 横版非九宫格**直接判失败**（新增判据） |
| (d) | 不登记（记为已知的两代差异） |

**我的推荐：(a)。** 四条理由：

1. **(c) 与 (d) 当场出局**：(c) 与 `auditPanelSize` 今天那条**重复**（§2.4 —— 非九宫格本来就必须声明 == 包），
   而它还要**禁止一件今天完全画得对的事**；(d) 与本票**存在**这件事自相矛盾（票 63 已经把它当缝开出来了）。
2. **(a) 在能过闸的配置上是空操作**（§2.4）⇒ **不改变今天任何一份产物的一个像素**，
   风险是**零**，而它把「声明值 = 画出来的尺寸」这句话**在横版变成真的**。
3. **它挡的是链正在往那边走的那一步**：塔防那一格已经声明 **480×30 ← 96×26**（§2.3）——
   链路产出「拉宽的九宫格面板」**不是假设，是已经发生的事**；横版今天只是**还没轮到**。
4. **(a′) 更保守但更贵**：它要在同一条 `else` 里再分一次叉，而分出去的那半（非九宫格）
   按 §2.4 **永远走不到「声明≠包」** ⇒ (a′) 多出来的那半个条件**今天恒为真**，
   是一句**没有读者的判断**（R7 的门）。

⚠️ **选 (a) 要摆到明面上的一件事**（票面 §4 已经点了）：它**碰票 63 那条规矩的理由**。
⚠️ 而**执行上它其实不碰**：那条规矩的**牙齿**是 `auditPanelSize` 的 `error`，
(a) 之后**照样**拒 —— 变的只是那句话的**说理**（「外壳画不了」→「这是我们定的规矩」）。
⇒ 请顺带裁一句：**要不要把 `game-config.ts:380-384` 那段理由改一个字**（我倾向**不改**，
