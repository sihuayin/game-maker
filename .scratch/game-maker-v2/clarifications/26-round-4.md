❓ **Q1** - **调用方怎么把 N 张按顺序给进来？**（票面整个 §「怎么分工」里唯一没问过的角）

现状（量的）：

| 入口 | 今天的样子 |
|---|---|
| CLI | `--style` **恰好一张** —— **给两次就是 usage 错**（`cli.ts:88-90`），而那条报错文案自己写着「今天 `--style` 恰好收一张（多参考图见**票 26**）」 |
| MCP | 一个 `stylePath: string`（`mcp/src/server.ts:263`） |
| 契约 | `styleReferences` 是个**数组**，但 `maxItems === 1` 由**调用方**执行（R4-Q3） |

`role` 已按第 3 轮裁定拿掉 ⇒ 输入就只是**一串有序路径**。那么：

- **(a) `--style` 可重复**，顺序 = 数组顺序。MCP 那边 `stylePath: string` → `stylePaths: string[]`。
- **(b) 新旗标 `--style-ref`（可重复）**，`--style` 保持单张。⇒ 两套并存，多一个概念。
- **(c) 一份清单文件**（一个 JSON 列 N 个路径）。⇒ 多一种输入形态要维护。
- **(d) 不在本票定**，随施工票一起（因为实现已经在 `## Out of scope`）。

➡️ **推荐 (a)**：

1. `role` 拿掉之后，输入就只是一串有序路径 —— 「给两次」今天**已经被当成错误**，
   改成合法是**把一条现成的错误放宽**，不是新增概念（(b)/(c) 才是新增）。
2. MCP 那个字段跟着从 `string` 变 `string[]`，两个入口**形状一致**。
3. ⚠️ **顺带把一条今天隐式的语义变成写下来的语义**：`refs[0]` 今天是「碰巧取第一张」
   （`ops.ts:232` 复制成 `reference.png`、`create-game.ts:246` 算 style-id），
   而甲① 之后**第 1 张就是锚图**（它的像素进生图那一发）。**(a) 的「顺序 = 数组顺序」正是这条语义的载体。**

⚠️ 若你倾向 **(d)**：请说一句，我就把入口**一起划进施工票**，本票只记「**按顺序的一串路径、第 1 张是锚图**」这条语义 ——
那样本票**现在就答完了**，可以立刻进 `## Answer`。

## 草案：本票的 `## Answer`（⚠️ 请过目 · 有错就改）

> 这是按你前三轮的裁定逐条落下来的，**还没有写进票里**。你过一遍，我按你的批注定稿。

**一、多图的语义（第 1 轮）**
1. 多参考图 = **同一个游戏世界的多个来源**（(A)）。**不收**「一图定色 / 一图定角色 / 一图定环境」的分工模型 ——
   没有材料证明那些角色都有明确的消费者。

**二、融合落在哪一层（第 2 轮）**

2. N 张图**共同进入一次** `analyze-reference` 调用，产出**一份** `style`（`palette` + `styleBrief` 四项）。
   ⇒ 实现上，拦住它的**只有 `analyze-reference.ts:155` 那一个 `> 1` 的 throw** —— `imageBlocks` 本来就通吃 N 张。
3. **生图协议的参考图槽位不扩展**：生图（母版 + 每个资产）**仍只带第 1 张原图**作为 `styleReference`。
   ⇒ Gemini 的三目编号、OpenAI 的 `[styleReference, reference]`、DashScope 的预检拒、minimax 无客户端 —— **一条都不用动**。
4. **第 1 张＝锚图**：它的像素进生图那一发；下游 `ops.ts:232`（→`reference.png`）与 `create-game.ts:246`（style-id）
   取的 `[0]` **从此是规定的语义，不再是静默行为**。

**三、冲突（第 3 轮）**
5. **不判**。本项目**不规定**冲突裁决规则：生图模型每次**自行处理**两侧输入
   （融合出来的文字描述 / `palette` 与第 1 张原图的像素）之间的潜在冲突。
   ⚠️ 「模型自行处理」是对**现有行为**的描述，**不是**一条要求模型执行的判据，**也不承诺**色彩一致。
   ⚠️ **施工票不得借此**增加冲突阈值、自动拒绝、额外检测或重生成逻辑。两侧来源不同，是甲① 已接受的设计代价。

**四、契约（第 3 轮）**
6. **移除 `role`**，契约目标回归 `styleReferences: { path }[]`（**回到 R15 的字面**）。
   理由：**零读者**（融合那次调用看不到它、提示词不写它、两个调用方都硬编码 `"global"`、无判据），
   必填字段不符合 **R7** 的字段准入原则。
7. **本票不直接改契约、不改 R18 决策表**；**另开票**处理 R18 的字面变更，按 **R17** 流程执行。

**五、边界与落点（第 1 / 2 轮）**
8. **第一阶段不变**：`maxItems === 1`；多给一张由**调用方边界**拒（`CommandError("usage")` ⇒ **退出码 2**），
   vision 内部保留**兜底**检查。⚠️ 文档那三处（契约注释 · `docs/v2/01-contracts.md:119` · 票面 §4）
   **不改**（它们描述的就是将来），**代码待改** —— 这是一条**待办**，不是已落地的实现。
9. **多图实现越出本图终点**（终点入口写的是 `--style <风格参考图>`，**单数**；`maxItems === 1` 就足以跑通终点）
   ⇒ 进地图 `## Out of scope`；**不成为终点的前置阻塞**。将来实施时另开施工票，守 R18 / R17。
10. 本票**不写代码 · 不动契约 · 不动 R 表 · 不开任何付费跑 · 不动 `game-maker.local.json`**。
