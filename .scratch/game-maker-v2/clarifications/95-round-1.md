## 五 · 「为什么不对账 `anchor`」的理由是什么（供 Q2 判断）

### A · 自动链上两侧**同源**，比它是恒等

- **类型侧**：`asset-spec.ts:12` 从 `./assetpack.js` 导入 `Anchor`，`:21` 用它声明 `AssetSpec.anchor`；
  `assetpack.ts:175` 也用**同一个** `Anchor`（定义在 `:73`）声明 `AssetPackEntry.anchor`。
- **值侧**：`pack.ts:1089` 逐字 `anchor: b.spec.anchor,`（交付清单）；`:1032`
  图集侧也是 `anchor: b.spec.anchor` —— **同一个 `spec`、同一行循环**。
- **调用侧**：`pack.ts:1170` 拿的是**同一次构建**刚写下的 manifest；`qa/src/visual.ts:119` 拿的是
  **同一次运行**的 recipe 与 pack（票 92 读数 H 量过）。
⇒ 在两条生产路径上，「`spec.anchor` vs `entry.anchor`」＝**把一个字段与它自己比**。
票 92 的人裁逐字：「**恒等就不该有对账**，但仅限于没有独立信息增量的字段比较」。

### B · `layers` 是同一把尺子（票 97）

`pack.ts:1095` 逐字 `...(b.spec.kind === "background" && b.spec.layers ? { layers: b.spec.layers.map(toPackLayer) } : {})`；
`toPackLayer`（`:151-153`）只搬 `name` / `parallax` / `tileable`、剥掉 `description` ——
而 audit 恰恰不比 `description`。⇒ 三个被比字段全是逐字节搬运，票 97 因此裁定**撤**。

### C · ⚠️ 但「同源」只对**自动链**成立

R9 / R10 允许人改清单（`runBuild` 文件头逐字：「只吃 `runDir` …… **R10「人可改」要的就是这个**」）⇒
**手工路**上两侧**可以**不同源，那正是这条判据原本唯一长牙的地方。票 92 的裁定是：
**那条路也不留这条恒等对账**。⇒ 若要把理由写进代码，措辞得说清是「**两条生产路径上两侧同源**」，
不能写成一句无条件的「两侧永远同源」—— 否则新注自己又是一句与事实有缝的话。

### D · 票 97 留下的一条边界

票 97 §三 逐字：「**不在 `:70` 与票 95 的文件头各写一份理由（理由只写一处）**」。
票 97 施工时**没有**在 `:70` 写任何「为什么撤」的理由（` :70-72` 只讲「为什么要豁免下面那条」）⇒
**「一处」今天还空着**。若 Q2 选「写」，**这一处**就是自然的落点（且**不要再往 `:70` 补一份**）。

## 六 · 本轮要裁的两格

### ❓ Q1 · 清单改成哪几个词？

- **(a) `kind` / `size` / `animations`** —— 把 `anchor` 换成 `kind`，**不补 `layers`**（97 已撤）。
- **(b) `kind` / `size` / `animations`，另加一句「并检查非 animation 不该有多帧」** ——
  把第 5 条派生规则也点名。
- **(c) 只删 `anchor`，不补任何词**（保留 `size` / `animations`）—— 改动最小，但「做了没点名」的 `kind` 原样留着。
- **(d) 别的写法**（请直接给逐字文本）。

➡️ **推荐 (a)**。三条理由：

1. 那句清单的语法列的是 **`AssetSpec` 的字段**；`kind` / `size` / `animations` 三个都真被读，
   `anchor` / `layers` 两个都真不被读 ⇒ **名与实一一对上**，且不引入新的派生规则。
2. 它同时兑现票面 §4 的验收：**`grep` 出「文件头点名的每一项都真的被读了」**。
3. (b) 会把一条**派生规则**塞进「字段清单」的句法里，(c) 则留着**已知的「做了没点名」**——两者都比 (a) 多留一点缝。

### ❓ Q2 · 要不要把「为什么不对账 `anchor`」写进文件头？

- **(a) 不写** —— 只改清单。理由留在票 92 / 97 里；票 91 的先例是「只改那一处错误陈述，不扩大为整段重写」。
- **(b) 写一句，只讲 `anchor`** —— 例如：「`anchor` 在两条生产路径上由 `spec` 逐字节搬到清单，比它是恒等，故不在这里对账。」
- **(c) 写一句，同时讲 `anchor` 与 `layers`** —— 两者是同一把尺子（票 92 / 97），一句话把两处都收住；
  落点在本文件头，` :70` 不再补理由（票 97 §三 的「理由只写一处」）。
- **(d) 别的写法**（请直接给逐字文本）。

➡️ **推荐 (a)**。理由：

1. 票 95 的边界逐字是「**只改这一段文件头**」；Q2 的目的是让文件头**与函数体一致**，
   “没有列 `anchor`”本身已经是「不承诺」，不需要再补一句解释。
2. 若写，措辞必须带上「**两条生产路径上**同源」这个限定（读数 C）—— 一句短注很容易写成无条件的
   「两侧永远同源」，那会**新增一句需要维护的真话**，与本票「让注释别再撒谎」的方向相反。
3. ⚠️ 但 (c) 有一个真实的好处：票 97 的「理由只写一处」今天还空着，而**将来读代码的人**可能把
   `anchor` / `layers` 当成漏掉的判据再补回来。你若更看重这一层，选 (c) 是站得住的。
