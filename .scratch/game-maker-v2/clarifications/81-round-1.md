| 立场 | 谁 | 判成什么 |

- ⇒ **凡是能让那条警告响的配置，都先被 config 的硬失败拦下了。**

⚠️ 这条更正**不改判决方向**（三处差异照样成立），但它改了**差异的性质**：
不是「一件事两种判法」，而是「**一条没人执行、也无从执行的警告**」。

### 2.6 ⭐ 那只负盒子是怎么来的（把票 82 钉进来 —— 这是本票的**唯一**真实现场）

追到了根上，链条是完整的：

| 环节 | 读数 |
| --- | --- |
| ① 骨架教模型写的正是那组数 | `ops.ts:636` `panel: { at: { x: 8, y: 262 }, size: { w: 72, h: 32 } }` —— **与现场一字不差** |
| ② 提示词逐字教「HUD 面板是**左下角**」 | `packages/assets/src/prompt.ts:826-827` |
| ③ 而那一跑生成的包，面板资源锚点是 **`{0.5,0.5}`** | `raw/run-out-2026-10-13e/ruined-city-scavenger/pack/v1/manifest.json` 的 `hud-bar-backdrop`（32×16，`{x:.5,y:.5}`） |
| ④ 于是盒子从 `at` **往左长了一半** | `at=(8,262)`、锚点 `{0.5,0.5}`、72×32 ⇒ 盒子 `(round(8−36), round(262−16)) = (−28, 246)` ✅ **与现场逐字吻合** |

⇒ ⭐ **负盒子在这一例里不是「模型写歪了」，是「提示词说的锚点约定」与「包声明的锚点」不一致。**
⇒ ⚠️ 也就是说：**只要锚点不是零，负盒子就随时可能出现**，而**锚点这笔账归票 82**，
本票**只引它、不代它裁决**（人裁原话）。

### 2.7 ⭐ 而 `allowPokeOut` 豁免的那条检查，**今天恒真**（不只是「没判据」）

砖盒子按构造**必然**落在世界里，三条既有判据合起来把它夹死：

- `td/world.ts:156-171`：砖按「**格心** + 锚点」摆 ⇒ `at = (ci·cell + ⌊cell/2⌋, ri·cell + ⌊cell/2⌋)`；
- `td-config.ts:412`：砖尺寸**必须等于** `arena.cell`（硬失败）；
- `td-config.ts:416`：砖锚点**必须是 `{0.5,0.5}`**（硬失败）；
- `td-config.ts:470`：`cols·cell == W` 且 `rows·cell == H`（硬失败）。

⇒ 每块砖的盒子**恒等于**一个格 `(ci·cell, ri·cell, cell, cell)` ⊂ 世界。
**⇒ `:46` 那个 `true` 今天既没在守、也没在放**（与 2.1 的探针互为印证）。

### 2.8 ⚠️ 负数今天在塔防**只对 `slot` / `core` 有可能**（`hud` 那一格结构上不可能）

读了夹具那一份包的全部 21 件资源：

| 类别 | 锚点 |
| --- | --- |
| 砖 / 插槽 / 机关 / 敌人 / 特效 / 弹丸 / 柜台（17 件） | 全部 `{0.5, 0.5}` |
| 四件 `ui`（`ui-hud-bar` / `ui-btn` / `ui-icon-*`） | 全部 `{0, 0}` |

而盒子公式是 `box.x = round(at.x − anchor.x · w)`，`at` 由 schema 保证**非负**
（`game-config.ts:32` `nonnegative`，塔防直接复用：`td-config.ts:36` `TdPoint = Point`）。

⇒ 锚点 `{0,0}` 时 `box.x == at.x ≥ 0` ⇒ **负数结构上不可能**（塔防 HUD 正好是这一档，
且夹具把它摆在 `at = {0,0}`）；锚点 `{0.5,0.5}` 时 `at.x < w/2` 就会出现负数
⇒ 塔防那三处四边判据里，**负数那一半今天只对 `slot` / `core` 是活的**。
⚠️ 而横版相反：HUD 约定锚点 `{0,1}` 或包里给的 `{0.5,0.5}` ⇒ 那一头**很容易**出现负数（2.6 就是）。
