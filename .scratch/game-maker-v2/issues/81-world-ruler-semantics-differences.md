## Question

**同一条规矩（「盒子得在世界里」）今天有五处各自内联的实现 —— 而它们对「负数」的判决三种都不一样。**

人裁点名要记的是**三处**（横版配置 / 塔防配置 / 塔防装配）。⚠️ 而**「几份」这个数取决于你怎么数**，

| 数法 | 数目 | 是哪几处 |

而 `pokeOut` 与两份路径点尺**各有各的理由**（见各自那段注释）—— 本票不预设它们该合。

### ⚠️ 一条把「负坐标」讲清楚的事实：**负坐标进不了 schema，只能从锚点来**

- 两个 schema 的坐标都**非负**：`game-config.ts:32` `export const Coord = z.number().int().nonnegative();`
  （`Point` `:33` / `Rect` `:42` 都从它来），而塔防直接复用 —— `td-config.ts:36` `export const TdPoint = Point;`
  ⇒ **`at` 不可能是负的**，`parseGameConfig` / `parseTdConfig` 当场拒。
- 负的 **盒子**只能从**锚点**长出来：`game-config.ts:110` 一带
  `x: Math.round(at.x - anchor.x * size.w)`。例：锚点 `{x:.5,y:.5}`、`at.x = 8`、宽 72 ⇒ `box.x = -28`。
  ⚠️ **那正是票 62 现场的那只盒子**（第十二跑）。

⇒ ⭐ **所以「横版配置不查负数」这条缝，不可能靠 `at` 复现** ——
它只在**锚点不是左下角**的包上出现（横版 HUD 的约定锚点是 `{x:0,y:1}`，而塔防夹具里是 `{x:0,y:0}`）。

### ⚠️ 另外两条今天量到的（都影响这一票的裁决）

1. **塔防那两处尺子，一条判据都没有看着**：`grep -rn "世界之外" packages/*/tests`
   只命中横版（`game-config.test.ts` / `reachability.test.ts` / `qa/tests/gameplay.test.ts`），
   而 `探出了世界的左边` 只命中 `demo/tests/site.test.ts:150`（**横版**）。
   ⇒ ⭐ **若只改塔防某一处，全仓没有一条测试会红或绿** ——
   「改完了看不出来」这件事本身就是本票要面对的。
2. **「有意探出去」有三种说法，各不相同**：
   - 横版 `pokeOut`：**报警告**，让**读的人**自己判（报文逐字「若这是有意的（从画面外伸进来的东西）忽略本条」）；
   - 塔防装配：**同一句话**（`:44` 「若这是有意的，忽略本条」）；
   - 塔防 `arena.tiles`：**调用方传一个 `allowPokeOut = true`**（`:46`）把那条**整个跳过** ——
     ⚠️ 这不是「同一条规矩的三种严重度」，是**三种不同的机制**（读的人判 / 读的人判 / 写的人预先声明）。
     ⇒ 本票要裁「统一」时，必须说清统一的是**哪一种**。

## 2 · 要裁决的（留给下一轮 grill，此处只列边界）

1. **「世界尺」的定义是什么**（§1 第二张表那三种数法）—— ⚠️ 不先把口径钉死，
   「应有几份」这一问**没有答案**。
2. **该合成一份吗？** 两份实现（`game-config.ts:423` / `td-config.ts:445`）**逐字同名、报文逐字相同**，
   而它们**已经漂了**（近端那一条）。⚠️ 反方向也有理由：合掉意味着横版要接受「查负数」，
   而**横版今天查负数会改变既有判决**（见 §3 的开放问题）。
3. **负坐标到底该怎么判**（人裁点名的那一句）—— 三种在下：
   - **横版配置：不查** ⇒ 靠视口尺（`screen-space.ts:56`，`error`）兜，**而只有 HUD 有视口尺**
     （`terrain` / `entity` / `player.at` **没有**）⇒ ⚠️ **世界空间里的负盒子今天没人管**（只在装配期 `pokeOut` 报个警告）。
   - **塔防配置：硬失败** ⇒ 四个边一个不放过。
   - **塔防装配：警告** ⇒ 与配置**同一件事两种判决**（⚠️ 这是三处里**最刺眼**的一处：
     同一个盒子在 config 是 `error`、到了装配期变成 `warning`）。
4. **要不要给塔防那两处补判据**（§1 末「一条判据都没有看着」）—— ⚠️ 与本票的「统一」是**两件事**，
   可以分开裁（「先统一语义、后补闸」或反之）。
5. **`allowPokeOut` 那个机制留不留** —— 它今天只用在 `arena.tiles` 一处，
   而「场地铺满世界」本来就由 `:31-36` 那两条判据盯着（⚠️ 两条同时成立时它是不是冗余的，**要当场核**）。
