## 1 · 现场

文件头逐字（`:36-44`）：

```
/**
 * **spec ↔ 产物对账**：`AssetSpec` 说要做成什么样，包里实际做出的是什么。
 *
 * 这是「需求 vs 产物」**唯一**的对账点。没有它，`AssetSpec` 里的
 * `size` / `animations` / `anchor` 就只是写给自己看的注释。
 *
 * @param drawlists 可选：给了就顺带核对每份 drawlist 的 `viewBox` 与声明的尺寸。
 *                  不一致时锚点的分母就错了，而错误会**静默**传递到装配。
 */
```

⚠️ **两头都错**（[票 92 的读数 A–D](../clarifications/92-round-1.md)）：

| 文件头说的 | 函数体实际做的 | 对不对得上 |
| --- | --- | --- |
| 点名 `anchor` | ❌ **一次都没读**（`grep -n anchor packages/contracts/src/audit.ts` ⇒ 只有 `:40` 那句注释本身） | ⚠️ **点名了没做的** |
| 未提 `layers` | ✅ `:72-84` 查层数 / 名字 / 视差 / 平铺 | ⚠️ **做了没点名的** |
| 未提 `kind` | ✅ `:49` | ⚠️ 同上 |

函数体**今天真查的五样**：`kind`（`:49`）· `size`（`:51`）·
动画名与帧数（`:56-68`）＋「非 animation 不该有多帧」（`:86`）· `layers`（`:72-84`）·

## 2 · 要裁的两格（本票**只作裁定**）

1. **清单改成哪几个词**？（`kind` / `size` / `animations` / `layers` —— 还是别的写法？）
2. ⚠️ **要不要把「为什么不对账 `anchor`」也写进去**？
   - 写：读代码的人当场知道那是**有意为之**（`anchor` 是恒等，见票 92 读数 A），
     而不是又一次「说一套做一套」。

   —— `drawlist.viewBox` 与 `size` 不一致时，锚点换算到像素的分母确实错了。
   ⚠️ 但它是**全文件唯一一处出现「锚点」二字而确实成立的地方**，改清单时**容易被顺手删掉** ⇒ 提醒一句。
