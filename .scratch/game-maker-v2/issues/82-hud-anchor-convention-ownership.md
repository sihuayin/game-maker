## 2 · ⚠️ 而盘上的锚点**不止一种**（今天逐包算出来的读数）

`anchorHint`（`ops.ts:658-662`）会把每个锚点翻成一句话，而它**按 `kind` 去重后印进清单**
（`ops.ts:835-836`，`[...new Set(assets.map((a) => \`${a.kind}：${anchorHint(a.anchor)}\`))]`）。
今天对两份入库包跑这段逻辑，得到的是：

```text
fixtures/packs/last-train/v2/manifest.json     ← 横版
    animation：{0.5,0.95}（归一化）     ← 脚
    animation：底边中心
    background：左上角
    sprite：底边中心
    ui：左下角                          ← ✅ 合约定（hud-lost-slots {0,1}）
    ui：左上角                          ← ⚠️ **同一个包里，ui 这一行还有第二条**

fixtures/packs/counter-siege/v4/manifest.json  ← 塔防
    sprite：{0.5,0.5}（归一化）
    animation：{0.5,0.5}（归一化）
    ui：左上角                          ← ⚠️ **只有这一条，与①③「左下角」相反**
```

逐行的现场（`manifest.json` 里读出来的）：

| 资源 | 包 | 锚点 | `anchorHint` 会印成 | 合约定吗 |
| --- | --- | --- | --- | --- |
| `hud-lost-slots` | last-train/v2 | `{x:0, y:1}` | 左下角 | ✅ |
| `hud-pip` | last-train/v2 | `{x:0, y:0}` | 左上角 | ⚠️ **同一个包、同一个 `kind=ui`** |
| `ui-hud-bar` / `ui-btn` / `ui-icon-scrap` / `ui-icon-life` | counter-siege/v4 | `{x:0, y:0}` | 左上角 | ⚠️ **整个塔防包都是左上角** |
| `hud-bar-backdrop` | **真跑产出**的包（票 63 记的） | **中心 `{x:.5,y:.5}`** | 归一化 | ⚠️ 第三种 |

⇒ ⭐ **一句「HUD 面板是左下角」对着三个不同的现实**：
横版面板 ✅ / 横版 pip ❌ / 塔防全部 ❌ / 真跑产出的面板 ❌。
⚠️ 而 `ops.ts:835-836` 那句去重是**按 `kind`** 去重的 ⇒
**它会把两条互相矛盾的话同时摆在模型面前**（上面那段 `ui：左下角` + `ui：左上角`）——
「示例错了，模型就会错」（票 40）那条规矩在这里**不是假设，是今天的读数**。

### ⚠️ 一条把本票与[票 81](81-world-ruler-semantics-differences.md) **咬合**的事实

锚点**直接决定负盒子出不出现**：`game-config.ts:110` 一带 `x = Math.round(at.x - anchor.x * size.w)`
⇒ 若把塔防的 ui 锚点统一成 `{x:0,y:1}`（左下角）而**塔防骨架那份 `at` 不动**
（`ops.ts:1039` 逐字 `panel: { asset: "…", at: { x: 0, y: 0 }, size: { w: 480, h: 30 } }`），
则 `box.y = 0 − 30 = −30 < 0` ⇒ **`td-config.ts:446` 那条硬失败（它查负数）当场点火**。

⇒ ⭐ **「锚点约定归谁管」与「世界尺要不要查负数」是耦合的两问** ——
⚠️ 但人裁把它们切成了两张票，**本票只引票 81 的那一条，不代它裁决**。

## 3 · 要裁决的（留给下一轮 grill，此处只列边界）

1. **归注释还是配方层？** 票 62 点名的那一问，至少有三种答法（⚠️ 本票**不预先指定**）：
   - **(a) 留在散文**：明确它**只是约定、不是闸**（像票 58 给层名那条补的「这一条不是防线」的写法）；
   - **(b) 提到配方层**：在 `AssetSpecSchema` / 清单里把它写成一条可校验的形状
     （例如 `kind === "ui"` 的某几类必须 `anchor = {x:0,y:1}`）；
   - **(c) 只提升一半**：只在**提示词/骨架**那一侧说清（模型可见的那一份），契约不判。
2. **若提到配方层，盘上那三份包怎么办？** ⚠️ 这是最硬的一格：
   塔防包四个 ui 全是 `{0,0}`、横版的 `hud-pip` 也是 `{0,0}` —— **它们今天是绿的**。
   判据化意味着**当场改既有包**（或把约定写成「按玩法分」）。**本票不预先决定走哪条。**
3. **两个玩法的约定是不是同一件事？** 横版提示词写「左下角」（`prompt.ts:826-827`），
   而塔防骨架写 `at {x:0,y:0}` 且塔防包全是左上角 ⇒
   「**HUD 面板**」这四个字在两个玩法里**指的是两种摆法**。
   ⚠️ 这一问与票 81 的「三份世界尺要不要统一」**形式同构**，但**对象不同**（那边是尺子，这边是锚点）。
4. **`anchorHint` 那句去重要不要动？** 它今天把两条矛盾的 `ui：…` 一起印给模型（§2 的读数）——
   ⚠️ 改它是**改提示词**，属另一次授权。
5. **与票 63 的接缝**：票 63 裁的是**尺寸**（Q1 = (b)「不要求无条件一致」，理由见
   `63-hud-panel-size-not-reconciled.md:124`），且它只把锚点当成**相邻事实**记了一笔
   （`:85` 那句「真实 32×16、锚点**中心**」）⇒ ⚠️ **本票不许重开尺寸那一问**（人裁原话「不合并施工」）。
