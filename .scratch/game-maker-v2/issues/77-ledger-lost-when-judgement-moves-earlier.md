## Question

**「哪些调用已经花掉了」这件事，在失败现场上可能看不见。**

现场（第十二跑 `raw/run-out-2026-10-13e/`，盘上现成 · 本 session 读出来的）：

```text
run-out-2026-10-13e/…/run/v1/ledger.json      5 发 · {analyze-reference 1, analyze-intent 1,
                                                        compile-design 1, character-dna 1, plan-assets 1}
run-out-2026-10-13e/…/pack/v1/ledger.json    30 发 · {master 2, image 12, drawlist 16}
run-2026-10-13e.json 里那枚异常上的 ledger     1 发 · 只有 {compile-runtime}
```

⇒ ⭐ **那一跑买了 14 张图（`image 12` + `master 2`），而人眼前那笔「已经花掉的」账上只有一发文本。**
它没丢 —— 它在 `pack/v1/ledger.json` 里 —— 但它**没进异常、也没进 run 级账**。

⚠️ **根因读得出来**（`packages/pipeline/src/create-game.ts`，逐行核过）：

```text
runBuild          :399  const ledger: LedgerCall[] = [];        ← 这一跑自己累的
                  :493  const union = [...prior, ...ledger];    ← 链级并集（Q14）：段 A 那几发 ∪ 这一段的
                  :494  writeRunLedger(…, union, …);            ← ⚠️ **只在末尾**，且**成功路径才走到**

失败那一刻          :929  throw new CommandError("invalid", …, ledgerCarrying(call.record()));
ops.ts:589          ledgerCarrying = (r) => r === null ? {} : { ledger: [r] }   ← ⚠️ **只带一发**
```

⇒ ⭐ **一句能记住的话**：**判据每前移一步，它前移到的那个位置就越可能在「账还没落盘」的那一段里死。**
票 65 把层盖不住这件事从**站点装配期**提前到 `config` —— 于是它**从「账已落盘」的那一段，
挪进了「账还没落盘」的那一段**。

⚠️ **这不是票 65 的错、也不是票 48 没做** —— 两件事各自都对，**是它们叠起来的那一格没人管**：
票 48 那条纪律治的是「按**类**读、不按类读」（`carryOnError` / `failureDirOfError` / `ledgerOfError` 都照它写）；
它**治不了「累积没挂上去」**这一格 —— 因为挂上去的那个东西**本来就只有一发**。

## 已经量到的（别重新量）

- **段 B（`runBuild`）**：`create-game.ts:372-505`。账在 `:399` 起累，`:492-494` 才落盘；
  **这一段没有 `catch`** ⇒ 抛出去时 `union`（= 段 A 那几发 + 这一段已经花掉的）**一发都没写**。
- **段 A（`createGame`）另一处、病不一样**：`:333-360` **有** `catch`，但那个 `catch` 只挂
  `failureDir`（`:358` `carryOnError(e, { failureDir: site })`）与两处 `attempts`（票 55 / 票 60 的现场），
  **不挂账** —— 它靠的是「**成功时才在 `:314` 写 run 级账**」。
  ⇒ ⭐ **两条路都不在失败时保账**，只是**病在不同处**：段 B 连 `catch` 都没有，段 A 有 `catch` 但那个 `catch` 不管账。
- **包自己那份账是安全的**：`pack/v1/ledger.json` 是**包的收据**（跟包走、被 `verify` 校验），
  它与 run 级账**口径不同**（`create-game.ts:490-491` 的注释逐字记着这一条）。
  ⇒ 所以问题**不是「账丢了」**，是「**账没汇到人眼前那一份里**」。
- **人眼前那一份是壳渲染的**：`packages/cli/src/cli.ts:598-602`
  （`ledgerOfError(e)` 取账、`failureDirOfError(e)` 取现场）—— 它**只印异常上挂着的东西**。
- **错误在失败现场里是「把已花的钱说小」的那一侧**：
  `formatSpentCalls` 渲染的是**异常上那一发**，而真相是**盘中 35 发（含 14 张图）**。
  ⇒ ⚠️ 这是一处**会让人在事后误判成本**的形状，不只是「不好看」。

## 要裁决的（留给下一轮 grill，此处只列边界）

   ⇒ 第一问是**这一条要不要成立**（也可能裁成「不必保：包里那份账已经是真相」）。

     的**形状**，而它今天在 `ops.ts` 里有 **8 个调用点**；
   - **(b) 失败时也写一份 run 级账**（给 `runBuild` 加 `catch`，照段 A `:333-360` 那套 `abandonRun` + `carryOnError` 的形状）——
     ⚠️ 要动的是**流水线**，正是人裁说「**不借机重构**」指的那一块；
   - **(c) 不改代码，只改「人眼前那一份」的渲染**（壳把 `failureDir` 里的 `pack/v1/ledger.json` 也读出来并印）——
     ⚠️ 这一条**最便宜**，但它把负担放在**壳**上，且要回答「现场目录里哪些账该读」。
3. **与票 48 的分工**：票 48 治「按类读」，本票治「累积没挂上去」 ——
   ⚠️ **两票落在同一处代码附近**（`carryOnError` / `ledgerCarrying`）⇒ 边界要在这一轮说清，
   免得后一张把前一张的成果收窄。

**2 · ⚠️ 一条被升成验收条件的读数（Q2 逐字）**：

⚠️ 它也顺带回答了材料 §3 Q2 那句「**请连『用哪个动词挂』一起裁**」：
人裁**没有指定动词**，而是把它**押给了施工票**，并明说「**调用 `carryOnError` 本身不算完成**」。
