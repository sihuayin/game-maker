## Question

Q19 的裁决是两半：

- **契约层进**：`styleReferences: { path, role }[]` —— 理由是「一图一角色」是个合理方向
  （`image A: palette` · `image B: character` · `image C: environment`），
  而且 `01-contracts.md` §2 与 `00-overview.md` §1（"Style Reference Image**(s)**"）本来就是复数。
- **第一阶段 `maxItems === 1`**：N 张图的**权重融合、冲突解决、谁说了算**，
  **没有任何实测**。不许在这一阶段实现。

这一票要答的就是被推迟的那件事。

### 1. `role` 是一个**封闭枚举**还是一段自由文本

Q19 给的例子是 `global` / `character` / `environment` / `palette`。
- 若是**封闭枚举**：每个 role 必须有**明确的优先级**（两张图都说自己是 palette 怎么办？）。
- 若是自由文本：那它**进不了任何判据**（R3），只能当提示词素材。

⚠️ 按 **R7 的门**：说不出「谁读它」的 role 不进契约。

### 2. 参考图与 `VisualWorldSpec` 的关系

今天（R15）：原图**只存引用**（路径），二进制不进 JSON。
多图之后要答：那张图**各自**参与生图调用吗？
⚠️ 生图那条路的既有实况（别重新量）：Gemini 把 `[styleReference, reference]` 按序内联、
prompt 里注明「附件第 N 张」（`image-gen.ts:299-312`）；OpenAI 有输入图时走 `/images/edits`
（`:460,469-474`）；**DashScope 接不了本地文件**（需公网 URL），**minimax 没有客户端**。
⇒ 多图会让「这个协议撑不撑得住」变成一个**每协议各不相同**的问题。

### 3. 冲突怎么判、要不要判

两张图互相打架时（一张冷调、一张暖调）：
- **(a) 不判**：全喂给生图模型，让它自己合 —— ⚠️ 那就是**不可复现**。
- **(b) 判**：按 role 定优先级 —— 那 `role` 必须是封闭枚举（见 §1）。
- **(c) 拒绝**：检测到冲突就**当场拒绝**（判据）。

⚠️ (a) 与 R6「换色板 → 创作态一字不变」那条**可复现**的性质直接冲突。

### 4. 第一阶段不许做的事（写在这里免得被顺手做掉）

**不许**做：权重融合 · 图与图之间的相似度 · 「哪张图更权威」的自动裁决。
第一阶段 `maxItems === 1`，多给了一张**就拒绝**（退出码 2），并**明说**这条限制。
