## Question

**链上两处提示词各自教出一个合法形状，而合起来不成立。**

```
段 A  packages/assets/src/prompt.ts:494-497   （recipeShapeSpec()，第 491 行起）
      background → "layers":[{"name":"sky","parallax":0.3},
                             {"name":"ground","parallax":1,"tileable":{"x":true,"y":false}}]
                    ← 不平铺的层**别写 tileable**（三层里通常只有墙与地平铺，**天空不平铺**）
      ⇒ ⭐ 样板自己就是「**不平铺 + parallax 非零**」（sky parallax 0.3）

段 B  packages/assets/src/ops.ts:808-809 规则 4 · :816-817 规则 8 · :618 骨架
      规则 4：「world.size.h 必须等于视口高 …，`world.size.w` **自己定**（横向滚多远）」
      规则 8：「⚠️ hud 的坐标是屏幕空间（≤ 480×270），不是世界空间。
              **世界可以宽 1440**，但屏幕只有 480 宽 —— HUD 写到 x > 408 就跑出屏幕了，直接拒。」
      骨架  :618  world: { size: { w: 1440, h: 270 } }
      ⇒ ⭐ 整段提示词在**往宽世界压**（骨架就是 1440，规则 8 又说「可以宽 1440」）

判据  packages/contracts/src/layer-coverage.ts:94-109（票 65 落地）
      auditLayerCoverage —— 报文末句逐字：「**不平铺的层只有 parallax = 0 才恒成立**」
```

⇒ **三样合起来**：凡是「不平铺且 `parallax > 0`」的层，**配**任何比视口宽的世界 ⇒ **必被拒**。

⚠️ **这不是纸上谈兵，也不是罕见形状** —— 本 session 全仓扫过一遍（去重后**带层的背景资源只有 3 处**）：


### 二 · Q1 的具体裁定（**逐字**）

> 修段 A 时，必须同时修正样板的表达规则：
>
> - 不平铺的层： 视差必须为 `0`。
> - 需要正视差的层： 必须设置适当的 `tileable`，或将资源绘制得足够宽，以保证整个滚动范围内的覆盖。
>
> 不能只把 `sky.parallax` 从 `0.3` 改为 `0`，却留下「天空不平铺」的宽泛示范。否则，中间层仍可能生成 `parallax: 0.4` 且不平铺的错误形状。
>
> 这里裁定的是应修正的规则与方向，不是预先指定最终实现方式，也不授权本轮修改提示词。
