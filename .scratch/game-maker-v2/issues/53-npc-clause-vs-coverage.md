## 2 · 量到的（第八次真跑 · 段 A）

现场：`raw/run-out-2026-10-13a/.failed-2026-10-13T02-21-58-177Z/`。

**意图层 7/7 跑都把主角登记成了一条 npc：**

```text
intent.entities[0] = { id:"scavenger", type:"npc", role:"玩家控制的拾荒者" }
```

**于是设计层有两条规矩同时生效、方向相反、而且两条都由判据强制执行：**

| 出处 | 话 | 执行者 |
|---|---|---|
| 第 **3** 条（`prompts.ts:132-135`） | 意图里已经有的 id「**原样沿用**：不许改、**不许删**、不许换桶」 | `auditIntentCoverage`（R12 拒绝） |
| 第 **4** 条 + `npcs` 台账（`prompts.ts:145-146` / `:159-161`）—— **票 42 新加的那一句** | 「**也**不许把玩家**复制**进任何一个桶 … **别在 `npcs[]` 里再写一条「玩家本人」**」 | 票 42 的 gate ⑤ |

⇒ 模型只有两条路：

- 照**第 3 条** ⇒ `scavenger` 留在 `npcs[]` ⇒ **`player.id` 必须换成另一个** ← **正解**
- 照**第 4 条** ⇒ 把 `scavenger` 从 `npcs[]` 删掉 ⇒ **第 3 条当场拒** ← **模型选了这条，然后死了**

拒因（`intent-entity-missing`）· 退出码 **4** · 墙钟 53.5s · **0 张图** · 文本 3 发。

**归因的把握**：`git log -S` ⇒ 那句是**票 42 那一笔**（`2cae283`）加进去的；
**改动前 6/6 份真实设计的 `npcs[]` 里都有玩家，改动后第一跑就没了**（n=1）。
⇒ **强相关，不是铁证** —— 但方向只有这一个。

⚠️ **票 42 自己的提交信息里已经写出了这团雾**（「意图层把主角登记成一条 `npc` 对不对 …
本票之后模型**必须**给玩家起**另一个** id，而 `npcs[]` 里那条在语义上**就是玩家本人**」）——
**它看见了这团雾，却没让新提示词回答它。**

⚠️ **夹缝有解，而且距离恰好一个 token**：把第七跑那份真实设计**只改一个字符串**
（`player.id`: `"scavenger"` → `"player"`，`npcs` 保持 `["scavenger"]`）重放 ⇒
`schema ⑤/⑥` **PASSES** · `auditIntentCoverage` **空** · `levels[].entities` **仍全部解析得到**。

## 3 · 要定的（人已裁：只改散文）
