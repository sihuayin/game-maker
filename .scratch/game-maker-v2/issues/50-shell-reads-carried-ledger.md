## Question

**票 48 让两个壳改「按能力读」了（`ledgerOfError` / `failureDirOfError`），而改完之后没有任何东西看着它们。**

今天三处读者的见证情况：

| 读者 | 位置 | 今天谁看着它 |
|---|---|---|
| CLI 文本 + `--json` | `cli.ts:598 / 602 / 609` | `cli.test.ts` 的两条 —— ⚠️ 但都走 `withDeadUpstream`（**死端口**）⇒ 撞的是**上游**那条路，`CommandError` 带着的那一份，**不是**「挂在裸 `Error` 上」那一份 |
| MCP 文本 + `structuredContent` | `server.ts:333 / 337 / 345` | `server.test.ts` **只覆盖 `usage`/2 一档**（参数错）⇒ **携带这条路一条测试都没有** |

⇒ 于是票 48 那五条手工量到的东西（裸 `Error` · 退出码 1 · 账 · 栈 · 现场指针），
**只有 `packAssets` 那一层被钉住了**；「**两个壳各自真的把它印出来了**」这条主张**没有见证**。
谁把 `cli.ts:598` 那行改回 `e instanceof CommandError`，**不会有任何东西变红**。

### 这一票要做的

⚠️ 它是 **task**（不是 grilling）：**没有要裁的设计问题**，只有一件必须做完才能让后续决定有依据的事 ——
**把「两个壳读出携带信息」变成可复跑的见证**。

1. **壳级端到端测试**：CLI 与 MCP 各一条，喂一个**判断失败**（不是上游失败），断言两端都读得出
   **账**与**失败现场指针**（CLI 文本 + `--json`；MCP `content` + `structuredContent`）。
2. **由此必须解决的那件工程问题**：CLI 既有夹具只喂得起**死端口**，而要撞上判断失败需要一个
   **活着并吐出一张（全透明的）图**的上游 ⇒ 要么在测试里起一个**本地 HTTP stub**，
   要么找到一个**不经过生图**就能撞上判断失败的点。
   ⚠️ **先量再选**：`pack` 段那 11 处抛点里，哪几处**不花钱也能撞到**（那几条不需要 stub）。
3. **顺带量清楚**：`compileRuntime`（`ops.ts:707 / 722`）那几个同形的 catch 是不是也该有壳级见证 ——
   **量出来再说**，不在本票预设结论。
