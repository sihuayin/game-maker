## 1 · 立案现场

**骨架**（`packages/assets/src/ops.ts:1078-1089`，`tdConfigExample.hud`）逐字：

```ts
  hud: {
    panel: { asset: "<顶栏的 id>", at: { x: 0, y: 0 }, size: { w: 480, h: 30 } },
    readout: { at: { x: 22, y: 5 }, step: { x: 0, y: 10 } },
    icons: {
      scrap: { asset: "<废料图标的 id>", at: { x: 8, y: 6 } },
      life: { asset: "<声望图标的 id>", at: { x: 8, y: 16 } },
    },
    buttons: { asset: "<按钮底板的 id>", at: { x: 300, y: 4 }, size: { w: 44, h: 22 }, step: { x: 48, y: 0 } },
    start: { asset: "<按钮底板的 id>", at: { x: 444, y: 4 }, size: { w: 28, h: 22 } },
  },
```

**而这一包里它们是**（本 session 只读核对，`fixtures/packs/counter-siege/v4`）：

| 骨架那一格 | 骨架写的 | 包里那件资源 |
| --- | --- | --- |
| `panel.size` | **480×30** | `ui-hud-bar` **96×26** · 锚点 `{0,0}` · **九宫格** |
| `buttons.size` | **44×22** | `ui-btn` **44×22** · 锚点 `{0,0}` · 九宫格 |
| `start.size` | **28×22** | 还是 `ui-btn`（**44×22**）· 九宫格 |

⇒ **骨架是照 `counter-siege` 那一包写的**（`buttons` 那格甚至**恰好相等** —— 票 72 量过那是**巧合**，不是规矩）。

**同一份提示词里没有任何一条规则说 `hud.*.size` 该怎么写。**
`tdConfigPrompt`（`packages/assets/src/prompt.ts:586-640`）的**铁律 1–11 一条也没提 `hud`** ——
第 1 条只列了 `hud` 这个键名，第 11 条只说「只许用清单里的 id 与动画名」。
⇒ **塔防这一份的 `hud` 尺寸，唯一的信息来源就是这份骨架 + 清单每行的「九宫格 / 非九宫格」半句。**

**而它教出来的东西躺在盘上**：入库夹具 `fixtures/td-configs/counter-siege.json` 的 `hud`
与上面那段骨架**逐字节相同**（含 `start.size = 28×22` —— 那正是[票 72](72-shell-no-stretch-non-nine-slice.md)
量到「照包里的 44 画、声明 28、右边缘出屏 8px」的那一格）。

## 2 · 与票 73 的关系：**同族，但不是同一个问题**

| | 横版（票 73） | 塔防（本票） |
| --- | --- | --- |
| 骨架里写着某一个包的数 | ✅ 是（`panel.size = 72×32`） | ✅ 是（`panel.size = 480×30`） |
| **提示词里有一条把那个数写进算术的规则** | ✅ **有**（规则 8 的 `x > ${vp.w − 72}`） | ❌ **今天没有**（全仓 `- 72` / `− 72` 只有 `ops.ts:857` 一处） |
| 骨架抬头写「逐字照抄」 | ✅ 是 | ✅ 是（`prompt.ts:633`） |
| 骨架的落款有没有把那个数排除在「照抄」之外 | ⚠️ 只说了**位置** | ⚠️ 只说了**那张地图**（`prompt.ts:636-639`：「骨架里那张地图是「行格式的演示」」）—— 其余的数**一个字没说** |
| 判据会不会响 | 会（`auditPanelSize` / `auditScreenSpace`） | 同样会（塔防三格共用 `auditPanelSize`；五个 HUD 成员走 `auditScreenSpace`） |

⇒ 票 73 的裁定（规则 8 改**盒子口径** · 「示意」覆盖**位置 + 尺寸 + 锚点**）**在塔防这一份上没有对应的落点**：
这里没有那条算术可改，缺的是**一句根本没有的话**。
⚠️ 而塔防的骨架还有一处横版没有的东西：**它里面的数更多**
（`readout.at` / `icons.at` / `buttons.at/step` / `start.at` —— 全是照着那一包挑的）。

## 3 · 要裁什么

- **Q1 · 那句「哪些数是示意」的话要不要加、加在哪**
  - **(a)** 与票 73 的 Q1′ 同款：在「逐字照抄这个骨架」那句上写明**位置、尺寸、锚点都是示例**，
    并让**清单**当尺寸的唯一权威；
  - **(b)** 只给 `hud` 那一块加一句（塔防的铁律里有地盘，可以写成第 12 条）；
  - **(c)** 不加（记为已知的示例口味）；
  - **(d)** 别的。
- **Q2 · `hud.*.size` 要不要一条**铁律**（横版也没有这条）**
  真正会响的约束是 `auditPanelSize`（非九宫格 ⇒ 声明必须 == 包）与 `auditScreenSpace`（整个盒子落在视口内）。
  ⚠️ **这会把票 73 的 (乙) 再往前推一格** —— 横版那边裁的只是「别让骨架暗示固定尺寸」，
  这里可能要**正面写出规矩**。⇒ 要不要写、写成什么样，由本票裁。
  ⚠️ 但**先量**：横版清单**每行**都印了「九宫格 / 非九宫格」那半句后果（票 71 / 85 的成果），
  塔防那份**也印**（同一份 `nineSliceNote`）⇒ **写一条铁律是不是在把同一句话说第二遍**，是本问的核心。
- **Q3 · 射程**：只治 `hud` 那三格，还是连 `readout` / `icons` 的坐标一起（票 73 的 Q4 裁的是「收进那句话、不逐项改数」）？
- **Q4 · 验证边界**：与票 73 同一把尺子 —— 免费能证「提示词自己说了什么」与「照抄会被哪条判据拒」；
  **证不了「模型会不会照抄」**（那要真上游 ⇒ 归[票 23](23-e2e-fixture-wasteland.md)）。
  ⚠️ 塔防多一个免费台子：`fixtures/td-configs/counter-siege.json` 就是一份**照抄过的样本**（§1）。
- **Q5 · 要不要一条判据**（票 73 的 Q3 在塔防这一侧的对应物）。
