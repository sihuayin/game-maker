## 1 · 现场（票 23 第二十跑的站点，只读）

- 站点：`raw/run-out-2026-10-17d/wasteland-scavenger-assets/site/v1/index.html`
- 截图：角色、HUD、三个拾取物、尖刺都在；**背景全黑**（等了 15s 再截仍一样，不是加载慢）。
- `game-config.json`：world **1920×270** · `scene.background.asset = "level-downtown-ruins"`（四层）。
- 包：`level-downtown-ruins` **size 1920×540** · **anchor `{x:0,y:1}`（左下）**。
- `buildWorld` 产出的四层盒子：全部 **`{x:0,y:-540,w:1920,h:540}`** ⇒ 视口 `y=0..270` **零重叠**。

## 2 · 根因

`packages/demo/src/draw.ts:224-225` 的 `buildBackground` 把每层的落点写死为：

```ts
draw: { at: { x: 0, y: 0 }, anchor, w: nom.w, h: nom.h }
box:  boxAt({ x: 0, y: 0 }, { w, h }, anchor)
```

- `last-train` 的背景 `bg-dusk-halt` 锚点是 **`{0,0}`（左上）**、480×270 ⇒
  `at(0,0)` + 左上锚点正好覆盖视口 ⇒ **旧夹具一直是对的**。
- e2e 这份背景的锚点是 **`{0,1}`（左下）**、1920×540 ⇒
  `at(0,0)` + 左下锚点把整块放到 **`y=-540..0`** ⇒ **在视口上方**。
- 相机 `setBounds(0,0,1920,270)`、**世界高 == 视口高** ⇒ 垂直滚不动，所以四层永远看不见；
  透出来的是相机底色（黑）。

⇒ **不是图像模型生错了图**（`delivery/atlas.backgrounds.png` 四层内容完整），
也**不是包 / 清单的锚点错了**；是**外壳把 `at` 写死成左上角**，
只在「背景资源恰好是左上锚点」时成立。

## 3 · 为什么第二十跑没抓到

- `auditLayerCoverage` 只量**绘制宽高 / 墨覆盖率**；`site.ts` 的层覆盖门只问宽与「最远层画满没有」。
- `world.test.ts` 的背景断言只量 `box.w`（平铺层是否铺满世界宽）与层 / 帧对应，**不量 `box.y`**。
- 站点在第二十跑才第一次装配出来；验收是文件级的（manifest / qa / site 存在），
  没有像素 / 落位判据。
⇒ 这是一条**缺失的判据**，不是某一次生成的偶然。

## 4 · 要改的（建议；施工前请拍板）

### 4.1 落位规则（二选一）

| 选项 | 内容 | 对 last-train | 对 e2e |
| --- | --- | --- | --- |
| **(a) 按锚点相对世界落位**（推荐） | `at = { x: anchor.x * W, y: anchor.y * H }` · `box = boxAt(at, {w,h}, anchor)` | **不变**（{0,0} ⇒ at(0,0)） | **修好**（{0,1} ⇒ at(0,270)，box y=-270..270） |
| (b) 背景层改用固定盒子 | 忽略 anchor，背景一律 `box={0,0,W,H}`、`at` 由盒子反推 | 不变 | 修好，但**丢掉包的锚点声明**，与其他资源的锚点语义不一致 |

**推荐 (a)**：它让两份真包各自按自己声明的锚点落位，且 last-train 的盒子逐字不变（`{0,0,480,270}`）。
