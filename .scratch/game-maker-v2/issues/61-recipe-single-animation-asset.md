## Question

**配方层产不出配置层要的角色形状。** 契约这一侧要的是：

```
contracts/src/game-config.ts:132   Player.anims = { idle, run, jump }  ← 三格**都必填**
contracts/src/game-config.ts:287-290  对每一格逐个调 ref(…, { asset: config.player.asset, anim })
contracts/src/assetpack.ts:341,354    resolvePackRef 查的是**那件资源自己的** animations
```

⇒ **一件资源要同时带 `idle` + `run` + `jump` 三个动画。**
⚠️ 而契约的**假设**就写在 `game-config.ts:264-266` 的注释里（原话）：
「**玩家资源按定义有多个动画**」。

**而活链产出的是另一回事**（第十二次真跑 · 段 B 实测）：

```
player-scavenger  sprite      anims []                    ← 模型在 config 那一步挑中了这件
player-walk       animation   anims ["walk"]              ← 名字是 walk，不是 run
player-jump       animation   anims ["jump"]
player-idle       animation   anims ["idle"]
26 件里 **0 件**带多于一个动画 · **没有任何一件**有叫 `run` 的动画
```

⇒ **`config` 那一发对活链产出的包过不去**（退 4、`config` 第一次被执行就抛）。
⚠️ 而**上游三个名字一次都没出现过**：`idle` / `run` / `jump` 只住在**配置层**

**配方 / 设计 / 视觉的提示词里一个都没有** ⇒ 配方层**不知道**配置层要什么形状。

## 验收条件（人裁给的五条 · **原话逐字**）

1. **生产形状正确**：角色资源包含 `idle`、`run`、`jump` 三个动画，名称与配置契约一致。
2. **动画确实不同**：三种动画不能仅因名字不同就算通过；至少要验证它们引用的帧序列或动画内容
   符合各自动作语义，**不能用同一个 `walk` 动画冒充三种动作**。
3. **引用闭环**：生成的 AssetPack 能被现有配置校验器接受，三个动画名称都能在同一件角色资源的动画表中解析。
4. **负例有效**：缺少某个动画、引用不存在的动画、**三个动作共用同一动画**，都不能被误判为满足本次验收目标。
5. **不削弱契约**：不通过放宽 `Player.anims` 必填要求或修改 `player.asset` 类型判据来绕过问题。

⚠️ **第 4 条是本票存在的理由**（人裁原话）：

判据必须落到**内容级**。

#### Q12 补充裁定：配方提示词的最终语义（原话逐字）

提示词必须表达以下完整约束：

- 玩家名下 kind: "animation" 资源恰好一件。
- 该资源的 animations[] 必须同时包含契约规定的三个固定名称。

- 每路动画至少 2 帧。
- 该资源的 characterId 必须存在，并严格等于设计层的玩家 ID。

不再使用容易让模型理解成"把分散资源合并即可"的模糊表述来代替资源基数约束。

#### Q13 补充裁定：判据与八发变异（原话逐字）

新增三项明确的覆盖要求：

1. 提示词判据：资产层测试必须断言配方提示词包含插值后的三个固定名称；配置层测试必须断言配置提示词包含"三格互不相同"的明确约束。不能只验证最终闸门行为。
2. 帧数变异 M7：移除玩家动画 frames >= 2 约束，原先把 jump 改成 1 帧的负例必须变红。
3. 提示词变异 M8：移除 Q9 玩家动画要求的整个提示词段落，新增的配方提示词判据必须变红。

原有 M1–M6 保持不变，总计 8 发变异。每发都要确认指定判据确实失败，再还原变异，并确认没有残留改动。
