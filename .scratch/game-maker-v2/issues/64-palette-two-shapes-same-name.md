## Question

`VisualWorldSpec` 里有**两个都叫 `palette` 的键，形状不同、还紧挨着**：

```text
顶层 palette       z.strictObject({ primary, secondary, accent, background, shadow, highlight })   ← visual-world.ts:199
                   六个桶，每桶一串 `palette:<下标>` 引用（PaletteRefShape，:81 的正则 `^palette:\d+$`）
style.palette      PaletteShape —— 有序色值数组 `["#rrggbb", …]`，世界的**唯一颜色来源**（:55 / :68 / :108）
```

⚠️ 而且**模型被要求同时写下这两份**：`ModelFacingSpec = VisualWorldSpecSchema.omit({ styleReferences: true })`
（`analyze-reference.ts:45`）**只 omit 了 `styleReferences`** ⇒ `style: StyleSpecShape`（`:284`，**必填**）
连同它里面的 `palette` 一并要模型写。

**要裁决的是**：这一处要不要动、动哪一支 —— 还是接受这个率。

### 两种形状的代价不一样（免费量到）

| **(b) 改键名** | 顶层 `palette` → 一个撞不上的词（票 34 治 `coreLoop` 的那一手） | **要付一次 format 升级**：`visual-world/v1`（`visual-world.ts:55`）是**真产物格式**，而它会**进资源包**（`pack.ts:330` 写 `authoring/visual-world.json`）并被读回（`ops.ts:246`）⇒ 旧 `run/v<N>/` 与旧包里的那份**会不再过契约**。⚠️ **具体代价今天没量过** |

## 已经量到的（别重新量）

- ⭐ **第十三次真跑（2026-10-13）· 3/3 全灭，三发都是同一形状**：
  `palette: Invalid input: expected object, received array`。
  现场 `.failed-2026-10-13T12-20-35-123Z/visual-world-attempts.json`（22501 字节 · `run-visual-world-attempts/v1` · **3 发**，
  票 60 的容器第一次在真跑上落盘）。逐发 `stopReason: "tool_use"` · `in 230` / `out 1662 · 1882 · 1439`。
- ⭐⭐ **读出来的病因（H4 的答案，且是最硬的那种读法）**：模型把**它刚写下的那份 `style.palette` 逐字节抄进了顶层 `palette`**。

  | | 第 1 发 | 第 2 发 | 第 3 发 |
  |---|---|---|---|
  | 顶层 `palette` | `["#2b3a4a",…]` 11 个 | `["#2b3147",…]` 12 个 | `["#1f2a44",…]` 10 个 |
  | `style.palette` | **同一份，逐字节相同** | **同一份** | **同一份** |
  | `materials.*.color` | ✅ `["palette:1","palette:8"]` | ✅ | ✅ |

  ⇒ **模型懂 `palette:N` 引用语法**（`materials` 全对），只是把「**色值的家**」摆到了「**桶**」的位置。
  ⚠️ 与票 60 票面的 H4 二选一逐字对上：「若它抄的是 `style.palette` 的 **hex 列表** ⇒ **同名两形状诱导**」。
- ⭐ **它是三发唯一的一处病**（免费判过，`packages/contracts/dist/visual-world.js`）：
  用 `ModelFacingSpec` 判 ⇒ 三发**各 1 处**、都是 `palette`；**只把那一格摆成六个空桶 ⇒ 整份都过**。
- ⭐⭐ **重排探针 ⑤（`raw/palette-shape/` · n=6 · 2026-10-10）那张表，结论比当时写的更强**：

  | # | 顶层 `palette` | 过 | 病由 |
  |---|---|---|---|
  | 1 | object | ❌ | `palette.primary.0` 写成**硬编码色值**，不是 `palette:<下标>` |
  | 2 | object | ✅ | — |
  | 3 | **array** | ❌ | `expected object, received array` |
  | 4 | object | ❌ | `Unrecognized key: "style"`（**自造了第七个桶**） |
  | 5 | **array** | ❌ | 同上那条 + `materials.clothingLight.color2` 多一个键 |
  | 6 | object | ✅ | — |

  ⇒ **4 发失败，4 发全出在顶层 `palette` 这一个字段上**（写成数组 / 桶里写死色值 / 自造桶）。
  ⚠️ 票 23 当时把它读成「**失败的形状是散的** ⇒ 模型在这个对象上本来就不稳」——
  **今天要更正这句**：散的不是**字段**，是**同一个字段的错法**。
  ⇒ 它不是「四个模式之一」，它是**整步现在唯一的失败点**。
- **率**：探针 ⑤ 首发成功率 ≈ **2/6 ≈ 33%**；R16 那 3 发地板下，**每跑约 30% 死在入口**
  （`(1−0.33)³ ≈ 0.30`）。⚠️ **n=6 太小**（95% 区间大致 10%~70%），别把「三分之一」当准数。
- **今天这一跑不改变那个率**：3/3 在 33% 那条率下概率 ≈30% ⇒ **落在噪声里**，与第四跑当时同一句结论
  （票 23 §九⑤）。⚠️ **一次运行 = 一个窗口**，它答不了「失败成不成串」（H2）。
- **声明是对的**（票 23 第四跑那节量过）：交到模型手上的 JSON schema 里，顶层 `palette`
  明明白白写着 `type: "object"`、六桶全 `required`、`additionalProperties: false`。**不是 schema 生成的锅。**
- ⚠️ **散文今天有半句诱导**（`prompts.ts` 的 `TOOL_DESCRIPTION` 第 3 条，逐字）：
  「六桶（`palette.primary` 等）与 `materials.*.color` 里的 `palette:N`，必须指向你**自己刚写下的那份** `style.palette`」
  —— 它**在同一句里同时引出 `palette` 与 `style.palette`**，却**从头到尾没说「顶层 `palette` 是一个对象，不是数组」**。
  ⚠️ 这一句是**今天的**读法，**不是判据**：它是不是病因，**没人量过**。
- ⚠️ **反例不能替它背书**：`style.palette` 是 **6/6 全对**（探针 ⑤）、今天 **3/3 全对** ⇒
  模型在**数组**这一侧从来没失手，失手**只发生在对象那一侧**。
