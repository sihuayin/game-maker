## Answer

**五问全按推荐**（人裁 2026-10-13，逐条原话见 §2）：**一条判据都不立 · 记账但修正措辞 · 新增「色板外像素」的诊断观察 · 「强调色面积上限」记为事实 · `panel 构图` 拆给 `review` / [票 22](22-review-with-reference-image.md)**。
⚠️ **本票的边界一个字没破**：`packages/contracts/` **一个字节没动**（票面「不许顺手改契约」· 人裁「沿既有 review 路径处理，避免扩大本票范围」）；**没回到提示词那条路**（票 30 的 Q1 = ② 早已否掉）；**一张图都没买**（零付费跑）。

> **人裁给的结论（原话，逐字进本票）**：
>
> 「当前三项视觉性质均不新增为 R3 判据。现有实现机制及特定样本的测量结果单独记账；新增色板外像素观察，使 inspectPack 不再静默丢失该诊断信息。未来如需将某项性质升级为判据，必须先定义机器可读、适用于目标视觉世界的声明及其契约传递路径，再单独决定执行与验收责任。」
>
> 并附上它纠正的那件事：
>
> 「这样就把问题从「谁来执行规则」纠正为「规则由谁声明、如何传递、谁负责验证」，同时不把当前实现行为误认为产品契约。」

### 1. ⚠️ 本票最要紧的一行：票面那三问问的是「**要不要给它们一个执行者**」，而量下来**缺的不是执行者**

票面（和 `prompt.ts` 那段代价自白）把这件事记成「那几条**一条都没有执行者**」。**实测这句话不准确**：

| 票面那一行 | 交付态实测（免费探针，走的是仓库自己的解码器 + 已经躺在 `fixtures/` / `out/` 里的产物） | 谁在守 |
|---|---|---|
| `no pure black or pure white` | **210 份图集 · 10,903,643 个不透明像素 ⇒ 纯黑 0 个 · 纯白 0 个 · 带它们的文件 0/210** | `quantizeToPalette`（交付的每个像素都被吸到色板项上）—— 而**全仓 80+ 份 `stylespec.palette` 里没有一份含 `#000000` / `#ffffff`** |
| `strict uniform pixel grid, no smooth anti-aliasing` | 现行契约那两份包（`counter-siege/v4` · `last-train/v2`）**非二值 alpha = 0** | `finishFrame` 里的 `thresholdAlpha` + `raster.ts:117` 自己写着「**不抗锯齿**」 |

⚠️ **两句要紧的话**：
- **守它们的是两个「不是为它们设的」机制** —— 量化与二值 alpha ⇒ 准确的说法是
  「**没有具名的执行者，但有两件副产品在替它们守**」，而不是「没有执行者」。
- **而那两件副产品各自有一个链上没人看着的输入**：① 色板（模型写的，`packages/contracts` 里**零规则**
  —— `grep 000000 packages/contracts/src` 零命中）② `alphaThreshold` 那个口子。
  ⇒ 「今天成立」**不是结构保证**，是「**今天恰好**成立」。

### 2. 裁定与边界（人裁原话，逐条逐字）

| 题 | 裁定 | 理由与边界（原话） |
|---|---|---|
| **Q1** 三条能否成为 R3 判据？ | **(a) 一条也不立** | 「纯黑 / 纯白为零、alpha 二值化、强调色面积上限，都缺少适用于不同视觉世界的机器可读声明。前两项目前是实现副产物；第三项在现有 V2 链路中没有可传递的契约依据。」 |
| **Q2** 如何记录「没有执行者」？ | **记账，但修正措辞** | 「不应写成「没有执行者」：quantizeToPalette 和 thresholdAlpha 已经在执行相关操作。真正缺的是针对这些性质的显式契约声明及相应验证责任。记录现有机制、未受契约约束的输入，以及当前保证的边界。」 |
| **Q3** 是否新增一条观察？ | **(a) 新增** | 「inspectPack 当前静默丢弃色板外像素，导致「交付图与色板不一致」不可见。将其作为诊断观察记录，而非失败条件、阈值或验收判据。」 |
| **Q4** 如何定性现有测量？ | **记为事实，不提升为规则** | 「210 份图集、10,903,643 个不透明像素中纯黑和纯白均为零；counter-siege/v4、last-train/v2 的非二值 alpha 为零；counter-siege sprites 存在 57 个色板外像素，约占 1.89%。这些是特定样本的测量事实，不构成普遍保证。」 |
| **Q5** `panel 构图` 如何处理？ | **拆给 `review` / 票 22** | 「不把构图质量混入本票的像素契约或色板诊断。沿既有 review 路径处理，避免扩大本票范围。」 |

### 3. 落地了什么（两处，都不动契约）

- **Q3 → `packages/assets/src/ops.ts` 的 `paletteUsage`**：那一行 `if (i >= 0) { … }` **没有 else**，
  色板外的像素被**静默丢掉**。现在补上另一半：逐色计数、`perAsset[].offPalettePixels`、
  包级 `offPalette: { pixels, share, colors[] }`（前几色），以及两处措辞
  （逐个资源那行**只在不为 0 时**挂一截 · 包级那行**恒打**，为 0 也打 ——
  「交付图与色板对得上」也是信息，不能靠「没有这一行」表示）。
  ⚠️ 头注释与出参注释都明写**它是诊断观察，不是失败条件、不是阈值、不是验收判据**，
  并写明 `offPalette.share` 的分母（**全部不透明像素**）与 `perColor[].share` 的分母（只在色板内的那些）
  **故意不同** ⇒ 别把两组数放一起比。
- **Q2 → `packages/assets/src/prompt.ts` 那段代价自白**：把「票 47：那几条今天**一条都没有执行者**」
  换成本票量到的事实（210 份图集 / 10,903,643 不透明像素 / 纯黑 0 / 纯白 0 · 守着它们的是
  `quantizeToPalette` 与 `thresholdAlpha` · **真正缺的是显式契约声明与验证责任** ·
  两个机制各自有一个没受契约约束的输入 · 「成立」是特定样本的测量事实、不是普遍保证）。
- ⚠️ **本票只接线** —— **没有新契约、没有新闸、没有新字段**。地图上那团已记的雾
  （「把 `inspect` 的观察**接进创建链**」，票 20 的 Q2 派生）**不在本票里替它做决定**，
  只把它那一半「报得出来」做完了（见 `Not yet specified` 的带日期更新）。

### 4. 判据（`packages/assets/tests/inspect.test.ts`，4 → 9 条）

保留票 39 那四条，新增一个 describe「票 47 · 色板外像素是一条**观察**（以前静默丢掉）」共 **5 条**：

- **真包上的事实**：`counter-siege/v4` 的 `offPalette.pixels === 57` · `opaquePixels === 8683` ·
  `share ≈ 57/8683`；`last-train/v2` 的 `2548`；两份都满足
  `totalPixels + offPalette.pixels === opaquePixels`（这两份数**不许各算各的**）；
  报出来的颜色**确实不在色板里**。
- **⚠️ 它不是判据**：断言钉在**那一行自己**上（`summary.filter(含「色板外像素」)` 恰好一行 + 措辞 + 照常返回）。
- **与契约字段对账**：`paletteBinding === "exact"` 的资源 ⇒ `offPalettePixels` 必须是 0，
  且**有非空守卫**（那两份包里真有资源带色板外像素，否则这一圈恒真）。
- **阴性 · 构造**（零付费，`generate` 是注入的桩）：全程只用色板色 ⇒ 0 个色板外像素、
  `colors` 为空、`totalPixels === opaquePixels`，而**那一行照样打得出来**（`色板外像素 0 个`）。
- **阳性 · 构造**：一个手写的 `opacity: 0.5` 就够 ⇒ 混出色板外的颜色，而且 manifest 里
  那些资源的 `paletteBinding` **自己说** `composited` —— 两条**独立**的事实对得上。

⚠️ **变异三发，各自红在该红的那一条上**（之后逐份还原，`diff` 对备份**逐字节相同**）：
① 抽掉那半个 `else`（回到静默丢掉）⇒ **红 2 条**（构造阳性 + `exact` 对账的非空守卫；
  ⚠️ **诚实交代**：包级的 `offPalette.pixels` 是**减出来的**（`opaqueAll - total`）⇒ 它**挺过了这一发**，
  咬住的是逐资源那个数与前几色那张表）；
② 把那一行的措辞降级 ⇒ **红 1 条** —— ⚠️ **第一版这条断言是空守卫**
  （拿整个 `summary` 去 match，而色板分布那块**本来就带**那四个字）⇒ 改成**只钉那一行**之后才红
  （先见到 0 红，才补的判据）；
③ 把它升级成失败条件（`if (off.pixels > 0) throw`）⇒ 文件在**收集期**就崩（module-scope 调用）⇒ 1 failed file。
