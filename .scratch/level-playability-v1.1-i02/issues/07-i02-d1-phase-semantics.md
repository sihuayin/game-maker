## Question

I-00 §4.3 / §5.1 已冻结「相位是自由变量，配置不表达相位」。I-02 必须裁定：算法在相位空间上做**全称证明**、**存在性证明**，还是**保守降级**。这直接决定 Witness 与永久封锁证明的量化方向。

### 必须裁定

1. **初始相位 `φ0` 的量化**：`∀φ0` / `∃φ0` / 未知即 `INSUFFICIENT_EVIDENCE`。分别对应什么结论资格。
2. **`T_arr` 与相位的关系**：玩家抵达危险区的时刻是否显式建模；若 `T_arr` 不可测，相位自由是否仍成立。
3. **U9 安全等待格**：如何证明「可达 + 可等待 + 等待过程本身安全」；三者缺一是否足以否定相位自由。
4. **Witness 的量化**：找到「某个 `φ0` + 某条路径」是否足以支持 `NO_PROVEN_BLOCKER`；还是必须证明「存在一个等待策略，使任意初始 `φ0` 都能实现安全通过」。
5. **永久封锁门的量化**：门区恒覆盖是否必须 `∀φ0` 与 `∀ lag 位姿`；与 I-00 PU 第 1 条的关系。
6. **`lagMs` 的方向**：Witness 用并集 / `pad`（保守多判危险），门区用交集 / 无 pad（保证覆盖）；是否需要第二套滞后模型，还是同一模型的两个方向。
7. **降级顺序**：相位不可确定且 U9 不成立时，是否一律 IE；与预算超限、几何不可信的优先级。
8. **诊断字段**：内部结果记录哪种量化、哪些相位/等待证据。

### 硬约束

- 不得把「相位是自由变量」误读成「输入中存在相位字段」。
- 不得用未裁定的量化方向先行固化算法原型假设。
- 与 I-00 冻结条文冲突时，回到冲突登记表，不静默择一。

## Answer

用户 2026-11-10 两轮裁定；第二轮五项全部采纳推荐，Q5 增加严格限定。**修改产品目录：否。**

### 1. 量化模式

- 初始相位 `φ0` 在出生时未知；量化 = **universal-per-phase**：`∀φ0 ∈ Φ0`。
- 每个 `φ0` 允许自己的策略/路径（路径族）；策略可以依赖**精确相位**（a1）。
- 碰撞判定用 `hazardSpeed × lagMs` 的扫掠带保守覆盖。
- NB 的充分条件：

  `NB ⇔ U9 ∨ (∀φ0 ∈ Φ0 : (spawn, φ0) ∈ W)`

  其中 `W` 是全相位 Winning Set，必须具有**完整、安全、可验证的转移证明**；不能用有限采样的若干成功轨迹冒充全相位证明。

### 2. `T_arr`

- I-02 **不消费 `T_arr`**：不新增 `TemporalAnalyzer` 入参，不修改现有输入 Contract。
- `φ0` 是出生时未知的初始相位；每个 `φ0` 对应的策略自行选择等待时间和抵达时间。
- Hazard 相位按 `Motion` 周期模型随 game-time 推进。
- 策略给出的等待、移动、抵达时间必须有限，且处于模型可验证的时间范围内；超出模型视野、无法计算或无法验证的时间轨迹 ⇒ `INSUFFICIENT_EVIDENCE`。
- **关键区别**：相位自由覆盖未知初始相位，不代表可以忽略玩家抵达时间；`T_arr` 不作为外部输入，但必须是策略轨迹中可计算、可验证的时间量。
- 未来若要调用方指定抵达时间，另提输入扩展裁定，不纳入 I-02。

### 3. U9

**U9 证书**（格子 `s`）必须同时满足：

1. `s` 是 `graph.standable` 定义的玩家脚点格。
2. 对每个合法初始相位 `φ0`，存在从 `(spawn, φ0)` 到 `s` 的无碰撞路径。
3. 在 `s` 停留完整周期 `P`，对每个合法初始相位，整个等待期间都无碰撞。
4. 上述路径与等待阶段都使用 Witness 的 lag pad。
5. 任何一项无法验证，U9 证书即不成立。

**角色**：

- U9 是 NB 的 canonical **充分**证书；`∀φ0` Winning Set 是另一条**独立充分**证书。
- U9 失败不自动等于 IE；还可以验证全相位 Winning Set。
- 两条路径均未能证明 NB 时，不能从搜索失败直接推导 PU。
- 两者任一完整成立即可支持 `NO_PROVEN_BLOCKER`。

**与 I-00 的调和记录（用户明确限定）**：

> I-00 的 U9 仍是相位自由条件下的 canonical 充分证书。I-02-D1 增加「`∀φ0` Winning Set」作为另一种独立充分证书。两者任一完整成立即可支持 `NO_PROVEN_BLOCKER`。该扩展**不改变** I-00 的任何 `PROVEN_UNPLAYABLE` 条件，也**不改变** U9 本身的定义。这是对证书**充分性**的操作性扩展，不得把 U9 的既有冻结语义改写成非必要条件，亦不得放宽 PU 条件。

### 4. Witness 证据形状

- 正式 Witness = **按初始相位覆盖的路径族**。
- 每个相位对应的路径段至少包含：起始状态与结束状态；起止时间及时间区间；玩家碰撞盒；Hazard 相位及对应位姿；lag pad 使用信息；连续时间无碰撞验证结果；路径连接处的连续性证据。
- 正式证明义务：`∀φ0 ∈ Φ0, ∃π_φ0 : VerifiedSafe(π_φ0)`。
- Winning Set 与策略表可以作为**内部构造形式**，但不能直接替代正式证明。
- 路径族体积过大时，允许「策略表 + 全相位验证轨迹」作为等价证据，但必须满足：
  1. 策略表覆盖全部合法初始相位；
  2. 状态转移关系可验证；
  3. 全相位验证轨迹覆盖策略所需的完整证明范围；
  4. 所有轨迹段均通过连续时间安全验证；
  5. 体积上限由 D5/D9 冻结，超限降级，**不得截断证据后继续判定 NB**。

### 5. PU 与 Witness 搜索

- PU 完全由 I-00 冻结的六项条件独立判定；Witness 搜索不必完成；**无 witness 永远不是 PU 的证明条件**。
- 门区：`D_gate = ⋂_{φ0∈Φ0} ⋂_{δ∈[0,lagMs]} H(φ0,δ)`。不能用某个幸运相位的门区覆盖证明全局永久封锁；某些相位有路、另一些无路，不足以支持 PU。
- 预算独立：

  | 证明路径 | 是否依赖 Witness 搜索完成 |
  | --- | --- |
  | NB：U9 证书 | 不依赖全相位 Winning Set 搜索 |
  | NB：Winning Set | 必须完成其自身证明 |
  | PU：门区 + I-00 六条件 | 不依赖 Witness 搜索完成 |

- Witness 搜索预算耗尽，不阻断独立 PU 证明；PU 的门区或图割证明预算耗尽，不能输出 PU；PU 不得仅凭门区成立而省略图割及其他冻结条件。
- NB 与 PU 是**两条独立证明分支**，不是同一条串行搜索链。这修正了第一轮降级链的表达：最后一阶「完整 Witness 搜索结果」只服务 NB。

### 6. 内部诊断字段

D1 冻结以下内部结果最低要求（只存内存、不落盘、不新增公共 evidence、不改公共 Contract；具体类型/枚举/体积限制由 D9 冻结）：

| 字段 | 记录内容 |
| --- | --- |
| `quantificationMode` | `universal-per-phase` |
| `initialPhaseSet` | 合法初始相位集合及其表示方式 |
| `u9Certificate` | 证书状态、失败条件或缺失原因 |
| `winningSetStatus` | 未运行、证明成立、证明失败或 IE |
| `tArrMode` | `strategy-derived` |
| `lagDirection` | Witness 并集/pad；Gate 交集/无 pad |
| `phaseWinCount` | 已验证成功的相位数量 |
| `phaseLossCount` | 已验证失败的相位数量 |
| `gateProofStatus` | 门区证明状态 |
| `budgetStatus` | 预算是否耗尽及具体预算类型 |
| `degradationReason` | 主要降级原因 |

- `phaseWinCount` / `phaseLossCount` 是诊断计数，**不代表已经证明完整相位空间**；必须同时记录相位覆盖是否完整，不能把抽样数量误读为全称证明。

### 7. 收口边界

- **不解锁**：I02-02、I02-03、I02-04、I02-05 的生产实现，也不解锁 I-03。
