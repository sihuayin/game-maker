### 2. R1（U1 完成后）逐项通过条件（Q2）

任一项 `FAIL` 或 `NOT_RUN` ⇒ R1 不通过 ⇒ U2 不得授权。不得用测试总通过率替代逐项验收。

| 项 | 通过条件 | 证据口径 |
| --- | --- | --- |
| 运动模型 | 三角波原式、`t=0` 在 `at`、`P/2` 折返、两端不停留、负时间/多周期、折返点不定义速度 | E1 `file:line` + E2 测试名/断言/退出码 |
| AABB 语义 | `overlapsStrict` 严格不等号；相切/角接触/零面积不算撞；`1e-9` 正面积算撞；y 轴同判据 | E2 + I02-06 Phaser 证据引用 |
| 连续求交 | 折返点切段、闭式解、开区间求交、相邻区间合并、不采样；折返点切触、同速、`dt=0`、非有限值 | E2 + E3 scratch 复跑 |
| ε | 单一具名常量 `max(1e-9, 1e-9×(xMax−xMin))`；只用于门宽/显式区间阈值；不进入碰撞谓词 | E1 + E2 |
| 数值稳定性 | `c1 === 0` 精确判定；不对速度差设绝对容差；不用 `hi−lo > 1e-9` 掩盖；任意小安全窗口保留 | E2 + E3 |
| 反例测试 | I02-03 §8 的 6 处 P0 差异、采样陷阱、折返点相切、负时间、同速、非有限值全覆盖 | E2 测试名清单 |
| 范围与确定性 | `git diff` 只含 U1 白名单；无新依赖；同输入重复运行逐字节一致；未接公共 Verdict | E3 命令 + 退出码 + diff stat |

**三个特别冻结的细节**：

1. `c1 === 0` 是**精确分支**；不允许用速度差容差把极小但非零的速度差归零。
2. 任意小的正安全窗口必须保留；不能用 `hi − lo > 1e-9` 把它吞掉。
3. `ε` 只用于门宽和显式区间阈值，不得进入碰撞谓词。

**Phaser 证据规则**：I02-06 的证据必须**可追溯引用**（`evidence/06-phaser-overlap.md` + `World.js:1698-1713`），记录具体证据位置及其能证明的判据范围。Phaser 证据**只证谓词语义**，不证 runtime hitbox equality，也不能替代连续时间解析求交的数学测试。

R1 的强制交付物是 `reports/R1-review.md`：逐项 PASS/FAIL、证据命令、退出码、原始输出摘要/hash、diff scope、未覆盖项、复核人、日期与用户签署。

### 6. Authorization Ledger、能力状态与 U4 统一语义（Q6、Q10）

#### 6.1 单元授权台账

| 单元 | 首次签署状态 | 后续授权条件 |
| --- | --- | --- |
| U1 | `AUTHORIZED` | 首次签署 |
| U2 | `PLANNED` | R1 PASS + 增量签署 |
| U3 | `PLANNED` | R2 PASS + 增量签署 |
| U4 | `BLOCKED` | R3 PASS + `graph.ts` 独立审批 + 增量签署 |
| U5 | `PLANNED` | R4 PASS + 增量签署 |

状态语义：

- `AUTHORIZED`：可按白名单实施，且只到该单元边界。
- `PLANNED`：已定义、未授权；不得提交实现 commit，只能做只读分析/估算。
- `BLOCKED`：存在命名阻塞，未清除前不得授权；**不代表可以绕过审批先做完整实现**，只允许按明确边界开展只读分析和 scratch 实验。

#### 6.2 能力状态（与单元状态分开）

| 能力 | 当前状态 | 解锁条件 |
| --- | --- | --- |
| `PUBLIC_NB` | `BLOCKED` | I-03 对应证据门槛通过 |
| `PUBLIC_PU` | `BLOCKED` | I-03 几何 coverage、移动模型闭合及其他 PU 条件通过 |

单元授权 ≠ 能力授权；I-02 内部计算成功不构成公共 Verdict 发布许可。

#### 6.3 U4 状态统一（Q6 + Q10）

- **完整 U4 实施授权**仍然要求 `graph.ts` 独立增量审批。
- `graph.ts` 审批通过：满足 R3 后，可以申请**完整 U4 授权**，实施双档 hop 采样及完整验收。
- `graph.ts` 审批未通过或被拒：**U4 保持 `BLOCKED`**；可以申请**另行限定的外部 scratch 分析**，但它不等于 U4 正式授权。
- 受限分析可以使用现有 graph API 做模型条件性实验，但双档 hop 加倍项必须标 `NOT_RUN` 或 `INSUFFICIENT_EVIDENCE`。
- 受限分析**不能获得 R4 PASS**，也**不能支持生产 PU**。

因此：Q6 的 U4 状态保持 `BLOCKED`；Q10 的「可做内部计算」限定为不构成 U4 单元授权的 scratch 活动。

#### 6.4 `PLANNED ≠ 隐含授权` 条文

> 授权包列出五个单元，不构成对任一 `PLANNED` / `BLOCKED` 单元的实施授权。每个单元必须有其自己的增量签署记录，引用对应复核产物；前序单元的完成、时间的推移、或 R2 的通过，均不自动授权后续单元。单元授权不等于公共 Verdict 能力授权。

### 7. 提交拆分与 PR 边界（Q7）

- 每个 U 单元一个独立分支、一个独立 PR。
- 上一单元复核签署后，才启动下一单元的正式实现分支。
- `graph.ts` 尾参变更单独 PR：先审批、合并，再由 U4 实现 PR 引用。
- 文档/授权包变更单独 docs PR。
- 禁止混合单元、禁止自动合并。
- 每个 PR 的证据摘要必须包含：测试命令、退出码、测试计数、`git diff --stat`、白名单外文件未修改声明。

### 8. 独立复核（Q8）

独立复核**不是作者换一个窗口自评**。复核会话只获得：

- 白名单；
- 验收表；
- 证据路径；
- 测试命令；
- 必要的原始输入。

不得以作者总结作为通过依据。复核人必须自己重跑命令、检查 diff、逐项判断。复核报告必须包括原始输出摘要或 hash、未覆盖项、复核人、日期及用户签署。E1/E2/E3 的证据标准照用。

### 9. 停止 / 缩范围 / 回滚 / IE 矩阵（Q9）

| 触发 | 动作 |
| --- | --- |
| 需要改白名单外文件 | STOP + HITL 修订授权 |
| 需要放宽 G-01～G-07 | STOP |
| 需要删除/放宽既有断言 | STOP |
| 需要改公共 Contract / CLI / MCP / Runtime | PAUSE + 影响分析 + 审批 |
| 需要新第三方依赖 | STOP |
| 模型外规避无法排除却想输出 PU | STOP PU；IE |
| hop 加倍系统性失败 | NARROW：PU 关闭 |
| 19 个既有移动 Hazard 出现假阳 | **任一确认假阳即停用该类别并调查**；达到系统性阈值时执行类别回滚 |
| 任何错误的 `PROVEN_UNPLAYABLE` | **严重证明健全性失败**；回滚 + 复审，不只是普通测试失败 |
| 预算硬上限系统性不足 | NARROW / STOP |
| 非整数出生点普遍存在 | NARROW / 另裁 |
| `coverage` 未按维度 `checked` 却想发布对应公共 Verdict | BLOCKED（内部计算可以，公共 Verdict 不行） |
| 需要改 I-00 / I-02 原文 | STOP；走冲突登记 |
| 双档 lag 不一致 | IE |
| 确定性失败 | 该单元复核 FAIL，修复前不得进入下一单元 |

**coverage 维度规则**：

- `geometry` 未达到 `checked` 时，不能发布依赖该几何证据的公共 Verdict；
- `temporal` 门槛按 D2/D10 对应证明分支判断；
- 不能把一个维度的 `checked` 借给另一个维度。

保留 I-00 §13 的退出条件：G-01 不可满足 ⇒ PU 关闭；hop 加倍系统性失败 ⇒ 缩范围；19 关假阳 ⇒ 回滚；前置不成立 ⇒ 停止 effort。
