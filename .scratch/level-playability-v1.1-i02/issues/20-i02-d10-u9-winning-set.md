### 1. U9 证书的可执行判据（Q1–Q4）

#### 1.1 空间底板与 coverage

- 使用**基础移动图**：`buildMovementGraph` 构建、**不带任何 moving-hazard 静态掩码**；Hazard 只经连续时间求交进入判定，不退化为静态 forbidden 区域。
- `s` 必须是该图的 `standable` 脚点格，且与 spawn 位于**同一脚点 y 的水平连通段**。
- 证书前置条件：`coverage.temporal = checked`。
- 空间几何的 `coverage` **照实记录**（当前代码恒为 `partial`），不得在诊断或授权包中写成 `checked`。
- I-00 §7.2「全部参与判定的几何 `checked`」保持只约束 **PU 六条件第 2 条**；U9 / W 不抬高也不降低该门槛。
- 若 [I02-D2 运动模型与输入契约裁定](08-i02-d2-motion-input-contract.md) 判定玩家几何不可信，U9 随 `coverage.temporal` 一起降级为 IE。

#### 1.2 运动原语与量化

- U9 接近路径**只允许同一脚点 y 的水平 `walk` 边**：不允许 `hop`、`walk-off`、`fall`（FR-03 / G-05 禁止把依赖未支持运动机制的路径当作确定性可达证明）。
- 量化 = **universal-per-phase**：`∀φ0 ∈ Φ0`，每个 `φ0` 拥有自己的等待 / 出发策略；不是一条万能路径。
- 若 `s` 与 spawn 不在同一水平连通段 ⇒ U9 直接不成立，让位给 W 或 IE，不做静默近似。

#### 1.3 接近段

接近段与 W 使用同一抽象（见 §2）：状态 `(x, k)`、`wait` / `move` 边、残差等待、连续时间解析验证；目标集 = `s` 所在的 x 栅格（同一 y）。形式化为一次以 `s` 为目标的 W 搜索：

- 对每个相位格 `k ∈ Z_N`：spawn 在 `C_k` 内的残差等待安全（§2.3），且 `(spawn, (k+1) mod N) ∈ W_{→s}`；
- `W_{→s}` 必须带终止性证据（§2.5）。

#### 1.4 停留段

- 等待区间 = `[T_arr, T_arr + P]`；`T_arr` 是策略给出的抵达 `s` 的时刻，**不是全局 `t=0`**。
- 切分：只在 Hazard 折返点 `k·P/2` 处切段，使 `P(t)` 在每段内线性，然后解析求交；**不按相位格 `dt` 采样**。
- pad：统一使用 Witness 方向的并集扫掠带，`pad = hazardSpeed × lagMs`，`hazardSpeed = 2·distance/P`；速度恒定 ⇒ pad 不随相位变化，等待全程同一 pad。
- 任一子段严格相交 ⇒ U9 证书不成立；不得因「大部分时间安全」而通过。
- **周期重复依据**：长度为 `P` 的等待恰好覆盖全部 Hazard 位姿一次；「停留后仍可无限等待且始终安全」的推论**仅**在严格周期 `P` 重复、固定 Hazard 几何与固定 Runtime Profile 下成立。该前提不成立 ⇒ U9 降级 IE。

#### 1.5 出口段

- U9 证书必须包含 `s → goal` 的出口段；仅「安全地待在一个格子」不等于走到了目标（I-00 §7 要求安全 witness 抵达目标）。
- 出口量化 = **`∃ψ`**：玩家在 `s` 可无限等待且始终安全，因此可把出口起始相位选到任意格点 `ψ`；只需存在一个安全排程。
- 形式化：`∃j ∈ Z_N` 使 `(s, j) ∈ W_{→goal}`，且该策略带终止性证据。玩家从抵达相位等待到 `j·dt` 的额外等待由 §1.4 的整周期安全覆盖。
- 接近段 `∀φ0`、出口段 `∃ψ` 的不对称是等待格解耦「抵达相位」与「通过相位」的直接结果；这不是把 U9 改写为非必要，也不改变 U9 的冻结定义。

#### 1.6 U9 证书形式化

`U9(s)` 成立 ⇔ 以下四项同时成立：

1. `s` 是基础移动图的 `standable` 格，且与 spawn 在同一脚点 y 的水平连通段；
2. `∀k ∈ Z_N`：spawn 在 `C_k` 内的残差等待安全，且 `(spawn, (k+1) mod N) ∈ W_{→s}`（策略终止）；
3. `s` 在全部相位 `θ ∈ [0, P)` 上、按折返点切段并带 witness pad 的连续时间检查中无碰撞（一次验证覆盖全部相位与任意额外等待）；
4. `∃j ∈ Z_N`：`(s, j) ∈ W_{→goal}`（策略终止）。

任一项不可验证 ⇒ U9 不成立；U9 成立即可支持 `NO_PROVEN_BLOCKER`。

### 2. 全相位 Winning Set（Q5–Q7、Q9）

#### 2.1 空间模型

- **1D 水平走廊**：状态 `x` = 玩家碰撞盒左边缘世界坐标，`x ∈ [xMin, xMax − width]`；与 P0 模型、I02-02「等待 + 水平移动」一致。
- x 栅格锚定 `xMin`，以 `xStep` 步进，并额外并入 `startX` / `goalX`；`xStep = 1px` 为默认值（与 `graph.ts` 的整数脚点格同分辨率，不引入第二个空间粗化）。
- `maxSpeed`、`xMin/xMax`、`startX/goalX` 的配置映射、走廊脚点 y 带、玩家几何可信性由 **I02-D2** 冻结；D10 只引用。
- NB 的 Witness **不建模跳跃 / 下落 / 重力时序**（FR-03、G-05）；2D 移动图只服务 PU 的图割证明（D4）。

#### 2.2 相位格与 `N`

- `Φ0 = [0, P)`；切成 `N` 个半开相位格 `C_k = [k·dt, (k+1)·dt)`，`dt = P/N`。
- 网格约束（I-00 §6.5 / B1）：`N ≥ 2`；`N ≤ floor(maxSpeed · P / xStep)`；在可行上界内取**最大** `N`，再受 `maxStates` / `timeBudgetMs` 约束。
- `floor(maxSpeed · P / xStep) < 2` ⇒ IE（`grid-resolution-infeasible`）；预算耗尽 ⇒ IE。
- `xStep` / `N` 的最终冻结值由 **I02-D5** 按 19 关语料确定；D10 只冻结导出规则。
- `Φ0` 若可收窄（例如 D2 能证明出生时刻相位有界），收窄规则也走 **I02-D2**，不得在本票私设。

#### 2.3 残差等待与全相位覆盖证明

真实出生相位 `φ0` 落在唯一 `C_k`。策略第一步是在 spawn 原位等待到 `(k+1)·dt`（长度 `< dt`）：

- 该段必须对 `C_k` 内 Hazard 位姿的**完整范围**做保守验证（并集 + pad），**不得只检查格端点**；
- 对齐后所有时间都是 `dt` 的整数倍，相位恰为格点；此后每条 `wait` / `move` 转移都在精确的 `[k·dt, (k+1)·dt]` 上做解析连续求交。

因此「N 个格覆盖完整」是**单元格覆盖论证**，不是抽样：每个实数 `φ0` 都归入一个格，并有一条被验证过的策略；代价是残差等待这一处保守化。

P0 原型只从 phase 0 出发做 BFS（`temporal-model.mjs:426`），给出的是单相位 witness，**不构成 `∀φ0` 证明**；I-02 必须对全部 `N` 个格验证 `(spawn, k) ∈ W`。

#### 2.4 状态与转移

- 状态 `(x_i, k)`：`x_i` 在 §2.1 的 x 栅格上，`k ∈ Z_N`。
- 边：`wait`（`x_i → x_i`）与 `move`（`x_i → x_j`，`|x_j − x_i| ≤ maxSpeed·dt`，方向任意）；每条边是一条**可执行的线性线段**，逐段解析验证。
- 抽象不允许「半步」状态（步内减速 / 折返不可表达）⇒ **不完备，但可靠**；不可表达只产生 IE，不产生假 NB。
- 策略：在 `(x, k)` 上的**无记忆策略**；状态已包含全部时序信息。

#### 2.5 Winning Set 的定义、计算与终止性

**修正（相对本票题面）**：Winning Set 是**最小不动点**，不是最大不动点。

`W = μX.(Goal ∪ Pre∃(X))`

其中 `Pre∃(X)` = 存在至少一条安全转移、且后继状态属于 `X` 的前驱状态集合。最大不动点通常对应安全不变集或博弈语义，不是当前的**存在性目标可达**证明；实现可以用反向 BFS / 队列或等价算法求这个最小不动点，但不得把它称为最大不动点。

- NB 要求 `∀k ∈ Z_N : (spawn, k) ∈ W`。
- **终止性是必要条件**：无记忆策略可能形成循环；仅「每条边安全」不足以证明 Winning Set。必须证明每个被覆盖的初始状态**最终抵达 goal**：提供有限完整轨迹，或提供严格递减的 rank / potential。最小不动点的迭代天然给每个状态一个有限 rank（到 goal 的距离）；提取策略时必须选择 rank 严格递减的后继。
- **可靠性**：任何离散 winning 策略都可展开为真实连续时间轨迹；不会产生假 NB。
- **失败语义**：搜索完成但未覆盖全部格 ⇒ `winningSetStatus = failed-complete`；预算耗尽 ⇒ `insufficient`；两者都只能导出 **IE**，绝不导出 PU（D1 已定）。

### 3. 两条证书的组合语义（Q8）

| U9 | W | 结论 |
| --- | --- | --- |
| 成立 | 不要求（可 `not-run`） | `NO_PROVEN_BLOCKER` |
| 不成立 / 未验证 | 证明成立（全格） | `NO_PROVEN_BLOCKER` |
| 成立 | 成立 | `NO_PROVEN_BLOCKER`（冗余；可短路，不要求跑第二条） |
| 两者都未成立，且至少一条因预算耗尽 | — | `INSUFFICIENT_EVIDENCE` |
| 两者都「完整失败」 | — | `INSUFFICIENT_EVIDENCE`，**不得推导 PU** |
| 输入 / 模型 / lag 前置失败 | — | `INSUFFICIENT_EVIDENCE`（优先于一切） |

- NB 与 PU 是**独立证明分支**；某条 NB 搜索的预算耗尽不阻断另一条已成立的 NB 证书，也不阻断 D4 的独立 PU 证明。
- 某条 NB 证书成立不影响 I-00 六条件对 PU 的独立判定；PU 门槛不因本票任何结论而放宽。
- 无 witness / 搜索失败**永远**不是 PU 的证据。

### 4. Witness 体积上限与压缩等价（Q9）

正式证据 = 「按相位格的策略表 + 全相位验证轨迹」。压缩形式只有在以下**六条**同时成立时才等价（D1 §4 五条 + 本票新增终止性）：

1. 策略表覆盖**全部 `N` 个相位格**（不是抽样的若干相位）；
2. 每条状态转移关系可验证，且每条转移都做过连续时间求交（含 §2.3 残差等待的整格保守验证）；
3. 验证轨迹覆盖策略所需的**完整证明范围**，不留未验证分支；
4. 所有轨迹段均通过连续时间安全验证；
5. **策略终止并最终抵达 goal**：提供有限完整轨迹，或严格递减的 rank / potential；只有逐边安全、没有终止性，不足以证明 Winning Set（修正项）；
6. 体积上限由 D5/D9 冻结；超限 ⇒ `INSUFFICIENT_EVIDENCE` + 降级原因 `witness-volume-exceeded`，**不得截断证据后继续判 NB**。

- 体积计量建议双口径：「已验证转移记录数 + 序列化字节数」；具体阈值交 D5，字段类型交 D9。
- 正式路径族与压缩形式都必须能被测试**确定性重放**。

### 5. 下游接口（Q10，含 D4 修正）

#### 5.1 I02-D3 安全通过 Witness 模型裁定

每段至少携带：

```text
{ phaseCell: k,
  t0, t1,
  x0, x1,
  playerBox,
  hazardPoseRange,        // 该段涉及的精确位姿范围，不是采样点
  lagPad,
  continuousCheckResult,
  continuityToPrev }
```

U9 出口段额外标记 `phaseChoice: "existential"`（其余为 `"universal"` 或 `"n/a"`）。D3 必须接收按相位格的策略表与全相位验证轨迹，并纳入：残差等待、U9 出口、周期重复依据、终止性证据（rank / 有限轨迹）。具体类型由 D3 冻结。

#### 5.2 I02-D4 永久封锁门与垂直规避图割裁定 —— **修正**

门区必须使用**全相位 × 全 lag 的公共交集**：

```text
D_gate = ⋂_{k=0}^{N-1} ⋂_{φ∈C_k} ⋂_{δ∈[0,lagMs]} H(φ+δ)
```

其中 `H(θ)` 是 Hazard 在相位 `θ` 的实际占据区域。

- 这是**全称交集**语义：永久封锁要求每个相位、每个 lag 偏移都被 Hazard 覆盖。
- **不得**用相位格内的扫掠并集冒充「每个时刻均被覆盖」——那会把「曾经经过某处」误判成永久封锁。
- 若先算每格内的精确位姿范围：每格的公共覆盖区 = `⋂_{θ∈C_k} H(θ)`（等价于 `[max_θ left(θ), min_θ right(θ)]`），再对全部格取交集；这样仍保持全局交集语义。
- 三角波在格内的极值必在格端点或折返点取得 ⇒ 极值可解析求得，不是采样。
- 本票题面「对 δ 取并集」是错误表述：**lag 并集只属于 Witness 方向（D1 Q2），永不进入门区方向**。
