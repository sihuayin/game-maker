## 1 · 证据

- C：864×1184，ratioDelta −2.70%。
- C2：858×1178，ratioDelta −2.90%。
- `master-ratios.json` 与 `verify` 都记录 `match:false`，但构建继续。
- 旧 107 母版 832×1248 vs 72×108（2:3）是精确一致。

## 2 · 要做什么

- 决定策略：
  (a) 保持零容差，规则是“必须精确”——那就要在生成侧选一个模型能精确返回的比例；
  (b) 给一个小容差（例如 ≤3%），并在验收里注明拉伸风险；
  (c) 生成后按 canonical 比例裁剪，而不是两方向独立拉伸。
- 把决定写进判据/测试，避免“记录了但不判”的状态。

## 3 · 验收

1. 三种母版比例（精确 / 2.9% 漂移 / 10% 漂移）的 fixture 行为明确。
2. 先红后绿。
3. 文档与 `verify` 输出一致。

## 4 · 边界

- 不改母版生成提示词的其它部分。
- 不跑付费上游。

## Answer

**一句话**：母版回图比例**只作观察读数**，保持零容差整数判定，不阻断、不归一化、不换模型；
不新增比例门 —— 沿用 v2《39 · 母版的长宽比判据降为观察》的裁定，本票只确认它在 Style Migration V1 的适用边界。

### 逐字裁定（人裁 2026-10-19）

**Q1 = A · 沿用既有裁定。** 母版回图比例只作观察读数，保持零容差整数判定，不阻断、不归一化、不换模型。用精确、2.9% 漂移、10% 漂移三种 fixture 钉住观察行为，不新增比例门。`recipe` 设计层的尺寸与 canonical 画布判据，以及 `pack` import 母版的画布与磁盘图片判据，继续保持硬判据。

**Q2 = A · 只裁定。** 写入 Answer、关票、更新地图；源码、测试、提示词均不修改。本轮裁定不构成施工授权，三种 fixture 的测试断言留待后续明确授权。

**裁定核心（逐字）**：母版画布比例偏差不等于角色本体比例偏差；动画帧后续会经过抠底、裁切和独立缩放，因此不能把交付资产的比例约束机械地套到母版上。既然没有证据表明新增门禁能保护最终交付物，就不应为已付费的生成结果增加一道没有修复路径的阻断。

**本轮仅确认既有策略的适用边界，不改变生成行为，也不改变任何既有硬判据。**

### 依据（查到的）

- v2《39 · 母版的长宽比判据降为观察》已裁：`aspectRatio` 是提示不是契约（同一 2:3 回来过
  832×1248 / 1184×864 / 1344×768）；**画布比例不是角色本体比例的代理**（同一 0.667 目标，
  前景包围盒量到 0.495 / 0.626 / 1.281；过了判据的两个母版里就有一个本体偏 26%）。
  它只把「上游回图」这一支降成观察，量法保持零容差，并明确「不许顺手加容差」。
- C/C2：请求 48×64（化简就是 Gemini 支持的 3:4），回来 864×1184 / 858×1178（2.7–2.9%）——
  即使 aspect 本身受支持，模型也不保证画布尺寸。
- 母版**不进交付包、也从不被缩放**（`pack.ts` 的 `authoring` 支只落盘 + 当 `reference`）；
  动画帧是在抠底、裁到自身 ink bbox 之后，由 `downscaleArea` 两方向独立缩放到 `spec.size` 的。
  ⇒ 母版画布比例不会机械地传递成一次拉伸。
- 母版提示词里「交付管线会把它两方向独立缩放到 canvas」对母版是**假话**（从资产提示词抄来）。
  ⚠️ 本票**不处理**它 —— 已另立票 07（只裁这句话的改法，不是施工）。
