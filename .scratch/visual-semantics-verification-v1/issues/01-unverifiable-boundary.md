# 不可判边界裁定：数量与空间关系的结构性不可判

Type: grilling
Status: resolved
Owner: claude (2026-10-25)

## Question

已核实事实（fact-finder 2026-10-25，file:line 已核）：

- 设计 spec **无数量字段**：四桶实体只 `{id, 自由文本×1~2}`（`game-design.ts:169-172`），
  `levels[].entities[]` 是 id 引用清单、不是「N 个」。1:N 是下游自由决策（`game-config.ts:92-95`）。
- VDS 布局**纯机械**：一行柱子、同一地面线、占位尺寸，role 是「视觉分组默认、不是身份断言」，
  **不读** `world.structure`/`levels[].layout`/实体自由文本（`layout.ts`）。
- 两把尺子：VDS 屏幕空间 480×270 ↔ GameConfig 世界空间（横向跟随镜头+视差），**无 screen→world 变换**。

用户 Q4=(a) 已裁「承认无可判之物，收缩本图」。本票把这句裁成**可写进文档的精确边界**，并定落点。

**B1 — 数量的可判边界**
- 可判的只有「每个设计实体 ≥1 个运行实体」（覆盖，`auditEntityIdentity` 已判）。
- 「该有 N 个」结构性不可判（设计无 `count`）→ 不可判，**不做**任何新检查。

**B2 — 空间关系的可判边界**
- 绝对位置：VDS 屏幕空间 vs config 世界空间，无变换 → **不可判**。
- 相对关系（左右/上下/相邻/包含）：VDS 无语义布局 → **不可判**。
- 现有几何检查只比 w/h、标 `warning`（观察），**维持不动**，不升判据。

**B3 — 「桶总序」去留（待裁）**
VDS 布局承诺「player → enemies → npcs → interactables → resources」左到右。它是**布局伪影**、
非语义断言（`layout.ts` 头明说 role 不是身份断言）。要不要加一条观察「config 的 x 序与 VDS 桶序是否一致」？

- **不加（倾向）**：它不承载语义（一个敌人合法地可以站在玩家左边），加了只会喷噪音、
  把「布局碰巧排的序」读成「设计想要的序」。
- 加：作为弱观察（只报、不阻断、描述性措辞）。

**B4 — 边界记在哪（待裁）**
- **CONTEXT.md 词汇表补词（倾向）**：在「观察/判据」附近补「数量」与「空间关系」在 VDC 验证语境下的
  「结构性不可判」说明（一句结论 + 三处 file:line 依据），让下一个读代码/画图的人不再走一遍本票的发现。
- 单独文档：开一份 `docs/v7.1/稳定03.md` 把边界写成 PRD。
- 只记本图 Decisions-so-far：不落仓库文档，只留在地图里。

## Answer

裁定（用户 2026-10-25 收口）：

| 项目 | 决策 |
|---|---|
| 数量覆盖（每个设计实体 ≥1） | 已有判据，继承，不重开 |
| 精确数量 N | 结构性不可判，不新增检查 |
| 绝对位置 | 结构性不可判 |
| 相对空间关系 | 结构性不可判 |
| `w/h` 几何观察 | 维持现状 |
| 桶总序 | 不加观察 |
| 边界记录 | CONTEXT.md 词汇表（已落） |

**核心原则**：布局伪影不升级为设计语义，缺失的语义信息不靠观察或阈值补造。

**落点**：`CONTEXT.md` 在「观察/判据」条目后新增「结构性不可判」词条 —— 一句定义 +
两条实例（数量精确值因 [[GameDesignSpec]] 无 `count` 字段；空间关系因 VDS 屏幕空间 ↔ GameConfig
世界空间无变换、且 VDS 纯机械布局不承载语义）。B3「桶总序」判定为布局伪影、非语义断言，
**不加观察** —— 比「弱观察不阻断」更干净，不把「布局碰巧排的序」读成「设计想要的序」。

**派生**：无新票。票 02（S=D 覆盖）不受本票影响，仍待收口。
